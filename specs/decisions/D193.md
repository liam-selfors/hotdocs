# D193 — license-scanner reports what it did not evaluate

## Context

`license-scanner` compares generated code against a corpus of precomputed
fingerprints (`VAR-LICENSE-CORPUS-PATH`), and no corpus exists anywhere
in this repository. Its gate_version was `license_scanner@3.1.0`
(corpus_version 0), and every scan returned `blocked: false`,
`similarity_score: 0.0`, no matches, recorded in each component's
provenance as a pass. The compliance gate looked like it had checked
something. It had checked nothing: the same flaw `D168` removed from
`secret-scanner`, whose pattern database was likewise never supplied.
`R-LICENSE-001` even required it: a missing or unreachable corpus "MUST
still produce a real, recorded clean result".

## Decision

Every result carries `evaluated` and `reason`. With no corpus
(`VAR-LICENSE-CORPUS-PATH` unset; a configured corpus with zero entries is `corpus-invalid` instead) the
result is `evaluated: false`, `reason: "no-reference-corpus"`, scores
`null` rather than `0.0`, and `blocked: false`: a pilot with no corpus is
not stopped, but the record no longer claims a check happened. A corpus
the operator configured and that cannot be used (missing, unreadable, or
malformed) fails closed instead: `evaluated: false`, `blocked: true`,
reason `corpus-unreadable` or `corpus-invalid`. Silent degradation there
would be the original flaw, hidden behind a typo in a path.

`gate_version` becomes `license_scanner@4.0.<corpus_version>+<H>` for an
evaluated scan, `<H>` being the first 12 hex digits of the corpus file's
SHA-256 so that any corpus change invalidates cached results even without
a version bump, and `license_scanner@4.0.0-<reason>` otherwise, so the
two kinds can never share a cache key or a provenance match: the
provenance of a component scanned without a corpus stops matching the
moment a corpus is configured. (Before this, corpus_version defaulted to
`0`, so an unconfigured scan and a real corpus lacking that field
produced the same string.) The CLI prints a plain `NOT EVALUATED:
<reason>` line; exit codes are unchanged except that an unusable
configured corpus now exits `1`.

## Consequences

Nothing outside license-scanner reads `similarity_score`, and every
consumer reads only `blocked`, so no consumer breaks. None yet shows
`evaluated: false`. The downstream change list is in the report that
accompanied this decision; the choice of a real detection source is
`D192`.
