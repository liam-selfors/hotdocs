# D37 — Resolve four standing open questions

## Context

A sweep for still-open items across the corpus (distinct from
`notes/backlog.md`'s separately-tracked gaps) surfaced four genuine
open questions still sitting, unresolved, inside component specs:
`cache-manager`'s determinism assumption, `merge-orchestrator`'s
sealed-component cache-hit semantics, `merge-tracker-ui`'s possible
convergence with `docs-site-renderer`, and `merge-tracker`'s
best-effort-vs-visible write-failure question. Bundled into one
decision since each is small and independent, following the precedent
of the project's own early "Resolve Q1"/"Resolve Q2" commits.

## Decision

**`cache-manager`.** Investigation found the open question understated
a real inconsistency, not just an unverifiable assumption:
`G-CACHE-001`'s safety argument literally required "every concurrent
writer produces the same result payload for that key," but `generator`
and `test-author`'s own `constraints.md` already declare themselves
**not** deterministic — only a cache *hit* is required to be
byte-identical, not every call capable of producing one. Fixed by
correcting the guarantee's stated precondition rather than changing
any mechanism: last-write-wins is safe because whichever write
survives a race is always an independently-valid, uncorrupted answer
for that key — true for every gate, deterministic or not — not because
concurrent writers are identical, which is only true for the
deterministic ones. `AC-CACHE-009` tests the non-identical-payload case
directly.

**`merge-orchestrator`.** A sealed component's characterization-test
path (`R-MERGE-015`) never participates in `R-MERGE-003`'s cache-hit
short-circuit, by construction: `verifier-orchestrator` never writes to
`cache-manager`, so there is no cached outcome for that path to ever
hit. This was already true of the existing mechanism — the fix is
making it explicit in `R-MERGE-015` rather than leaving it to be
rediscovered. `license-scanner`/`secret-scanner` are unaffected and
continue caching normally against a sealed component's content.

**`merge-tracker` / `merge-orchestrator`.** "Best-effort, but never
silent" was resolved as both at once, not a choice between them. The
non-gating half was already settled (`R-MERGE-019`/`021`,
`R-TRACK-005`). The visibility half: a failed `merge-tracker` call is
now caught and surfaced as `MergeResult.tracking_write_error`
(`{category, message}`, mirroring `model_call_error`'s shape from
`D32`) rather than silently swallowed — reusing the one place every
merge attempt already reports its outcome instead of inventing a
second channel. `AC-MERGE-024` tests it.

**`merge-tracker-ui`.** Closed the `docs-site-renderer` convergence
question by recognizing it was already answered: the component's own
Scope section already excludes reading anything committed. Staying
separate is now stated as the decision, not left as an open deferral —
revisit only if a concrete cross-referencing need actually surfaces.

## Consequences

All four open questions are closed. The `cache-manager` fix is the
more consequential one: it corrects a guarantee file whose literal
precondition was false for two of its four real callers, closing a
latent correctness gap before it could cause confusion during a future
audit. The other three are documentation-precision fixes with no
behavior change (sealed/cache-hit, UI convergence) or a small,
additive one (`tracking_write_error`).
