# D49 — depends_on_guarantees is a flat list of bare G-&lt;comp&gt;-NNN strings; ownership is derived from directory location, never parsed from the id

## Context

A real candidate's own hand-written verification suite found its entry parser only recognized a nested `{component, guarantees}` shape; the real frontmatter shape is a flat list of bare id strings, confirmed from a real component's own real frontmatter. Against real data the parser always found zero recognized entries and silently fell back to an unnarrowed default.

## Decision

Clarified directly: a `G-id`'s owning component is never parsed from the id string itself (ambiguous once a slug contains hyphens), but determined by which component's real `interface/guarantees/` directory contains that file.
