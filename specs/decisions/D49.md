# D49 — Real `spec-bundle-assembler`

## Context

`D47`/`D48` built real `llm-endpoint`/`cache-manager` — two of
`generator`'s three dependencies. `spec-bundle-assembler` is the third:
fully specced, entirely deterministic (`R-ASSEMBLE-001`–`010`, all
`kind: compiled`), and the component that actually produces the
`SpecBundle` `generator` would dispatch to a model.

## Decision

`gen/spec-bundle-assembler/spec_bundle_assembler.py` implements
`assemble(component_id, repo_root, mode) -> SpecBundle` and
`assemble_criterion(component_id, criterion_id, repo_root) ->
CriterionBundle`, reusing `spec-linter`'s own `load_corpus()` rather
than re-parsing spec files independently (`SPEC_GUIDELINES.md` §10) —
`single source of truth`, not a second, independently-written file
walker. `R-ASSEMBLE-010`'s one narrow exception (a dependency's
`Purpose` text) is read via `graph-query-engine`'s `component_context`
view specifically, never a dependency's `component.md` directly.

`depends_on` was missing `comp-graph-query-engine` — the same drift
`D44`/`D45` already found and fixed for `spec-linter`/
`corpus-graph-builder` — fixed here too.

This is the sixth hand-bootstrapped component, temporary like
`cache-manager`: nothing stops a real `generator` from cold-
regenerating it later.

Verified against a synthetic fixture (a `comp-foo`/`comp-bar` pair with
a real dependency edge, a var, and a product capability), needed for
precise control a real corpus can't currently give cleanly — a
dependency with known `Purpose`/`Rationale` text to assert
`R-ASSEMBLE-002`/`010`'s exclusion boundaries on, and a deliberately
broken corpus to exercise `R-ASSEMBLE-005`'s precondition-failure path
without touching this repo's own real one. All 10 tests pass, one per
`AC-ASSEMBLE-*` criterion. Also smoke-tested directly against the real
corpus (`comp-cache-manager`, `comp-spec-linter`), confirming
`dependency_interfaces`/`dependency_context` populate correctly for a
real dependency and that no `acceptance/` content leaks in — checked by
hand, since `spec-linter`'s own `requirements/` text happens to discuss
the `Covers:`/`Kind:` convention by name, a legitimate false-positive
risk for a naive substring check.

## Consequences

`generator` now has all three of its real dependencies
(`spec-bundle-assembler`, `cache-manager`, `llm-endpoint`) — nothing
left to build before attempting a real `generator` implementation.

Linter: 0 failures once this file exists (1 failure beforehand, the
`R-LINT-026` citation of this decision), 21 warnings (unchanged).
Pytest: all six suites (`spec-linter`/`graph-query-engine`/
`corpus-graph-builder`/`llm-endpoint`/`cache-manager`/
`spec-bundle-assembler`) run separately, 42/7/8/7/10/10 passed.
