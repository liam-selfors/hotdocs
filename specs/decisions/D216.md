# D216 — `graph-query-engine` tolerates a corpus with no components, and the last prose `compiled` criteria become generated tests

## Context

Regenerating `graph-query-engine` (seed 6, mutation 1.0) failed three
criteria. Two generated tests built corpora with no `component.md`, and
the candidate's views raised, as `R-GQE-007` allowed: it exempted the
component glob from the zero-match guard because "no corpus is ever
linted with zero components". That is false: a project `hotdocs init`
set up without `--example` has none, and `hotdocs lint` was made to work
there. The third, `AC-GQE-009`, was `kind: compiled` but written in prose the
step grammar cannot parse. So was the capability scenario
`CS-DECISION-INTEGRITY-001`. `D43` reclassified every other such
criterion to `generated-test` and missed these two.

## Decision

`R-GQE-007`'s guard covers `specs/components/*/component.md` like every
other glob, and every view exists with zero rows when nothing matches.
`AC-GQE-009` and `CS-DECISION-INTEGRITY-001` are
`kind: generated-test`.

A third generation (seed 7) failed only `AC-GQE-009`: its test wrote
`supersedes: [D2]`, though `R-GQE-002` reads `supersedes` as one id. The
criterion now gives the exact frontmatter line.

## Consequences

No criterion in the corpus is `kind: compiled`; `criterion-compiler`
remains in place for the first one written in the grammar.
