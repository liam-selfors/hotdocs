# D207 — `spec-bundle-assembler`'s criteria share one stated, lint-clean fixture corpus

## Context

`assemble` lints its corpus first and refuses one with a hard failure
(`R-ASSEMBLE-005`), so every test's synthetic corpus has to pass
`spec-linter`. Only `AC-ASSEMBLE-011` said so (`D177`). Regenerating the
component (seed 50) failed 14 of 15 criteria: the code reached mutation
score 1.0, but each test guessed a corpus shape and most guesses failed
lint, on a missing `Kind:` line (`R-LINT-010`) or a requirement with no
RFC 2119 keyword (`R-LINT-007`). One test imported `spec_linter` by
name, which never resolves.

## Decision

`interface/library.md` gains a "Test fixtures" section, the pattern
`D204` set for `review-packet-builder`: the literal files of a minimal
corpus, checked to lint with no findings at all, how a dependent
declares `depends_on`, where a dependency's real code goes, and one
reliable way to make lint fail (drop the `Kind:` line). It says a test
never imports `spec_linter`. `AC-ASSEMBLE-011` points at it instead of
listing lint rules.

`component.md`'s Acceptance criteria section said every criterion was
`kind: compiled`; all are `generated-test`, and it now says so. Its change
log is shortened to one line per decision, which holds the rationale.

## Consequences

The test author gets the corpus shape from the bundle instead of
inferring lint rules, and the spec stays under the word cap.
