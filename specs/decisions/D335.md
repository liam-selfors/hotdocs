# D335 — JavaScript held in a string is mutated too

## Context

Components that render a page return JavaScript as a Python string and
test it by running it in `node` (`docs-site-renderer`,
`provenance-tracker-ui`). `verifier-orchestrator` mutated only Python
syntax, so the JavaScript, nearly all such a component's logic, was
never mutated: one scored 1.0 with a test that only searched its source
for a word (issue #13).

## Decision

A string constant holding JavaScript, by a stated pattern and never a
docstring, gets token-level mutants: `===`↔`!==`, `==`↔`!=`, the four
ordering swaps, `&&`↔`||`, `true`↔`false`, and binary `+`↔`-`. A small
tokenizer skips the script's own strings and comments; no JavaScript
parser is needed. In a string holding an HTML page, only the text
inside `<script>` elements is read. The exact rules, with Python's
operators, move from `R-VERIFY-006` to `specs/architecture/mutation-runs.md`.
`AC-VERIFY-026` covers them. `GATE_VERSION` becomes
`verifier-orchestrator@2.3.0`.

## Consequences

Components with embedded JavaScript get more mutants, and their scores
now say how well their criteria pin the script; some will fall below the
bar until their criteria do. Every manifest misses once for the version
change.
