# D302 — Authoring verbs, and an optional model the CLI injects from `hotdocs.toml`

## Context

`hotdocs-cli` injects the configured model only into verbs that cannot
run without one (`generate`, `author-test`). `assist`, `verify` and
`track ui build` run without a model but do less: `assist` skips its
judgment, and `verify` exits `2` when a capability needs a fresh run. A
user who configured a model in `hotdocs init` reasonably expects those
verbs to use it, and instead sees degraded output or a usage error that
names a flag they never had to pass elsewhere. The new `spec check` has
the same shape. The `spec-scaffolder` and `spec-reviewer` verbs are not
reachable at all.

## Decision

- `VerbTable` gains rows for `spec check`, `decision new`,
  `decision ratify`, `decision record-commit` and `component new`.
- A third `model` value, `optional`, marks `assist`, `spec check`,
  `verify` and `track ui build`. For these the configured model is
  injected as for `required` rows, with a one-line stderr notice naming
  it, so the paid work is never silent. `--no-model` on a `required` or
  `optional` row is removed and suppresses injection; on any other row it
  is forwarded, where the component treats it as unknown.
- A hand suite, `verification/hotdocs-cli/test_verb_routing.py`, drives
  every row whose component implements
  `specs/architecture/cli-conventions.md` through the real dispatcher
  with an unknown argument and requires exit `2`, a `usage error:` line
  and no traceback. The set grows as components adopt the conventions.

## Consequences

`hotdocs-cli` is a leaf; only it regenerates.
