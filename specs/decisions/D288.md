# D288 — `provenance-tracker-ui` catches the `ValueError` `check_readiness` raises

## Context

`provenance-tracker-ui` caught `provenance-tracker`'s own `UsageError`,
which `provenance-tracker`'s interface never declares: there a
capability miss with no model raises `ValueError`. Seed 1 of the UI
passed every criterion against a fake tracker, then crashed with an
`AttributeError` the first time `hotdocs track ui build` ran against the
real one.

## Decision

`R-UI-009`, `interface/cli.md`, `interface/library.md` and `AC-UI-009`
name the `ValueError` `check_readiness` raises instead.

## Consequences

`provenance-tracker-ui` is regenerated. The consumer-surface gate checks
only the names a candidate provides, not the names it uses, which is
why this reached a real run.
