# D182 — Model strings, backward compatibility, and one open caveat

## Decision

A model string is `<provider>:<model>`, the prefix counting only when it
names a provider, or a bare name (glossary: "Model string"). The
provider is sent the part after the prefix; the response, call log, and
provenance keep the string the caller passed. With no configuration a bare
`claude-*` name uses the `claude` command and anything else still fails
before any call, exactly as before, so `generator`, `test-author`, and
`component-gate-runner` are unchanged.

Two deliberate changes. The `claude` command's response `backend` label is
now `claude-cli`; `anthropic` names the Messages API, and nothing in
`gen/` reads the label. `resolve_backend_name` stays as a legacy
single-argument function returning `"anthropic"` for a bare `claude-*`
name, so its existing test still passes. And a configured
`timeout_seconds` cannot go below 300, though `check_connection`, a
probe, takes its own short bound and is not logged as a pipeline call.

## Open caveat

Ollama's default context window may silently truncate a long
generation prompt, which would show as a nonsense reply rather than an
error. `num_ctx` is passed through when a caller sets it; no default is
chosen because a safe size depends on the model and machine.
