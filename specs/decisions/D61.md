# D61 — Another real self-hosted-generation gap, same class as D55/D56/D57

## Context

The first real `generate()` call for `provenance-checker` (no errors,
no refusal, a well-reasoned 3-file package) built
`gen/<component_id>/.provenance.json` directly from the caller-supplied
`component_id` — never stripping its `comp-` prefix. Confirmed by a
direct test: `check_provenance("comp-widget", "H", {}, repo_root)`
reported a miss even with a real, matching manifest sitting at
`gen/widget/.provenance.json` (the correct, prefix-stripped path).

Checked whether this was documented anywhere: it is not, in
`SPEC_GUIDELINES.md` §1 (states the `gen/<component>/` path pattern
but never says how `<component>` relates to a `component_id`) or
`glossary.md` (no `component_id` entry existed at all). Every real
component that has ever needed to resolve a `gen/<component>/`-shaped
path from a `component_id` — `generator` itself, every caller of
`cache-manager` — independently reimplemented the same
`component_id[len("comp-"):] if component_id.startswith("comp-") else
component_id` logic, silently, with nothing shared or specified. This
is the same class of gap `D55` found for import paths and `D57` found
for cache-manager's payload schema: a fact more than one component
needs, never promoted to the one place `SPEC_GUIDELINES.md` §10 says
it belongs, until a real generated candidate got it wrong for lack of
anywhere to look it up.

## Decision

Added a `glossary.md` entry ("Component id / component slug") stating
the relationship explicitly: `component_id` is always `comp-<slug>`;
every `gen/<slug>/`, `verification/<slug>/`, `specs/components/
<slug>/` path uses the bare, prefix-stripped slug, never the full id.
`glossary.md` is part of every real `SpecBundle`
(`spec-bundle-assembler`'s `assemble()` always includes it), so this
reaches every future cold-mode `generate()` call automatically,
without needing a per-component `dependency_usage`-style fix.

Also fixed `provenance-checker/component.md`'s stale "every criterion
is `kind: compiled`" claim (`D59` reclassified them all to
`generated-test`) while in this file for an unrelated reason — the
same stale claim exists in 16 other `component.md` files as a
mechanical side-effect of `D59`; left for whenever each one is next
touched rather than swept now, since it's cosmetic and blocks nothing.

The buggy candidate's `gen/provenance-checker/` output (R-GEN-006's
own "write on success" — success meaning "didn't error," never
"passed independent verification") was deleted before being
committed, never swapped in. A fresh retry with this fix in place is
`D62`, tracked separately.

## Consequences

Every component whose real implementation will eventually need to
turn a `component_id` into a `gen/`/`verification/` path (several of
the 13 components still left to build) now has one real, documented
place to get this right the first time, the same way `D55`'s
`dependency_usage` fix did for import paths.

Linter: 0 failures. Pytest: all 108 tests across all eight real
components re-verified unchanged (doc-only edit, no code touched).
