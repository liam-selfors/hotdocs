# D157 — in degraded mode spec-completeness-assistant makes no model call, including generator's

## Context

Third real attempt (after `D156`): `AC-ASSIST-003` and `AC-ASSIST-006`
failed because their generated tests expected a `generator` call that
the candidate deliberately skipped. Both called `assist` with no
`model`. `R-ASSIST-007` said degraded mode still runs the hint preview,
"which need[s] no model beyond what `generator` itself already
requires" — but `generator` requires a model, and having none is the
very definition of degraded mode. The requirement contradicted itself.
The candidate resolved it sensibly: with no model it calls nothing that
reaches a model, and uses the hint-mode `SpecBundle` itself as the
preview. That is also what `AC-ASSIST-007` already asserted, since
`generator` dispatches through `llm-endpoint`.

`AC-ASSIST-008`'s test snapshotted `repo_root` and flagged Python's own
`__pycache__` bytecode for the faked modules as a write by this
component — the same false positive `provenance-tracker-ui`'s
`AC-UI-004` hit in this same session. Fixed per criterion here; a
third occurrence would warrant a `test-author`-level rule.

## Decision

`R-ASSIST-003` and `R-ASSIST-007` amended: no `model` means no model
call of any kind, `generator` included, and each preview is the
hint-mode bundle alone. `interface/library.md`'s call order marks
`generator` model-only. `AC-ASSIST-003` gains a no-model case,
`AC-ASSIST-006` drops its implied `generator` dependency, and
`AC-ASSIST-008` excludes `__pycache__` explicitly.
