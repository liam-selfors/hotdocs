# D110 — test-author statically validates its own output instead of trusting model self-check alone

## Context

`provenance-tracker`'s retried `AC-TRACK-009`/`010` authorings failed for real, functional reasons once the bootstrap driver's own transitive-dependency sandbox bug (not a spec/candidate issue) was fixed. `AC-TRACK-010`'s fake for `provenance-checker` defined one function and aliased it under **five** plausible real names (`check_provenance`, `check`, `check_component_provenance`, `get_provenance`, `provenance_check`) — itself evidence the model did not reliably know the real name — and gave it 2 parameters against the real, fully-documented 4-parameter `check_provenance`. This is the same bug class `R-AUTHOR-011`/`D100` was meant to close.

Rather than patch this one instance and wait for the next recurrence, this session paused to have four parallel agents independently audit test-author's design: a producer/consumer field-compatibility audit across every `CriterionBundle`/`SpecBundle` builder, a fresh-eyes critique of the prompt-construction design, an adversarial stress test constructing hard bundles and inspecting the rendered prompts, and a design review of what a structural self-check could look like. All four converged independently on the same diagnosis: the roughly ten real bugs found this session split into two populations, not ten one-offs — (a) genuine context gaps closed correctly by adding prompt instructions (`R-AUTHOR-009`–`019`), and (b) `author_test`'s own code bugs, invisible under a mock backend that silently accepts anything (`D106`, `D108`) — and that asking the model to self-check its own fake (`R-AUTHOR-015`) is necessary but structurally insufficient: a model that doesn't reliably know a dependency's real signature cannot reliably judge its own guess against it either, which is exactly what the five-alias hedge demonstrates.

Two further, currently-latent structural gaps were found and are deliberately **not** addressed by this decision, tracked separately: a third, field-incompatible `CriterionBundle` producer in `capability_scenario_verifier` (silent, total content loss if a capability scenario is ever marked `kind: generated-test`), and `dependency_interfaces` never resolving a type referenced by a dependency's own signature but owned by a different, undeclared component (the actual reason `write_attempt_record`'s `GenerationResult`/`VerificationReport` parameters are underspecified in `provenance-tracker`'s own prompt).

## Decision

New `R-AUTHOR-020`: `author_test` MUST statically validate a response before accepting it — `ast.parse()` the content first (a `SyntaxError` is a distinct `malformed_code` failure), then best-effort check that any fake-dependency callable's arity matches its real documented signature from `dependency_interfaces` (a mismatch is a distinct `fake_signature_mismatch` failure) — both implemented in `author_test`'s own code, never left to the model. `R-AUTHOR-015`'s self-check is upgraded from SHOULD to MUST, since a model-judgment-gated safeguard is no safeguard where it matters most.

Separately (not a spec change, hardening the hand-maintained suite directly): `MockBackend` is made strict — it now rejects any unexpected keyword argument, the same way the real backend's CLI would reject an unsupported flag, so a `D108`-class bug is caught locally without needing a live bootstrap to surface it.
