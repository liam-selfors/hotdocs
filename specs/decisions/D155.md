# D155 — a hard-fail lint finding stops spec-completeness-assistant, not just runs first

## Context

First real cold-generation attempt for `spec-completeness-assistant`:
four criteria pass, both `llm-judge` criteria are `skipped` (this
pipeline's bootstrap driver passes no judge), `mutation_score=1.0`, and
two criteria fail. `AC-ASSIST-008`'s failure is a test-fixture
omission (its repo_root never fakes `generator`, which the hint
preview needs) and not investigated further. `AC-ASSIST-001`'s is a
genuine ambiguity: `R-ASSIST-001` said a hard-fail `spec-linter`
finding must be surfaced "before any judgment-based analysis runs."
The candidate read that as ordering, linting first and then running
the model judgment anyway; the generated test read it as a stop. In a
function that returns a single report, ordering is unobservable, and
paying for a model judgment or a `generator` hint preview against a
spec that already hard-fails lint buys a result the developer must
throw away.

## Decision

`R-ASSIST-001` amended: any `"fail"`-severity finding makes `assist`
return immediately with only `lint_findings` populated, every other
field empty or null, and no model call of any kind. `AC-ASSIST-001`
rewritten to pin that exactly, plus a warn-only case confirming a
non-fatal finding does not stop the run.
