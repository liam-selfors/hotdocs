# D197 — hotdocs init seeds a sealed allowlist for the vendored tool

## Context

`init` vendors `gen/review-packet-builder`, which holds the git empty-tree
hash, a public constant the secret scanner flags. A fresh project's first
whole-repository scan was therefore flagged, and under `D195` the only way
to allow it is a non-empty allowlist sealed by a ratified decision.

## Decision

When `init` creates `.secret-allowlist.json`, it writes that one
`public-constant` entry and a ratified decision, numbered after the
project's highest existing one, recording the file's hash. An existing
allowlist is left alone and no decision is written, so `init` never
changes which seal is in force for a list it did not create.

## Consequences

A fresh project scans clean. The entry names a fixed path, so it is
reported unused if that component is ever removed or renamed, which is
harmless. Later changes to the list follow `D195`: a new decision with a
new hash.
