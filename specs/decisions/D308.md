# D308 — A tool-use endpoint, with `claude-cli` tools served over MCP

## Context

Every model call in the pipeline is one message and one reply. A
generator that can read files, run its own tests and revise needs a
multi-turn tool loop, and each provider has its own wire format for it.
For `claude-cli`, `llm-endpoint` isolates a subscription login with
`--safe-mode`, which a spike showed also disables every MCP server, so
no tool can reach the model that way.

## Decision

A new component, `llm-tool-endpoint`, runs a bounded tool loop:
`anthropic`, `openai` and `openai-compatible` over HTTP per
`specs/architecture/tool-use-wire-formats.md`; `claude-cli` through a
stdio MCP server the loop starts, which relays each call over a Unix
socket to the caller's `execute`. The spike settled the `claude-cli`
isolation without `--safe-mode`: `--tools ""`, `--strict-mcp-config`,
`--setting-sources ""`, `--disable-slash-commands`, settings that turn
off auto-memory and hooks, and the caller's own `--system-prompt`. With
those, a CLAUDE.md and an AGENTS.md planted in the working directory
were not seen, and only the listed tools were exposed. `gemini` and
`ollama` raise `ToolUseUnsupported` before any call.

## Consequences

`llm-endpoint` is unchanged. The loop never retries; a failed request
ends it with `llm-endpoint`'s error categories.
