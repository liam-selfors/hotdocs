# D167 — generator's three "pre-existing" test failures were real defects

## Context

`generator`'s hand-maintained suite had carried three failures for
many sessions, filed as "pre-existing" and left alone:
`AC-GEN-018` and both `AC-GEN-017` tests. The first real end-to-end
`hotdocs generate` (`D166`), run on a throwaway copy of the
repository, crashed in `provenance-writer` with `missing required
field: 'spec_bundle_hash'`. That was `AC-GEN-018`'s failure,
surfacing for real: `GenerationResult` never carried
`spec_bundle_hash`, although `R-GEN-017` requires it and
`provenance-writer` has no other source for it (`R-PROV-002`). No
`.provenance.json` could ever have been written.

The two `AC-GEN-017` failures were as real. In `hint` mode, `generate`
wrote `gen/<component>/` and the cache anyway, against `R-GEN-016`.
`spec-completeness-assistant` calls `generator` in `hint` mode for its
previews, so a `hotdocs assist` run with a model configured would have
overwritten a component's verified code with a speculative preview.

## Decision

`generator` (hand-authored, a permanent exception) is fixed directly:
every `GenerationResult` carries the bundle's `spec_bundle_hash`, and
`hint` mode writes neither `gen/` nor the cache, on a fresh call or a
cache hit. `GATE_VERSION` moves to `generator@1.7.0`. Its suite passes
19 of 19.

A failing test is a claim about the code. Filing one as
"pre-existing" stops anyone asking whether that claim is true; all
three of these were.
