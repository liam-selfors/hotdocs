# D209 — Interfaces state every name and value other components rely on

## Context

Regenerating the hand-written components from their specs (`D206`)
depends on each spec naming everything a consumer or a test needs. A
hand-written module could carry an unspecified name for years, because
nothing regenerated it. Before regenerating, every name other modules
reference on each of the six was collected from their source, and every
value a criterion needs was checked against the spec. Eight were missing.

- `cache-manager`: `now_iso()`, used by `generator` and `test-author` for
  `CachedResult.stored_at`, and `Miss` as a class consumers test with
  `isinstance`.
- `generator`: `GenerationResult` as a dataclass, and the exact cache key. `AC-GEN-005` pre-populates the cache,
  which a test can only do knowing `gate_inputs_hash`'s formula and
  `GATE_VERSION`.
- `criterion-compiler`: `GATE_VERSION`, which `provenance-checker` reads
  into every component's provenance key.
- `criterion-compiler`: `ParsedCriterion` and `CompileReport` as
  dataclasses (`capability-scenario-verifier` builds the first), and the phrases
  its error messages carry, which its hand-maintained characterization
  suite checks.
- `criterion-compiler` and `spec-linter`: `main(argv)`, which
  `hotdocs-cli` calls with the verb already stripped.
- `spec-linter`: `LintReport` and `Finding` as dataclasses with
  `hard_failures`/`warnings`/`skipped` counts, which `impact-analyzer`
  reads by attribute.
- `spec-bundle-assembler`: `SpecBundle` and `CriterionBundle` as
  dataclasses that also read as mappings; `generator` reads them by
  attribute, `test-author` by key.
- `llm-endpoint`: `parse_model`, `resolve_provider` and
  `DEFAULT_TIMEOUT_SECONDS`, whose behavior `R-ENDPOINT-002` and
  `R-ENDPOINT-004` already defined, and that `complete` returns a plain
  dict. Its hand-maintained tests had reached a private backend class;
  they now go through `complete`.

`spec-linter`'s `load_corpus` was the ninth, recorded in `D208`.

## Decision

Each is now in the component's `interface/`. `criterion-compiler`'s
`GATE_VERSION` stays `criterion-compiler@1.0.0`, since its compiled output
does not change. `generator` moves to `generator@2.0.0` and prompt `v10`,
because a regenerated generator writes a new prompt; its
`gate_inputs_hash` formula is the one already in use.

`tools/bootstrap_component.py` now refuses a candidate that lacks any
name other components or tools reference on it, before running anything
else, so a gap of this kind fails loudly instead of breaking a consumer.

## Consequences

A regenerated component keeps the surface its consumers use. Old cache
entries keyed on `generator@1.8.0` are never hit again.
