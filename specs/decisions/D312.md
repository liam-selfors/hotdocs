# D312 — The manifest records how a candidate was generated and every attempt it took

## Context

With an attempt loop and an agentic mode, a manifest that names only the
model and prompt version no longer says how its code came to be: whether
it took one attempt or three, with what feedback, and whether a model
ran code on the machine and under what isolation. A reviewer judging a
landing needs those facts, and an auditor needs them without the
transcripts, which can hold the whole spec bundle.

## Decision

The manifest gains `generation` (mode, generator version, transcript
hash, turns, tool calls, isolation), `attempts`, and `attempt_history`:
one entry per attempt of the landing run, with its outcome, feedback,
error category, failed requirement ids and transcript hash. Only hashes
and counts are written, never a transcript. `SPEC_GUIDELINES.md` §7
lists the fields.

## Consequences

`provenance-writer` takes `attempt_history` in `ProvenanceInputs`; the
gate runner passes the attempt loop's list through.
