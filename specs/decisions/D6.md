# D6 — Cross-step literal substitution is bare-identifier-only, resolved at compile time

## Decision

A bare identifier occupying an entire leaf/scalar position in criterion-compiler's literal syntax — whether the whole argument or nested inside a larger literal — is literal substitution if it exactly matches a fixture already bound by an earlier step in the same criterion, resolved at compile time by direct lookup, never runtime computation. Anything beyond a bare identifier in a leaf position (an operator, field/index access, concatenation, a call) is expression evaluation and a compile error. Field/index access into an already-bound literal is deliberately excluded even though it would be no less safe, since allowing it means extending the step-phrase grammar itself for a need nothing has raised yet.
