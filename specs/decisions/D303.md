# D303 — Probe every generated test, and let the test author repair its own

## Context

A generated test that is broken in itself (an undefined name, an import
of a module that does not exist, a fake whose signature disagrees with
the interface, a fixture that is never defined) fails against every
candidate. In the tool's own regeneration such tests were cached and
reused, so every later attempt failed for the test's reasons and the
verdict blamed the code. `test-author` checked syntax and fake arity
only, and never asked the model to fix a test it had rejected.

## Decision

A new component, `test-probe`, checks one test's source: syntax, pyflakes
undefined names, imports that resolve to nothing, and fake arity (moved
from `R-AUTHOR-020`). Then it runs the test once against a stub module in
which every call raises `HotdocsProbeStubReached`, a `BaseException` no
`except Exception` can swallow. A test that fails before reaching the
stub is a `test_bug`; one that passes without reaching it is `vacuous`, a
warning.

## Consequences

`test-probe` has no dependencies. `test-author` and
`verifier-orchestrator` adopt it in later changes.
