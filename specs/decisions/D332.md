# D332 — Main's demo-build fixes merged into the authoring work

## Context

`main` fixed the demo build's issues through `D316` and `D318` to
`D331` while this branch built the test probe, the attempt loop and
agentic generation (`D298` to `D317`). Both sides changed `test-author`,
`verifier-orchestrator`, `component-gate-runner` and `generator`, and
`D316` exists on both: `main`'s copy is this branch's, ported without
the `test-probe` stand-in because `main` had no `test-probe`.

## Decision

- `D316` keeps this branch's text, which names the `test-probe`
  stand-in, and `main`'s ratification.
- A cached test with no `# hotdocs-criterion` header is stale and
  authored again (`D320`), not "never stale" as `D307` had it: `D328`
  gave every committed test a header, so nothing is re-authored by
  surprise. Before a test runs it is still probed, and a probe failure
  re-authors it once (`D307`); a transient authoring error is retried
  once (`D319`). `R-VERIFY-019` states the three steps.
- `component-gate-runner` derives `block_reason` from the attempt loop's
  last outcome (`D310`), and a final `verification_failed` attempt whose
  failing criteria all have `failure_origin` `"test"` gives
  `"test_authoring_failed"` (`D319`), which exits `1` like
  `"model_call_error"`.
- `test-author` implements both `test-author-fixtures.md` and
  `test-author-output.md`; they state the same extraction and header.
- New gate versions mark the merged behavior: `generated_test@2.1.0`
  and `verifier-orchestrator@3.1.0`, then `generated_test@2.2.0`,
  `verifier-orchestrator@3.2.0` and `test-probe@1.1.0` once `D334` and
  `D335` merged too.
- Here the fake-arity check is `test-probe`'s (`R-PROBE-004`), so
  `D334`'s rule, a fake only when it stands in for a dependency, applies
  there, and `AC-PROBE-004` covers it; `test-author` keeps delegating to
  the probe, and `main`'s `AC-AUTHOR-029` does not apply.
- `generator`, `verifier-orchestrator` and `provenance-writer` went over
  the 4000-word cap merged; change logs became id lists and restated
  rationale was cut, with no rule changed. `generator`'s scope note now
  says `generation-loop` retries (`D310`).

## Consequences

Every component either side changed regenerates on this branch, as its
Phase F already planned.
