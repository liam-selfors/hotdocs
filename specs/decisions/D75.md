# D75 — The nonexistent specs/capabilities/ path, and criterion-compiler's missing primitive

## Context

A real `generate()` call for `capability-scenario-verifier` produced a
well-structured, well-documented candidate (it explicitly flagged its
own "implementation assumptions" distinct from spec content, a good
discipline on its own part) — but two of those assumptions were
confirmably wrong, not just design choices:

1. It read capability scenarios from `specs/capabilities/<slug>/
   acceptance/*.md` — a directory that does not exist anywhere in this
   corpus. Checked directly: capability scenarios are `### CS-<id>`
   sections embedded inside each capability's own `specs/product/
   <name>.md` file (`SPEC_GUIDELINES.md` §3.1), the exact same shape as
   a component's `acceptance/<id>.md` unit file, just nested as a
   subsection rather than a separate file.
2. For `kind: compiled` dispatch, it called `criterion-compiler`'s only
   public entry point, `compile(component_id, repo_root, ...)` — hardcoded
   to scan one component's own `acceptance/` directory. A capability
   scenario is never scoped to any single component, so this can never
   work regardless of path fixes; the candidate's own scenario-discovery
   code and its `compile()` call even pointed at two different,
   mutually-inconsistent paths, confirming this concretely rather than
   by inference. `R-SCENARIO-001` explicitly forbids inventing new
   dispatch machinery to route around this — the only correct fix was a
   real extension to `criterion-compiler` itself.

## Decision

Fixed in `criterion-compiler` directly (sealed, hand-authored — edited
in place, never through `generate()`): new `R-COMPILE-012` /
`compile_criterion(criterion, surface=None)`, a directory-scanning-free
primitive that `compile()` now uses internally for each criterion it
finds, and that `capability-scenario-verifier` can call directly for
content outside any component's `acceptance/`. `surface=None` is a
real, valid input — a capability scenario is black-box against the
whole assembled system, with no single component interface to resolve
against; a step that still references a function/type is a located
compile error regardless, never silently skipped for lack of a
surface. Behavior-preserving: all 12 pre-existing `criterion-compiler`
tests pass unchanged; a new `AC-COMPILE-013` covers the primitive
directly.

`R-SCENARIO-001` now states both fixes explicitly: the real location
of capability scenarios, and that `compiled`-kind dispatch must use
`compile_criterion` with `surface=None`, never `compile()`.

A `spec-linter` test hardcoding `criterion-compiler`'s interface-surface
word count at 3 was updated to 4 — a correct, expected consequence of
a real second library function, not a bug.

The buggy `capability-scenario-verifier` candidate was deleted before
being committed, never swapped in.

## Consequences

A retry, with both fixes in place, is the next real test. Notably,
this is the first decision in this sequence where the fix required
*extending a sealed component's own hand-authored code*, not just a
spec clarification — `criterion-compiler`'s permanent seal means this
kind of real capability gap can only ever be closed by a human (or an
assist agent acting with that authority) editing it directly, never by
a `generate()` retry producing a different candidate.

Linter: 0 failures once this file exists. Pytest: all 166 tests across
all fourteen real components re-verified (one test updated to reflect
a real, correct interface-surface count change; `criterion-compiler`'s
own suite grew to 13).
