# D75 — decision-drift-detector: staleness detection and pre-ratification impact analysis

## Context

Nothing in the corpus could answer two related questions once decisions became a real, queryable graph: (a) does a live file's own citation of a decision predate something that has since superseded it — a candidate for staleness review; (b) before altering or superseding a decision, what else would be affected. No existing component's purpose fit either boundary.

## Decision

A new, purely diagnostic component, serving a new product capability (none of the existing ones described a concern about the corpus's own decision history staying internally consistent over time, and forcing a fit would have mischaracterized what it does). Its staleness check walks a citation's supersession chain to the latest superseder, if any, and compares the citing file's own last-touching commit against that superseder's ratification commit via commit ancestry — never a timestamp comparison, since a non-linear history has no trustworthy order by date alone. Its impact-analysis check walks the graph backward from any decision id — including one not yet ratified — collecting every decision and every live file that would be affected by altering it, unfiltered by staleness, since "what would need review" is a different question from "what already looks stale." Neither check is wired into anything as a merge precondition.
