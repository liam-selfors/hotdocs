# D51 — `llm-endpoint` regenerates itself

## Context

`D47`/`D50` built real, hand-written `llm-endpoint`/`generator`
implementations, both on the theory that they were bootstrap
exceptions nothing could cold-regenerate: `generator` is the component
that does the regenerating, and `llm-endpoint` is what it dispatches
through, so neither seemed able to produce the other. That theory was
never actually tested — only assumed. Once both existed for real, it
became directly testable: could the hand-written `generator`, calling
through the hand-written `llm-endpoint`, cold-regenerate `llm-endpoint`
itself from its own current spec?

## Decision

**Yes — tested directly, not assumed.** Assembled `llm-endpoint`'s real
`SpecBundle` via `spec-bundle-assembler` and called the real
`generator.generate()`, dispatching through the real (then
hand-written) `llm-endpoint`, in `cold` mode — the same purity rule
`R-GEN-001` requires for any component, no exception made for
regenerating the very component standing in the call path. The result:
a seven-file `llm_endpoint` package (`__init__.py`, `endpoint.py`,
`model_response.py`, `resolve.py`, `call_log.py`,
`backends/__init__.py`, `backends/anthropic.py`) — genuinely different
in internal shape from the hand-written version (a package vs. a flat
module; a plain-callable backend convention vs. a `.complete()`-method
object), but implementing the same public contract
(`complete(prompt, model, *, backend=None, **params) -> ModelResponse`).

**Verified independently before swapping anything in** — the same
discipline every prior real component in this corpus has followed, not
relaxed for a self-referential case:

- Reviewed all seven files by hand before executing any of them.
- Wrote a fresh verification harness (not reusing the old hand-written
  suite's assumptions) testing every `AC-ENDPOINT-001`–`006` criterion
  against the generated package directly, using mocks matching *its*
  actual backend convention — all passed.
- Made exactly one real, billed `claude` CLI call through the generated
  code to confirm the actual integration works end to end
  (`text="PONG\n"`, `model_call_error=None`) — not repeated
  automatically.

**Swapped in because it passed, not because it was produced.** Passing
every acceptance criterion was the bar, not "a generation attempt
completed" — the same provenance-hit-vs-blind-trust distinction this
corpus's own `D39`/provenance-checker design already draws elsewhere,
applied here to a self-replacement instead of a cache decision.

`gen/llm-endpoint/llm_endpoint.py` (hand-written, `D47`) is deleted;
`gen/llm-endpoint/llm_endpoint/` (the generated package) takes its
place. `verification/llm-endpoint/`'s test suite was rewritten — not
just re-pointed — to match the new package's actual internal backend
shape (a plain callable, not an object with `.complete()`), since that
shape was never fixed by `interface/library.md` in the first place,
only an implementation-internal choice each version is free to make
independently. `verification/generator/`'s own test suite needed the
identical adaptation, since `generate()`'s `llm_backend` parameter
passes straight through to whatever `llm-endpoint.complete()`'s
`backend` parameter currently expects.

## Consequences

`llm-endpoint`'s own `BOOTSTRAP.md`/`component.md` are corrected, not
silently overwritten: `D47`'s claim ("nothing could ever cold-
regenerate this component") is revised to the more precise one this
decision actually demonstrates — nothing could generate the *first*
working version, but once one exists, it can author its own successor,
the same way a compiler bootstraps by compiling itself once a first
version exists by other means. `D47`'s own record stays immutable and
unedited, per this corpus's decision-record discipline; the correction
lives here and in the living docs it ratifies.

This resolves the generator/`llm-endpoint` chicken-and-egg problem in
exactly the way that was hoped for, not merely in theory: a spec change
to `llm-endpoint` can now flow through to a real new implementation
without a human hand-writing it, as long as the result keeps passing
`llm-endpoint`'s own acceptance criteria — genuine self-improvement
under version control, each generation either earning its place by
passing verification or leaving the prior version in place.

A downstream consumer that encoded an assumption about an
implementation-internal detail (the backend's exact call convention)
had to be updated — a real, non-hypothetical cost of this kind of
self-replacement, documented rather than hidden. Future regenerations
of `llm-endpoint` (or any component whose internal shape downstream
test harnesses assume something about) should expect the same class of
adaptation, not assume it was a one-time fluke.
