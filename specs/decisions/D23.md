# D23 — Cache eviction has no correctness dimension; license/secret reference data must come from a maintained external source, not a frozen spec snapshot

## Context

Closed the last three items of a deferred-items queue, all the same
shape: an exact tuning value or policy previously left as "an
implementation detail not pinned down here."

## Decision

- **`cache-manager`'s eviction/retention policy (`R-CACHE-008`)** —
  resolved by noticing it was never actually a correctness question.
  `R-CACHE-001` already requires `get` to return a definitive miss, never
  an approximation; an evicted entry is, to a caller, indistinguishable
  from a plain miss — eviction can happen for any reason, at any time,
  with zero correctness impact, only ever affecting hit rate. The exact
  policy stays unpinned deliberately: the backing store is pluggable
  (`VAR-CACHE-STORE-URL`), and the right policy depends on which store it
  ends up being.
- **`license-scanner`'s k-gram size (`R-LICENSE-001`)** — 9-token
  windows. The reference corpus itself MUST be precomputed hashes plus
  metadata, sourced from a maintained, continuously-updated external
  reference set — never raw license text, and never a one-time list
  hand-curated and frozen into this spec, since fingerprints for active
  OSS projects change as those projects evolve.
- **`secret-scanner`'s pattern database and entropy threshold
  (`R-SECRET-001`)** — entropy threshold 4.0 bits/char. The shape
  database follows the same external-sourcing rule, for the same reason.

**Deliberately not added:** a new `specs/vars/` declaration for "which
external source" either scanner pulls from — that's a vendored-dependency
choice, not a deployment-time config parameter a human sets per
environment.

See `specs/components/cache-manager/requirements/R-CACHE-008.md`,
`specs/components/license-scanner/requirements/R-LICENSE-001.md`, and
`specs/components/secret-scanner/requirements/R-SECRET-001.md` for the
current, authoritative rules.
