# D115 — test-author's synthetic-fixture guidance must also state that unit files carry no frontmatter at all

## Context

The `spec-bundle-assembler` retry that exercised `D114`'s new `R-ASSEMBLE-013` passed the new criterion (`AC-ASSEMBLE-015`) directly, confirming the transitive-type fix works. Three other, previously-passing criteria (`AC-ASSEMBLE-006`/`011`/`013`) regressed, all for the identical cause: synthetic fixtures gave `constraints.md` a YAML frontmatter block, which `R-LINT-016` correctly rejects — unit files (`constraints.md`, and anything under `requirements/`, `interface/`, `acceptance/`) carry no frontmatter at all; only `component.md` does. `R-AUTHOR-012`'s existing "these fields are required" instruction was evidently over-applied to a file class it was never meant to cover.

## Decision

`R-AUTHOR-012` is amended with a fourth addition, stating the opposite rule just as explicitly: a unit file MUST carry no frontmatter at all. `test-author` is cold-regenerated against this amendment; `spec-bundle-assembler` is retried once more.
