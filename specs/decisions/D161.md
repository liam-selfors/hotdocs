# D161 — provenance-tracker-ui's no-generate-action check must exclude the snapshot data block

## Context

Re-run on `D158`'s corrected mutation gate, `provenance-tracker-ui`
passed eight of nine criteria with `mutation_score` 1.0. The one
failure was a contradiction inside the spec, not a candidate defect.
`R-UI-002` requires the snapshot embedded in a
`<script type="application/json" id="tracker-snapshot">` element, and
that snapshot carries `provenance-tracker`'s `not_ready_reasons`
verbatim, which read "... run hotdocs generate comp-foo".
`AC-UI-003` forbade the text "hotdocs generate" inside *any* script
element, so a correct candidate could not satisfy both.

## Decision

`AC-UI-003`'s check applies to executable script elements only; the
`tracker-snapshot` JSON block is excluded by name. `R-UI-003` states
that the data block is data, not an action.

With that fixed, the next round passed all nine criteria at
`mutation_score` 0.75. Nine of fourteen survivors were in `main`: no
test used the `--flag value` form, a flag with no value, a wrong
subcommand, or checked that `--model`/`--seed` reach
`check_readiness`. `interface/cli.md`, `R-UI-009`, and `AC-UI-009` now
state and exercise all four, the same gap `D160` closed for
`spec-completeness-assistant`.
