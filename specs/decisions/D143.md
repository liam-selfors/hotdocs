# D143 — test-author must read a fake's recorded invocation through sys.modules after the call, never a pre-call local reference

## Context

Seventh `review-packet-builder` retry (after `D142`'s fallback):
`AC-PACKET-007` now passes, but `AC-PACKET-001` newly fails with
`assert 0 >= 1` against `fake_tracker.calls` — the identical failure
shape already seen once before, at a different seed, on
`AC-PACKET-007` itself (flagged in `D142`'s own context as "not
re-triggered at the next seed, so not invested in further for now").
It has now recurred on a second, independent criterion, confirming it
is a real, systemic test-authoring gap rather than a one-off.

Both tests' own fakes correctly record their invocation in an
in-process list (`R-AUTHOR-022`'s own already-ratified rule is
followed to the letter: no guessed `sys.modules` key, a real recorded
invocation). The actual defect is one step earlier: both tests call
`importlib.util.spec_from_file_location`/`module_from_spec`/
`exec_module` themselves to install the fake and keep a local
variable (`fake_tracker`) pointing at *that* module object — then,
after calling `build_review_packet`, assert against
`fake_tracker.calls`. But `review-packet-builder`'s own loader
(correctly, per `R-GEN-018`) performs its *own*, separate
`exec_module` call every time it runs, producing a brand-new module
object with a fresh, empty `calls = []` and re-assigning
`sys.modules["provenance_tracker"]` to point at it. The test's local
`fake_tracker` variable still points at its own, now-orphaned earlier
module object — the two never share state, by construction, no matter
how correct the recording code inside the fake is. `R-AUTHOR-022`
closed the "guessed key" failure mode; this is a distinct failure mode
with the same root mechanism (a dynamic, per-call `exec_module` reload
defeats an assumption the test made about shared module state) that
nothing yet names.

## Decision

New `R-AUTHOR-024`: the prompt MUST instruct that when a generated
test needs to confirm a dynamically-loaded fake dependency was
actually invoked via the fake's own recorded-invocation list
(`R-AUTHOR-022`), it MUST read that record back through
`sys.modules[<module_name>]` **after** the function under test
returns — never through a local variable holding the test's own,
separate, pre-call load of the same file. A correct candidate's own
loader re-`exec_module`s a fresh module object on every call
(`R-GEN-018`), which replaces whatever `sys.modules` entry existed and
orphans any earlier local reference the test took before the call.
New `AC-AUTHOR-024`.

`test-author` is regenerated against this amendment, per its own `D58`
bootstrap exception (never via `bootstrap_component.py`, which cannot
be used on `test-author` or `verifier-orchestrator` themselves).
`review-packet-builder` is retried next.
