# D24 — `nodes`/`edges`/`component_docs` promoted to named views; adopted by `spec-linter`, `corpus-graph-builder`, and `merge-orchestrator`'s R-MERGE-014

## Context

Closes out the "candidates, not adopted" list `D22` itself had already
named, and fixes a real gap found while writing up the corpus-graph data
model for review: `R-IMPACT-009`'s original wording named three
frontmatter sources for node loading but never said how guarantee
nodes — the target side of a `depends_on_guarantees` edge — get
enumerated at all, since guarantee files carry no frontmatter.

## Decision

`graph-query-engine.md` gains a "Query surface" section naming three
views as the one shared surface every adopting component queries:
`nodes` (one row per spec id — components/capabilities/vars from
frontmatter, guarantees from `read_text()` + filename since they have
none, with `owner_component_id` resolved from path), `edges` (one row
per `(source_id, target_id, edge_type)`, unnested from each component's
list-valued frontmatter fields), and `component_docs` (frontmatter
joined with a component's full raw text).

`impact-analyzer`'s `R-IMPACT-009` now points at `nodes`/`edges`
directly, resolving the guarantee-node gap. `spec-linter`'s new
`R-LINT-020` adopts R-LINT-003/004/018 onto this surface.
`corpus-graph-builder`'s new `R-GRAPH-009` builds R-GRAPH-001/002
from it directly, with two component-local views
(`component_provenance`, `component_size` — the former later promoted
to shared by `D26`). `merge-orchestrator`'s new `R-MERGE-020` adopts
R-MERGE-014's capability-intersection lookup (later moved to
`golden-scenario-verifier` by `D25`).

**Explicitly deferred, not folded in** (later resolved by `D27`):
`spec-linter`'s R-LINT-008/009 (requirement-to-acceptance traceability)
walk a different graph — thought at the time to need a second node/edge
vocabulary.

## Consequences

All four adoptions are implementation requirements, not behavioral
ones — nothing about what any of the adopted rules require the *answer*
to be changed, only how the graph each walks gets built.

See `specs/architecture/graph-query-engine.md`'s "Query surface" and
"Scope of adoption" sections for the current, authoritative rules.
