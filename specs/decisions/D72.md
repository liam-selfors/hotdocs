# D72 — First real generate() call for test-author crashes on its own first cache write

## Context

A real `generate()` call for `test-author` produced an otherwise
well-reasoned candidate — correct `CriterionBundle` narrow-contract
enforcement (`R-AUTHOR-002`, structurally rejecting any unexpected
field), correct injectable-backend pattern mirroring `generator`'s own,
correct output path under `verification/<component>/generated-test/`.
It set `GATE_VERSION = "test_author@v1"`, reasonably mirroring
`generator`'s own `GATE_VERSION = "generator@1.2.0"` pattern — but
`cache-manager`'s `CacheKey.gate_type()` derives the gate type from
that exact string prefix, and its six-entry registry
(`interface/data/CachedResult.md`) has no `test_author` entry at all;
the real entry for this kind of artifact is `generated_test`.
Confirmed by direct test, not just reading: the candidate's own
`cache_manager.put()` call raised `SchemaValidationError: result.gate_type
'generated_test' does not match cache_key.gate_version's gate type
'test_author'` on its first real cache write.

`generator`'s `GATE_VERSION` prefix equaling its own gate type is a
coincidence (its artifact kind and its component name happen to be the
same word) — nothing in `test-author`'s own spec said this doesn't
generalize, and a real candidate reasonably assumed it did.

## Decision

Clarified directly in `R-AUTHOR-004`: the `gate_version` prefix MUST
be exactly `generated_test`, not this component's own name. The
buggy candidate's `gen/test-author/` output was deleted before being
committed, never swapped in.

## Consequences

A retry, with this fix in place, is the next real test. Sixth real
gap found by this self-hosted-generation sequence in an implicit
corpus convention that turned out not to generalize the way it looked
like it should (`D55`, `D57`, `D61`, `D62`, `D64`'s two, `D65`, `D67`,
now `D72`) — found only once a real candidate tried to follow the
pattern and a real cache write caught the mismatch immediately.

Linter: 0 failures once this file exists. Pytest: all 158 tests across
all thirteen real components re-verified unchanged (spec-only edit).
