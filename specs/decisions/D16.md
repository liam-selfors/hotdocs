# D16 — merge-tracker-ui is served via a trivial local static-file server, never opened via file://

## Decision

A developer opens the tracking UI through a minimal local server (static bytes only, zero backend computation) rather than the filesystem directly, avoiding `file://`'s CORS fragility. The query itself still runs entirely client-side via DuckDB-WASM — "no server process" in this corpus's broader sense always meant no backend *computation*, not no transport at all.
