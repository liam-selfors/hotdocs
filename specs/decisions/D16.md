# D16 — Behavioral guarantees are part of the contract; golden scenarios are a permanent backstop, not a transitional one

## Context

Arose from one question about `impact-analyzer`'s blast radius: should
`transitive-var`/`transitive-capability` inclusion cascade beyond one
hop? The answer — stay one-hop — only holds up once two real gaps it
exposed are closed together; neither alone was sufficient.

**Gap 1:** nothing ever actually ran golden scenarios. `SPEC_GUIDELINES.md`
§3.1/D8 described them as "exercised black-box against the assembled
system," but no component was assigned to execute them.

**Gap 2:** a component's real contract with its dependents isn't only
types. Swapping `cache-manager`'s backing store can leave every type
signature and drift check green while quietly changing a consistency
guarantee a dependent actually relies on — invisible to blast radius,
because that guarantee lived in `requirements/`, which dependents never
even receive.

## Decision

**Gap 1 fixed:** `merge-orchestrator` gains a gate — once every blast-radius
component passes per-component verification, run every intersecting
product capability's golden scenarios against the real assembled `gen/`
output, blocking the merge on failure. Permanent, not superseded once
gap 2 closes — documentation of foreseeable guarantees can never be
complete.

**Gap 2 fixed:** `interface/` gains a fourth kind,
`interface/guarantees/G-<comp>-NNN.md` — one behavioral/non-functional
guarantee per file, D15's one-file-per-unit convention extended to
behavioral contract content. A new optional field,
`depends_on_guarantees: [G-<comp>-NNN, ...]`, lets a dependent narrow its
blast-radius inclusion to only the specific guarantees it relies on —
**strictly opt-in**: silence still gets the safe, coarse default (any
`interface/` file change propagates).

## Consequences

The under-declaration risk `depends_on_guarantees` introduces (claiming
reliance on fewer guarantees than actually exist, producing a
false-negative blast-radius miss) is exactly why the golden-scenario
gate stays permanent rather than superseded — it's the backstop for
precisely that class of wrong-but-locally-plausible claim.
`impact-analyzer`'s R-IMPACT-002/003 generalized from enumerating
`interface/` file types by name to "any file under `interface/`," so
future `interface/` kinds need no further edit.

See `SPEC_GUIDELINES.md` §1–§3.4 and §6 step 5, and
`specs/components/impact-analyzer/`, `specs/components/merge-orchestrator/`
(later refined by `D25`) for the current, authoritative rules.
