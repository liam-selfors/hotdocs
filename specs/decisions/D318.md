# D318 — One JSON conversion that never raises

## Context

`provenance-writer`, `provenance-tracker` and `component-gate-runner`
each converted results to JSON their own way, falling back to `vars()`
for anything that was not a dict, list, string or number. A failing
generated test whose `failure_detail.actual` was a `set` made
`write_provenance` raise `TypeError: vars() argument must have __dict__
attribute`, so `hotdocs generate` ended in a traceback with no attempt
record or provenance (issue #2).

## Decision

`specs/architecture/json-values.md` gives one conversion, implemented by
all three components: sets become sorted lists, `bytes` decoded text,
paths strings, enums their value, dataclasses their fields, objects with
a `__dict__` their public attributes, and anything else its `repr`. It
never raises.

## Consequences

Any value a test, model or scanner reports reaches the manifest, the
attempt record and `--format=json` output. A set's order is fixed, so
the written manifest is stable.
