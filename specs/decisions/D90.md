# D90 — Atomicity and citation discipline, made explicit rather than assumed

## Context

The user raised a direct concern: a trace of decisions bundling
multiple topics risks becoming internally confusing over time, and
citations that aren't checked against what they actually name risk
quietly going wrong. Both concerns are already real in this corpus.
`D87` itself bundled the `supersedes` mechanism with an unrelated
mis-citation fix found while verifying it — two topics, one record.
Separately, `D87` and `D89` each found a real citation pointing at
the wrong decision (`D45` credited for a fact only `D46` states) —
not because the citation was dangling (it resolved to a real file,
`R-LINT-026` would have found nothing wrong), but because nobody had
checked it said what it was being used to support.

## Decision

`SPEC_GUIDELINES.md` §3.5 gains two rules. Atomicity: a decision
record must cover exactly one topic, tested with a concrete question
— does removing any one paragraph leave the rest meaning something
different? If not, split it. `D87` is named explicitly as a known,
immutable exception that does not meet this bar, rather than silently
grandfathered in. Citation discipline: a `D<N>` citation must point
to the specific decision responsible for the specific fact stated,
checked against that decision's own text before relying on it —
not assumed correct because it resolves to a real file.

A third paragraph documents the practical, zero-tooling side of the
user's "drift protection" ask: `grep -rn '\bD<N>\b' specs/
--include="*.md" | grep -v '^specs/decisions/'` as the canonical
pre-deprecation check, excluding `specs/decisions/` deliberately —
a citation inside another decision's own frozen historical narrative
is never a drift candidate, only one inside a live spec file is.
Verified this already works cleanly against the real corpus today
(citation formatting is already consistent enough that no new
formatting rule was needed).

## Consequences

This decision's own existence is itself the first real application of
the rule it states: `builds_on` (originally drafted alongside this
text) was split out as `D91` once checked against the same atomicity
question — a schema addition is a different topic from a citation
discipline rule, even though both were drafted in the same sitting.
