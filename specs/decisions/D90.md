# D90 — review-packet-builder consumes provenance-tracker's own query rather than duplicating it

## Context

`review-packet-builder`'s job — formatting already-computed results for human review, never the generated code diff itself — overlaps substantially with what `provenance-tracker`'s own live query (`D88`) now assembles: per-component and per-capability provenance state across a scope. Building a second, independent aggregation would duplicate logic that already exists and already has to stay correct.

## Decision

`review-packet-builder` depends on `provenance-tracker` directly, consuming its provenance-query capability to build a static, point-in-time exportable artifact (for a PR description or an equivalent static review surface) rather than re-deriving the same aggregation itself. It remains its own component — the artifact it produces (a static export, reviewed once per spec change) is a genuinely different lifecycle from `provenance-tracker-ui`'s live, continuously-current interactive view, the same distinction `merge-tracker`/`docs-site-renderer` already drew between local-only and CI-rendered output.
