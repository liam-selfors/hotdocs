# D11 — cache-manager's eviction/retention policy has no correctness dimension

## Decision

A cache `get` already must return a definitive miss, never an approximation — an evicted entry is, to a caller, indistinguishable from a plain miss. Eviction can happen for any reason, at any time, with zero correctness impact, only ever affecting hit rate. The exact policy stays deliberately unpinned: the backing store is pluggable, and the right policy depends on which store it ends up being.
