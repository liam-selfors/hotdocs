# D364 — hotdocs capability new lays out a capability file

## Context

`hotdocs component new <slug>` writes `realizes: []`, which lint
rejects: a component must realize a capability. Nothing laid out a
capability file, so a new user's first scaffolded component failed lint
until they wrote `specs/product/<name>.md` by hand from an example.

## Decision

`spec-scaffolder` gains `new_capability` and the command
`hotdocs capability new <name>` (`R-SCAFFOLD-009`). It writes
`specs/product/<name>.md` with the id `P-<NAME>`, a title and a `Purpose`
section to fill in, and prints the path and the id. `hotdocs-cli`'s verb
table gains the row. `component new` is unchanged: its `--realizes` flag
already takes the id.

## Consequences

`hotdocs capability new order-book` followed by
`hotdocs component new order-book --realizes=P-ORDER-BOOK` lints clean.
`spec-scaffolder` and `hotdocs-cli`, both leaves, are regenerated.
