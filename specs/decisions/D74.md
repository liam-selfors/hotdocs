# D74 — Fourth real call lands, after two spec fixes and one plain retry

## Context

`D72` fixed `test-author`'s required `gate_version` prefix. `D73`
added the missing `llm_backend` parameter to `interface/library.md`.
A third real `generate()` call, with both fixes in place, produced a
candidate whose dependency loader had a plain implementation bug — an
asymmetric path error between its correct package-loading branch and
its incorrect flat-module-loading branch — not a spec gap, since the
candidate's own code demonstrated it already knew the correct nested
convention one branch earlier. Deleted, not swapped in.

A fourth attempt, run as a plain retry with no spec change, returned
the *same* rejected candidate from cache — correctly: nothing about
the component's `SpecBundle` had changed, and the cache key has no way
to know a human rejected that exact result for a reason outside the
key itself. Forced a genuinely fresh call by deliberately deleting
that one specific stale cache entry, confirmed first by inspecting its
payload before removing it.

## Decision

The resulting candidate correctly nests its flat-module dependency
lookups. Verified against all 8 `AC-AUTHOR-*` criteria for real,
including one using the real `spec_bundle_assembler.assemble_criterion`
against the real repo — the strongest available check that a
genuinely narrow `CriterionBundle` carries nothing from a component's
real `gen/` source. Swapped in.

A real operational hazard was found and fixed during the swap: an
earlier `rm -rf gen/test-author` left a stale `test_author/` *package*
directory sitting alongside the final flat `test_author.py` module
once a cache-hit replay re-wrote it — Python's import machinery
silently prefers a same-named package over a flat module, so tests
would have quietly run against rejected code. Caught by a failing
traceback naming the rejected candidate's own internal structure, not
by assuming a clean `rm -rf` had actually been clean.

## Consequences

Fourteenth real component built — the last in batch 1 of this
session's regen plan (`criterion-compiler`, `provenance-checker`,
`impact-analyzer`, `license-scanner`, `secret-scanner`,
`docs-site-renderer`, `test-author`, all now real). Batch 2
(`capability-scenario-verifier`, `verifier-orchestrator`,
`spec-completeness-assistant`) depends on several of these — their
real `dependency_usage` surfaces will be exercised for the first time
there.

Linter: 0 failures once this file exists. Pytest: 166 tests across all
fourteen real components, 8 of them this component's own.
