# D296 — `hotdocs` turns an unresolvable model into a usage error

## Context

`hotdocs track ui build --model=<a name no provider knows>` ended in a
traceback: `llm-endpoint` raises `ModelResolutionError` for such a
model (`R-ENDPOINT-002`) from wherever a gate first calls it, deep in
`capability-scenario-verifier`, and nothing above caught it. Every verb
that can reach a model call has the same exposure.

## Decision

`hotdocs-cli`, which dispatches every verb, catches an exception whose
class is named `ModelResolutionError`, prints `usage error: <message>`
to stderr and returns `2` (`R-CLI-006`, `interface/cli.md`). It matches
by name because each component loads its own copy of `llm-endpoint`,
so the classes are never the same object. Any other exception still
propagates. `AC-CLI-006` covers both.

## Consequences

`hotdocs-cli` is regenerated; no other component depends on it.
