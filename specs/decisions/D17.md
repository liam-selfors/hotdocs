# D17 — Diagnostic-guided retry: feed best-of-k failed-requirement ids back, via graph topology, not test content

## Context

Resolving best-of-k's exact `k` value turned into something more
fundamental after three proposals were each ruled out in turn:
(1) drop retry entirely, treat any failure as an underspecified
requirement — rejected, pushes real spec-authoring overhead onto every
transient generation miss; (2) feed the retry the prior attempt's code
as hint context — rejected, that's external/stale state, exactly
`hint_code`'s risk (D1); (3) feed back which acceptance criteria failed,
including Gherkin text — rejected, reopens `spec-bundle-assembler`'s
exclusion of `acceptance/` from what a generation model ever sees, the
same overfitting risk in degree if not in kind.

## Decision

Lean on graph topology that already exists: every acceptance criterion
already declares `Covers: R-<id>`. Project each criterion's pass/fail
onto the `R-id`(s) it covers (AND-aggregated — any failing *or skipped*
covering criterion makes that requirement `fail`), and feed back
**only that projection** — a bare `{R-id: pass|fail}` map, never Gherkin
text, rationale, or expected/actual values.

This resolves all three objections at once: derivable entirely from the
current spec bundle plus the current sequence's own output (cold-mode
safe); discloses nothing beyond "your attempt didn't satisfy text you
already had" (a requirement's text is already in the bundle); still
concrete enough to turn a blind re-roll into a targeted edit.

## Consequences

`verifier-orchestrator` gained `R-VERIFY-011` (`requirement_results`,
stricter than `overall`'s own skip-handling). `generator` gained
`R-GEN-010` (`retry_feedback`, a pure pass-through, folded into the
cache key). `merge-orchestrator`'s best-of-k loop extracts only the
*immediately preceding* attempt's failures — not accumulated across
more than one prior attempt. `k`'s default resolved to 2 (one blind
attempt, one informed retry), overridable via a new `best_of_k`
frontmatter field. Provenance gained a `retry_feedback` field for audit.

(The retry *trigger* itself was later generalized by `D21` to also fire
on a `generator`-level `model_call_error`, not only a verification
failure — this decision's feedback-content mechanism is unchanged by
that.)

See `SPEC_GUIDELINES.md` §2 (`best_of_k`), §7 (provenance schema), and
`specs/components/{generator,verifier-orchestrator,merge-orchestrator,
provenance-writer}/` for the current, authoritative rules.
