# D124 — mutation_score must be a union across a component's own generated-test criteria, never an average of per-criterion-isolated scores

## Context

With `D119`–`D123` landed, `provenance-tracker`'s real acceptance criteria finally all passed behaviorally — but `verify()`'s separate mutation-score gate still failed, consistently, across every attempt (scores from 0.04 to 0.14, against an 0.8 bar), regardless of how correct or well-written any individual criterion's test was.

Diagnosis: `verifier-orchestrator`'s own mutation testing generates mutants once, from the *whole* candidate module, then scores *each* `generated-test` criterion's own test file in isolation against all of them, and averages the per-criterion scores. `provenance-tracker` has three behaviorally distinct entry points (`write_attempt_record`, `last_requirement_failures`, `check_readiness`); a criterion whose own Gherkin scope covers only one of them has no way to kill a mutant living in a sibling function, no matter how thorough its own test is — it is being scored against code it was never asked to cover. `interface/data/VerificationReport.md` already documents `mutation_score` as exactly one number per component, never one per criterion, confirming the averaging-of-isolated-scores approach was never the intended design — `SPEC_GUIDELINES.md` §5's "a `generated-test` criterion's mutation score MUST meet 80%" means the criterion's test contributes to one shared, component-wide number, not that it must independently defeat the whole module alone.

This is a structural gap affecting any multi-function component scored this way, not specific to `provenance-tracker` — confirmed directly with a new, minimal two-function fixture in the hand-maintained suite (`comp-foo` with `do_the_thing`/`double_it`, each covered by its own test): under the old algorithm the reported score was 0.25 despite both tests passing cleanly and each fully covering its own function.

## Decision

`R-VERIFY-006` is amended: `mutation_score` MUST be computed as a union across all of a component's own `generated-test` criteria's test files — a mutant counts as killed if *any* of them fails against it — never an average of narrower, per-criterion-isolated scores. New `AC-VERIFY-015`. `verifier-orchestrator` is cold-regenerated against this amendment, validated directly against the hand-maintained suite (per `D119`'s own exemption from the full self-verifying bootstrap cycle). `provenance-tracker` is retried once more.
