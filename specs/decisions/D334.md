# D334 — Only a function standing in for a dependency is checked as a fake

## Context

`test-author`'s fake-arity check (`R-AUTHOR-020`) treated every
top-level function of a generated test whose name matched a dependency
function as a fake of it. A test for a component depending on one whose
interface has `build_graph(manifest, *, plan=None, dbt_links=None)`
defined its own zero-argument helper `build_graph()` that stood in for
nothing, and authoring failed with `fake_signature_mismatch`; four of
nine criteria of one `hotdocs generate` failed this way (issue #12).

## Decision

A function is checked only when it stands in for a dependency function:
defined in a string literal that parses as Python, the source of a fake
module, or installed under a dependency function's name by
`monkeypatch.setattr`, `setattr` or attribute assignment, and then
checked as that name. A top-level helper installed nowhere is never a
fake. `AC-AUTHOR-020` installs its fakes accordingly, and `AC-AUTHOR-029`
covers the helper. `GATE_VERSION` becomes `generated_test@1.2.0`.

## Consequences

A fake made some other way, such as a class attribute, escapes the
check, which stays best-effort (`D110`).
