# D221 — `llm-endpoint` states missing-key behavior, and its criteria give their fixtures exactly

## Context

Seed 2 of `llm-endpoint` failed six criteria, mostly on fixtures the
criteria left loose: a test wrote an invalid `hotdocs.toml` through
`save_config`, which rightly refuses it; another wrote a table without
`provider`; a third read the `x-api-key` header in the wrong case, since
`urllib.request.Request` capitalizes header names. And the spec never
said that a missing key for `anthropic`, `openai` or `gemini` is an
`auth` error with no network call, which the hand-written version did
and a test did not expect.

## Decision

`R-ENDPOINT-005` states the missing-key rule. `AC-ENDPOINT-005` sets the
three keys before the HTTP scenarios, `AC-ENDPOINT-001` writes its
invalid file as text, `AC-ENDPOINT-011` gives its table's values, and
`interface/library.md` notes how header names are stored.

## Consequences

`llm-endpoint` is regenerated against it.
