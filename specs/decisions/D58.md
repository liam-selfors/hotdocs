# D58 — The fourth real retry closes the loop

## Context

`D54` found generator's self-regeneration failing on an import-path
assumption. `D55` fixed that gap (`dependency_usage`). `D56` found and
fixed a self-referential delimiter collision and a degenerate
empty-files caching bug. `D57` found and fixed a real crash in a
candidate's dynamic dependency-loading technique (missing `sys.modules`
registration) and a schema table that was real but invisible to any
dependent. Four real, billed retries, four genuinely different findings
— none a repeat of a prior failure class.

A fourth real retry, with every fix above in place, produced a
complete, 537-line candidate. Unlike the prior three, this one:

- Registers each dynamically-loaded dependency module in `sys.modules`
  *before* running its code — `R-GEN-014`'s exact requirement,
  satisfied correctly, with a comment in the generated code citing
  `D57` directly.
- Writes a `put` payload containing `component_id`, `model`,
  `prompt_version`, and `files` — every key `cache-manager`'s real
  schema requires.
- Independently arrived at the same per-call nonce design this
  component's own installed code already used, including the same
  "describe it in prose, don't reproduce it literally" instruction —
  without ever having seen that code (cold mode never includes it).

## Decision

Verified against all 12 of this component's own testable `AC-GEN-*`
criteria (`001`–`006`, `008`, `009`, `012`–`015`) for real, run against
real copies of `cache-manager`/`llm-endpoint` with an injected mock
backend — including `AC-GEN-015`, written specifically to exercise the
exact crash `D57` found. All 12 passed. Two test-harness bugs were
found and fixed *in the verification harness, not the candidate* while
writing these checks: the candidate's generic rules text names
`HINT_CODE`/`RETRY_FEEDBACK`/`Gherkin` in prose explaining the
convention on every call, which a naive whole-prompt substring check
mistook for actual leaked content — fixed by scoping each check to the
real labeled section the data would appear in, not the whole prompt.

Swapped in. `gen/generator/generator.py` is now this candidate, not the
`D50` hand-authored bootstrap. `verification/generator/{conftest.py,
test_generator.py}` rewritten to match its real conventions: the nonce
lives directly in `prompt`, not a separate `system_prompt` parameter;
`repo_root`'s fixture now stages real `cache-manager`/`llm-endpoint`
copies under `tmp_path`, since dependencies load dynamically from
`repo_root` per call rather than via a static `sys.path` entry.
`BOOTSTRAP.md` is kept, explicitly, as the historical record of how
this component came to exist and what each real attempt against it
found — not as a description of the code now installed.

## Consequences

Four billed retries to get here, each finding something real. This is
the methodology's own discipline working exactly as designed across
`D54`–`D58`: verify fully against real acceptance criteria before ever
swapping, reject anything that doesn't pass regardless of how
plausible it looks, and treat each failure as a real finding worth
fixing at its actual layer (spec, prompt, or test harness) rather than
patching around it. `generator` joins `llm-endpoint` (`D51`/`D53`) as
the second component in this corpus whose installed code is itself a
product of this pipeline, not hand-written.

Linter: 0 failures once this file exists. Pytest: every component's
suite re-verified after the swap (96 tests total across all seven
real components), not just `generator`'s own 12.
