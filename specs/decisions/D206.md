# D206 — `criterion-compiler` is generated from its spec and stays sealed

## Context

The MVP claims that every component's code is cold-generated from its
spec. `criterion-compiler` was the exception by design: its spec said it
was "never agent-generated", because a `compiled` criterion is trusted
only if nothing model-written sits between the criterion and its check.

Two things already carried that trust without depending on who wrote the
code. `sealed: true` makes `generator` refuse the component, so the
pipeline can never regenerate or swap it on its own (`R-GEN-009`). And
`verifier-orchestrator` verifies a sealed component only by its
hand-maintained characterization suite in
`verification/criterion-compiler/`, written by a person and independent
of any implementation.

## Decision

`criterion-compiler`'s code is generated from its spec like every other
component's. It stays `sealed: true` at `pipeline/criterion-compiler/`.

A version is produced outside the pipeline: generated unsealed in an
isolated sandbox, required to pass its generated tests, mutation testing
and the hand-maintained characterization suite, and then installed at
`source_path` by a person (`tools/bootstrap_component.py
--sealed-install`). `generator` still refuses it, and `hotdocs verify`
still checks it only against the hand-maintained suite.

The trust anchor moves from "a person wrote the code" to "a person wrote
the suite that every installed version must pass, and a person installs
it". The characterization suite is never generated and is edited only
by hand.

## Consequences

`component.md`'s Purpose and Rationale say this instead of "never
agent-generated". The hand-written implementation from `D44`, `D59`,
`D62` and `D83` is replaced by the generated one. Every later change
goes through the spec and another `--sealed-install` run, never through
an edit of the installed file.
