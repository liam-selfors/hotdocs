# D125 — two more real bugs found with mutation scoring finally working — wrong capability-scenario-verifier function name, and a PyYAML import in a generated test

## Context

With `D124`'s union-mutation fix landed, `provenance-tracker` reached `mutation_score=1.0` directly — confirming the gate itself is now sound. Two real issues remained, surfacing across the next two retries:

- `AC-TRACK-010` failed at two different seeds with the identical symptom: the real candidate calls `capability_scenario_verifier.run_capability_scenarios` instead of `run_capability_gates`. `R-TRACK-010` already names `run_capability_gates` explicitly in prose — the two names are close enough, on the same dependency, that prose alone naming the right one was not reliably sufficient, the same "worked snippet beats prose" lesson this corpus has learned repeatedly for other requirements.
- `AC-TRACK-004` failed with `ModuleNotFoundError: No module named 'yaml'` — a generated test for `provenance-tracker` reinvented frontmatter parsing with PyYAML, the identical mistake `D101`/`R-ASSEMBLE-012` already closed for a real *candidate's* own code. That fix was scoped to `spec-bundle-assembler`'s own generation; nothing in `test-author`'s own spec stated the same rule for test-authoring itself, so it was free to recur in a completely different component's fixtures.

## Decision

`R-TRACK-010` is amended with the literal worked call (`run_capability_gates(capability_id, repo_root, judge=judge, test_author=test_author)`), naming `run_capability_scenarios` explicitly as the wrong, different-purpose sibling to avoid. `R-AUTHOR-012` is amended: a test MUST NEVER `import yaml` or any other not-already-installed third-party package — the same `D101` lesson, generalized to test-authoring itself rather than left scoped to one candidate's own code.

`test-author` is cold-regenerated against the `R-AUTHOR-012` amendment; `provenance-tracker` is retried once more.
