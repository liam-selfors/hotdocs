# D324 — Mutation runs mirror the criterion run's layout and need a passing baseline

## Context

`verifier-orchestrator` copied `gen/<slug>/` to `<tmp>/<slug>/` for
mutation testing, so a component that loads a dependency by path from
its own `__file__` could not find it there, though its criteria passed
(issue #9). It then ran the tests once unmutated only to time them,
ignoring the outcome: a baseline that failed made every mutant count as
killed, a spurious score of 1.0, and one that timed out gave every
mutant a 3000-second timeout, an 8-hour `hotdocs generate` in the demo
build (issue #8).

## Decision

Mutation runs follow `specs/architecture/mutation-runs.md`
(`R-VERIFY-014`). The copy sits at `<tmp>/gen/<slug>/` beside links to
every other `gen/` directory, so path-loaded dependencies resolve as
in the criterion run. Only the tests of passing criteria run. They must
pass once unmutated before any mutant runs; otherwise `mutation_score`
is `null`, `overall` is `fail` and the new `mutation_error` says why.
`GATE_VERSION` becomes `verifier-orchestrator@2.2.0`.

## Consequences

A test that only passes from `repo_root` now fails verification
instead of inflating the score. The version bump makes every
provenance key using this gate miss once.
