# D26 — `review-packet-builder`'s redundant fan-out dropped; `merge-tracker-ui`'s local-open question resolved to a trivial static-file server

## Context

Two small, unrelated loose ends closed together, both flagged during a
warnings/next-steps review that followed `D25`.

## Decision

**`review-packet-builder`'s fan-out (5 → 1).** It depended directly on
`verifier-orchestrator`, `license-scanner`, `secret-scanner`, and
`cache-manager` — but every field it reports from them was already
sitting in `provenance-writer`'s manifest, which it already depended
on; none of those four write their own file. New `R-PACKET-011` makes
this explicit (read via `component_provenance`, never a live call).
`component_provenance` (previously scoped to `corpus-graph-builder`
alone, `D24`) was promoted into `graph-query-engine.md`'s shared Query
surface once a second consumer needed it — the same reasoning that
already governs `nodes`/`edges`/`component_docs`.

**`merge-tracker-ui`'s open question — resolved, not deferred again.**
Whether a developer opens the built page via `file://` (CORS-fragile)
or a trivial local server. Resolved to the server (`R-UI-006`, `hotdocs
track ui serve`): static bytes only, zero backend computation,
DuckDB-WASM still runs the query entirely client-side.

## Consequences

`R-UI-001`/`constraints.md`'s "no server process" wording was clarified
to mean "no backend *computation*" — the posture was always about
where the query runs, not the transport used to open the page; the old
wording read as a contradiction once a server entered the picture at
all. `AC-UI-001` updated accordingly.

See `specs/architecture/graph-query-engine.md`'s "Query surface"
section, `specs/components/review-packet-builder/requirements/
R-PACKET-011.md`, and `specs/components/merge-tracker-ui/requirements/
R-UI-006.md` for the current, authoritative rules.
