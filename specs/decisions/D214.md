# D214 — The step-phrase grammar defines its argument, literal and result-path forms exactly

## Context

The first generation of `criterion-compiler` from its spec (seed 2,
mutation score 1.0) failed four of fifteen criteria. Three traced to the
grammar and the interface, not the code. `<args>` was never defined, so
a generated test wrote `with text: payload` while the candidate read an
object literal. Nothing said how an unmatched step is quoted, so the
candidate dropped the keyword a test expected. And nothing said what
`compile_criterion` compiles with no interface surface, so a test called
a function without one. The hand-written compiler had settled each of
these in code: one literal for `<args>`, the keyword kept, and only
surface-free steps compiling without a surface.

## Decision

`specs/architecture/step-phrase-grammar.md` gains "Exact forms": the
identifier forms, a literal as a JSON value in which a bare fixture name
may stand for a scalar, `<args>` as one literal (object to keyword
arguments, array to positional, otherwise one argument), and the
`<result-path>` form. These are what the hand-written compiler accepted,
so no existing criterion changes meaning. `CompileReport.md` gives the
unmatched-step message with its keyword, and `interface/library.md` says
which steps compile with no surface.

A second generation (seed 3) showed two more gaps. `R-COMPILE-001`
asks for a "located" error, but the hand-written compiler never put a
line anywhere in its output; `CompileReport.md` now starts each error
message with `line <n>: `. And `AC-COMPILE-007` let a test look for the
bound payload as a module-level name, where the grammar binds a local
inside the test function; it now says exactly what to check.

## Consequences

`criterion-compiler` is regenerated. The fourth failure, a candidate
that left a fixture name unsubstituted, was a code defect, which a new
seed addresses.
