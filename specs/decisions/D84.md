# D84 — Interface drift is one-directional — extra undocumented public names are never drift

## Context

A real `generate()` candidate for `verifier-orchestrator` implemented `R-VERIFY-004`'s interface-drift check as set equality between `interface/library.md`'s documented callable names and every public function/class the target module actually defines. This produced false-positive drift on an entirely unchanged, non-drifted test fixture: the fixture's target module defines both a documented function and an undocumented return-type dataclass, and the dataclass's mere existence as an extra public name made the two sets unequal. `R-VERIFY-004`'s own wording — "the generated code's actual public interface MUST match the component's `interface/` contract exactly" — is genuinely ambiguous about which direction "exactly" binds, since it doesn't specify whether extra, undocumented public names count as a violation.

## Decision

Interface drift checks one direction only: every callable `interface/` documents MUST exist with a matching signature. A module defining additional public names `interface/` never documented is never drift on that basis alone — those names are either genuinely internal, or already covered by `interface/data/`'s own separate contract for return/argument shapes. `R-VERIFY-004` now states this explicitly.
