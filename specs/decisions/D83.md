# D83 — Checking an existing cross-reference's claim against real code found it was also wrong

## Context

A pre-generation audit of `provenance-writer`'s dependency contracts
(the same proactive check that found `D81`/`D82`), before this
not-yet-built component is ever generated, found that two of its
manifest's fields — `pipeline_version` and `verification_run_id` —
appear in the bundle-visible `interface/data/provenancemanifest.md`
JSON example but have no requirement stating where either value
should come from, and `ProvenanceInputs` (the component's own input
schema) contains neither field.

Checking the one existing cross-reference that did claim a source for
a third field — `R-PROV-002`'s "`spec_bundle_hash`... MUST be
populated from `generator`'s `GenerationResult`" — against
`generator`'s real, already-swapped-in code found the claim was also
false: `GenerationResult`'s real dataclass
(`gen/generator/generator.py`) has no `spec_bundle_hash` field at all.
The same pattern as `D82`'s spec-linter mis-citation: a claimed source
existed, but nobody had checked it against the thing it claimed.

## Decision

Fixed at the true source rather than inventing a workaround in
`provenance-writer`: added `spec_bundle_hash` to `GenerationResult`
itself (new `R-GEN-017`/`AC-GEN-018`), since `provenance-writer` has no
other dependency (it does not depend on `spec-bundle-assembler`) that
could supply it.

`pipeline_version` (`R-PROV-012`): a component-owned version constant,
mirroring `generator`'s own `PROMPT_VERSION`/`GATE_VERSION` pattern —
bumped when this component's manifest-population logic changes, never
computed from input.

`verification_run_id` (`R-PROV-013`): a deterministic
`"<slug>-attempt-<attempts>"` construction from `ProvenanceInputs`'
own `component_id`/`attempts` fields. Not an arbitrary design choice —
`constraints.md`'s existing determinism requirement ("given the same
`ProvenanceInputs`, the written manifest MUST be byte-identical across
runs") already forbids a freshly generated random id; this just makes
the specific construction explicit instead of leaving it to be
independently guessed.

Two new real tests on the `generator` side (`test_ac_gen_017`/`018`,
part of this commit) confirm the gap against the current, unfixed
`generator.py` — both correctly fail, ready for the fix once a real
`generate()` call lands. `provenance-writer` has no `gen/` or
`verification/` yet; both of its fixes are spec-only, waiting for its
first real build.

## Consequences

Eighth occurrence of the "fact one component needs from a dependency
(or claims to have, but doesn't) was never actually sourced correctly"
gap class this session (`D61`, `D62`, `D65`, `D67`, `D69`, `D76`,
`D80`, `D82`), and the third caught proactively (`D81`, `D82`, this
one) before a real `generate()` call was spent on the affected
component. The specific lesson from this one, distinct from `D82`'s:
a *claimed* source is not evidence the source actually exists — check
the claim against the real code it points to, not just whether a
citation is present.
