# D330 — Re-ratify the secret allowlist after the demo-fix regeneration

## Context

Regenerating `generator` for the demo-build fixes produced a test,
`verification/generator/generated-test/test_ac_gen_018.py`, whose
parametrized fixture hash, a 16-character hex run repeated four times,
the scanner reads as a hex high-entropy string. `.secret-allowlist.json`, sealed by
`D294`, did not cover it, and because re-recording provenance scans the
whole repo, every manifest re-recorded since recorded `flagged`, so
`hotdocs verify` reported fifteen components not ready.

## Decision

The allowlist is the scanner's own `propose()` output: the 57 existing
entries plus that one, `planted-fixture`, checked by hand. This record
carries its hash.

## Consequences

A full scan is clean again; the fifteen components are re-recorded so
their manifests carry the clean scan.
