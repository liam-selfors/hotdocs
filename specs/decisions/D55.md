# D55 — `dependency_usage`: real usage facts flow one way, down the DAG

## Context

`D54` found that `generator`'s self-regeneration attempt failed to
import because it guessed wrong about `cache-manager`'s real module
layout — nothing in this corpus's methodology had ever required a
component to state, as part of its interface contract, how a dependent
should actually import it. Two directions for a fix were considered:

1. A static "Importable as: ..." line hand-written into
   `interface/library.md` — cheap, but goes stale the moment a
   dependency's own internal shape changes again (as `llm-endpoint`'s
   already has, three times), unless a human remembers to update it
   every time.
2. A live-derived fact, mechanically introspected from whatever the
   dependency's real code currently is, recomputed fresh on every
   assembly — never stale, because it's never hand-maintained.

A third idea — feeding a dependency's *dependents'* real call-site usage
back into the dependency's own regeneration, to "harden" it against
real-world usage — was raised and rejected: it would reintroduce a
cycle into what `depends_on` otherwise keeps acyclic (a dependency
regenerated to fit today's usage could invalidate that same usage,
forcing dependents to regenerate again, repeating), and it would let
accumulated calling patterns steer a dependency's real behavior instead
of its own normative `interface/` contract — the exact spec-drift
failure mode this corpus's own discipline (`D42`–`D54`) exists to catch,
not reproduce.

## Decision

Option 2, one-directional only. `spec-bundle-assembler` (`R-ASSEMBLE-011`)
now derives a third field, `dependency_usage`, alongside the existing
`dependency_interfaces`/`dependency_context`: for each real dependency,
its actual importable module path and the signature/docstring of each
public top-level symbol its current `gen/` code defines — introspected
directly (`inspect`), never read from source text, never from
`acceptance/`. Empty for a dependency with no real code yet, or whose
code fails to import for any reason — fail-to-empty, the same posture
`R-GQE-005`/`R-CACHE-004` already take elsewhere, never a crash that
blocks assembling the rest of the bundle.

**This requires dependency order, not an arbitrary or parallel one,
whenever more than one component in the same pass needs regeneration.**
`merge-orchestrator` gained `R-MERGE-023`: generation calls within one
merge's blast radius MUST be sequenced so a component's `generator`
call never starts before every `depends_on` target also in that blast
radius has completed its own — narrowing `R-MERGE-008`'s existing
"independent gates may run in parallel" exactly along the one edge that
was never actually independent, not every pair in the blast radius.

**Deliberately, explicitly one-directional** — restated directly in
`R-ASSEMBLE-011` itself, not left implicit: a dependency's own bundle
never carries anything about how its dependents use it. If a dependent's
real need reveals a dependency's contract is genuinely missing
something, that's a human-reviewed `interface/` spec change, flowing
through `impact-analyzer`'s blast radius the normal way — never a
generation-prompt input derived from accumulated usage.

A drift-check (comparing dependents' real usage against a dependency's
documented contract, surfacing a mismatch for human review) was also
discussed as the safer way to capture the same underlying goal the
rejected feedback-loop idea was reaching for. Deliberately **not**
built here — tracked as a deferred follow-up, not silently dropped.

## Consequences

Re-attempting `generator`'s self-regeneration (`D54`) with this field
present is the real test of whether this actually closes the gap —
done separately, not assumed here, once this decision's own
implementation is verified on its own terms first.

`SpecBundle` gains a field for the third time (`component_id`'s
siblings: `dependency_interfaces`, D-original; `dependency_context`,
`D35`; now `dependency_usage`) — each added only once a second real
need for exactly that shape appeared, never spawned speculatively.
