# D47 — Real `llm-endpoint`; the `.claude/agents/` subagents retired

## Context

`D45` built four Claude Code subagents to simulate `llm-endpoint`'s
real callers, and used one of them to cold-generate `corpus-graph-
builder`. `D46` confirmed `claude -p` (the CLI's own non-interactive
mode) is a real, scriptable alternative — explicit model selection,
structured JSON output, a system prompt passable via a flag — and
pinned down exactly how it bills (`ANTHROPIC_API_KEY`, when set,
always wins over a Pro/Max login).

That made the subagent definitions themselves redundant: everything
they did, a real `llm-endpoint` built around `claude -p` does too,
without `.claude/agents/`'s unfixed reproducibility gap (`D45`'s own
open item — the definitions were gitignored, so nothing about them
survived a clean clone).

## Decision

**`.claude/agents/generator.md`, `test-author.md`, `judge.md`, and
`spec-completeness-assistant.md` are deleted.** Removed, not replaced
in place — the four model-call boundaries they simulated still need
real implementations, built the normal way (hand-authored bootstrap
exceptions, same as `spec-linter`/`graph-query-engine`), not as a
second generation of subagent definitions.

**`gen/llm-endpoint/llm_endpoint.py` is the first of those four, real.**
A fourth hand-bootstrapped component, but a structurally different,
permanent exception: `spec-linter`/`graph-query-engine`/`corpus-graph-
builder` are bootstrap exceptions because no real `generator` exists
*yet*; `llm-endpoint` can never be produced the normal way even once one
does, because `generator` would dispatch through `llm-endpoint` to do
the generating — nothing could ever generate it first. Implements
R-ENDPOINT-001–006:

- `complete(prompt, model, *, backend=None, **params) -> ModelResponse`
  — the `backend` parameter is new (`interface/library.md`), a
  pre-existing gap: every one of this component's own acceptance
  criteria already required "an injected mock backend," the same
  dependency-injection pattern `spec-linter`'s `judge` and
  `verifier-orchestrator`'s `judge`/`test_author` parameters already
  establish, just never written into the interface spec until now.
- Model-to-backend resolution (`R-ENDPOINT-002`) is a plain naming-
  pattern match (`claude-*` → Anthropic), raising `UnsupportedModelError`
  immediately for anything else, before any call is attempted.
- `AnthropicBackend` (`R-ENDPOINT-003`) dispatches via `claude -p
  --output-format json --model <id>`, a bounded `subprocess.run` call
  (`R-ENDPOINT-004`) classified into exactly one of
  `network`/`auth`/`rate_limit`/`timeout` — the CLI's own
  `api_error_status` field is the primary signal, stderr text-matching
  the fallback.
- The credential is never read by this module at all (`R-ENDPOINT-005`)
  — the `claude` subprocess inherits `ANTHROPIC_API_KEY` directly from
  the environment; nothing here ever holds or could leak it.
- Every call writes one record to `.hotdocs/calls/` (`R-ENDPOINT-006`).

**Verified almost entirely on an injected mock backend, at zero cost** —
all 7 tests in `verification/llm-endpoint/` (one per `AC-ENDPOINT-*`
criterion, plus one for `BackendResult`'s own mutual-exclusion
invariant) use `MockBackend`, never a real network call, exactly what
`AC-ENDPOINT-002`/`003`/`006` themselves specify. **Exactly one real
call was made**, to confirm the actual integration works end to end
(`text="PONG"`, `model_call_error=None`, its `.hotdocs/calls/` record
independently confirmed queryable via DuckDB's `read_json`) — not
repeated on every test run, since `ANTHROPIC_API_KEY` is set in this
environment and every such call bills real money (`D46`).

`AC-ENDPOINT-005`'s "dispatches successfully" was interpreted as testing
internal model-to-backend resolution directly (`_resolve_backend`), not
a real network round-trip — consistent with its own `kind: compiled`
and this component's `constraints.md` ("idempotent dispatch is not
claimed").

## Consequences

`D45`'s open backlog item (the subagent mechanism isn't reproducible
from a clean clone) is resolved by removal rather than by fixing it in
place — there is nothing left to reproduce. A fresh clone now has a
real, working `llm-endpoint` instead.

`generator`/`test-author`/`spec-completeness-assistant`/the `judge`
callable remain unimplemented — this decision builds the transport they
would all dispatch through, not any of them. Building a real
`generator` next would, for the first time, make genuine (non-
subagent-simulated) cold regen possible for any other component in this
corpus — tracked as the natural next step, not done here.

`model_call_error.category`'s classification logic is confirmed correct
only for the success path and for whatever `api_error_status` values
the CLI's own documentation implies — not independently verified
against a real auth/network/rate-limit failure, which would mean
deliberately spending real money to trigger one for no additional
verification benefit a mock doesn't already provide. Flagged in
`verification/llm-endpoint/BOOTSTRAP.md`, not silently assumed correct.
