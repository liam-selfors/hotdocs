# D367 — The packaged tool root holds the reference documents its guides cite

## Context

The installed package holds `QUICKSTART.md`, `AUTHORING.md` and
`agent-skills/` (`D360`), and those guides name documents the package did
not hold. `AUTHORING.md` calls `SPEC_GUIDELINES.md` the normative reference
and points at `specs/architecture/step-phrase-grammar.md` for a `compiled`
criterion's steps and at `specs/architecture/cli-conventions.md` as its
example of a shared rule. `QUICKSTART.md` names the built-in asset kinds'
definitions, `specs/architecture/asset-kind-<kind>.md`, and the
`hotdocs-asset-kind` skill opens by telling its reader to read the contract,
`specs/architecture/asset-kinds.md`. A new project has no
`specs/architecture/` directory, so with the repository out of reach none of
these could be read.

## Decision

`tools/build_dist.py` copies into the packaged tool root, at the paths they
have in a checkout: `SPEC_GUIDELINES.md` and, under `specs/architecture/`,
`asset-kinds.md`, `asset-kind-python.md`, `asset-kind-javascript.md`,
`step-phrase-grammar.md` and `cli-conventions.md`. A path a shipped guide
names is read relative to the directory that holds `QUICKSTART.md`, which
`hotdocs init` prints. `tools/release_check.py` fails when a part
`build_dist.py` lists is missing from the installed package.

They are reading matter only. A component falls back to the tool root for
paths under `gen/` alone (`D199`, `R-ASSEMBLE-016`); a project's specs,
its `Implements:` documents and its own kinds' definitions are read from
the project, never from here.

## Consequences

No component changes and nothing is regenerated. A project that wants a
shared rule such as `cli-conventions.md` copies it into its own
`specs/architecture/`, where it becomes part of that project's specs. The
package grows by six documents, about 13,000 words. A guide that later
names another document outside the package needs that document added to
`build_dist.py`'s list.
