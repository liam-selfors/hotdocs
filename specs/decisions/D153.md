# D153 — Exemption Changes' own sub-headings needed the same flat-rendering fix already applied elsewhere

## Context

Across rounds 28, 34, 37, and 39 of bootstrapping `review-packet-
builder`, `AC-PACKET-007`'s own markdown-rendering scenario kept
failing with the identical shape: a generated test's "find the next
heading after `## Exemption Changes`" parser breaks because the very
next line is itself a heading — `### Sealed` — with no content in
between, so the parser's search immediately matches the heading it
was looking *for* as the boundary it should stop *at*. `D150` already
diagnosed and fixed the identical ambiguity for "## Verification
Results"/"## Capability Scenarios" by switching those sections to
flat lines with no per-entry sub-heading — but `D150`'s own write-up
incorrectly asserted "## Exemption Changes" already worked that way
"without incident," when `D145` had in fact given it real `###
Sealed`/`### Pinned Overrides` sub-headings. That incorrect claim is
exactly why the fix was never generalized to this section, and the
same defect kept recurring three more times after `D150` landed.

## Decision

`R-PACKET-012` corrected: "## Exemption Changes" now renders
`**Sealed:**` and `**Pinned Overrides:**` as bold-labeled lines,
never `###` sub-headings — preserving `D145`'s own "always present,
explicitly empty, never omitted" requirement while removing the
structural ambiguity. `review-packet-builder` is retried next.
