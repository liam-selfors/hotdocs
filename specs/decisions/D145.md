# D145 — review-packet-builder's CLI entry point had no requirement or acceptance criterion either

## Context

Eleventh `review-packet-builder` retry (after `R-PACKET-011`'s field-
name fix and `AC-PACKET-007`'s rewritten Gherkin): all eleven criteria
pass behaviorally for the first time. `verify()` still fails:
`mutation_score=0.58` against the `0.8` bar — 19 of 45 mutants
survive. Direct inspection of each surviving mutant's location: six
cluster in `main()`, `_parse_build_args`, and `render_markdown`
(`--format=json` vs `--format=markdown` branching, the usage-error and
missing-upstream-result exit paths, and parts of the markdown
rendering itself) — the identical shape already found twice this
session, `R-PROV-015`/`D130` for `provenance-writer` and
`R-DRIFT-005` for `decision-drift-detector`: every criterion exercises
`build_review_packet` directly as a library call, none through
`main()` — `interface/cli.md` documents a real CLI that no
requirement or acceptance criterion has ever covered.

The remaining survivors are scattered across `_default_branch_ref`'s
own fallback chain and a `_has_sealed_change` edge case masked by an
unrelated fixture coincidence (a test component literally named
`sealed-foo`, whose own diff header line contains the substring
"sealed") — lower-value to chase individually; the new CLI criterion
below is expected to move the score meaningfully on its own, with
further rounds addressing whatever remains by the same iterative
process `D137` already established for `decision-drift-detector`.

## Decision

`cli.md`, covering both `--format` values, the no-`--changed` and
invalid-`--format` usage errors, and the missing-upstream-result exit
path. Retrying generation next.
