# D307 — The verifier probes every generated test and says whose fault a failure is

## Context

`verifier-orchestrator` reused any test file present under
`verification/<component>/generated-test/`, even one written for an
earlier wording of its criterion, and ran it without checking it. A
broken or stale test failed every candidate, and the report could not
say that the test, not the code, was at fault, so any automatic retry
would feed the generator a requirement id it had in fact satisfied.

## Decision

- A cached test whose `# hotdocs-criterion:` header names a different
  criterion and requirement text is stale and is authored again; a file
  with no header is never treated as stale.
- Every test is probed with `test-probe` before it runs. A cached test
  that fails the probe is authored again once; one that still fails is
  never run.
- Each failed criterion carries `failure_origin`: `"test"` when no sound
  test could run, `"implementation"` when one ran and failed.

## Consequences

`verifier-orchestrator` depends on `test-probe`. An attempt loop can
leave `"test"` failures out of its feedback.
