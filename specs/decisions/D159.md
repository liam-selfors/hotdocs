# D159 — D138's universal dependency-loading rule ignored a sealed dependency's own source_path

## Context

Regenerating `verifier-orchestrator` for `D158` produced a candidate
that failed all sixteen of its own hand-maintained tests in under a
second: it looked for `criterion-compiler` under
`<repo_root>/gen/criterion-compiler/`. `criterion-compiler` is this
corpus's one sealed component; its real code lives at its
`component.md`'s own `source_path`, `pipeline/criterion-compiler/`, and
the candidate's own bundle said so (`dependency_usage`: "module path
`pipeline/criterion-compiler/`"). But `D138`'s universal prompt line
told every candidate, as a hard requirement, to resolve a dependency
"strictly" from `<repo_root>/gen/<dep-slug>/`, and the candidate
followed the stronger universal rule over the bundle's specific one.
`D138` was written against three components whose dependencies all
lived under `gen/`, and never considered a sealed one.

The live `verifier-orchestrator` was restored from backup before
anything ran against the broken candidate. Only
`capability-scenario-verifier` and `verifier-orchestrator` depend on a
sealed component; the former has not been regenerated since `D138`,
so no landed code was affected.

## Decision

`R-GEN-018` and `generator`'s prompt line corrected: resolve from
`repo_root` joined to the module path `dependency_usage` gives —
`gen/<dep-slug>/` for an ordinary dependency, a sealed dependency's own
`source_path` otherwise. `PROMPT_VERSION` → `v8`, `GATE_VERSION` →
`generator@1.5.0`. `AC-GEN-019`'s hand test now also asserts the prompt
names `source_path`. `verifier-orchestrator` is regenerated again.

## Second finding, same regeneration

With the `source_path` fix in place, the next candidate passed 13 of
16. All three failures shared one cause: it ran each mutant's tests
with `cwd=repo_root`. Generated tests commonly add a relative
`sys.path` entry such as `gen/foo`, which then resolves to the
*original* module under `repo_root` ahead of the mutated copy on
`PYTHONPATH`, so every mutant survived (`mutation_score` 0.0). The
prior implementation never set a working directory and so avoided
this only by accident. `R-VERIFY-014` now requires a mutant's tests to
run with both the working directory and `PYTHONPATH` set to the
mutated copy.

## Third finding: the operator set was never specified

The next candidate passed 15 of 16; the new timeout fixture scored
5 of 6 rather than 3 of 3. It had quietly added a fifth mutation
operator, numeric constants (`i = 0` to `i = 1`), which the prior
implementation never used and no requirement mentioned. A broader
operator set changes every component's score against a bar calibrated
on the old one, including components already landed, so a gate this
consequential must not change shape as an unreviewed side effect of a
regeneration. `R-VERIFY-006` now names exactly four operators: a
comparison swap, an `and`/`or` flip, an arithmetic operator swap, and
a boolean constant negation. Its backstory paragraph was compressed to
make room, its full account remaining in `D124`.
