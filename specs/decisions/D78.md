# D78 — A bootstrap exception's permanence claim is about the first version only

## Context

`llm-endpoint`'s `D33` bootstrap was originally framed as "structurally permanent, not temporary" — nothing could ever cold-regenerate it, since it is the one component every other generation call dispatches through. The real `generator`, dispatching through that exact `D33` implementation, then cold-regenerated `gen/llm-endpoint/` from this component's own current spec, and the result passed every `AC-ENDPOINT-*` criterion and was swapped in, replacing the hand-written version. This happened again a second time (`D34`/`D35`'s fixes landing via a second self-hosted regeneration). This fact had never been given its own decision record — it lived only as an unattributed changelog bullet in `specs/components/llm-endpoint/component.md`.

## Decision

The earlier "nothing could ever generate `llm-endpoint`" framing is revised to the more precise claim: nothing could generate the *first* working version — once one exists, it can author its own successor, the same way a compiler can compile itself once a first version exists by other means. A bootstrap exception's permanence claim is therefore never about the component forever, only about how its first version had to come into existence; a later self-hosted regeneration that passes every acceptance criterion is swapped in as the new current version, same as any other component's normal regeneration, not treated as a special or riskier event because of how the first version was produced.
