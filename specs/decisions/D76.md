# D76 — capability-scenario-verifier's first real generate() call exposes a dependency_usage gap

## Context

A real `generate()` call for `capability-scenario-verifier` produced a
candidate whose dynamic dependency loader assumed `criterion-compiler`'s
real code lives under `gen/criterion-compiler/`, matching every other
dependency's convention — but `criterion-compiler` is sealed, with its
real code at `pipeline/criterion-compiler/` instead (never `gen/`, by
design). Checked directly: `spec-bundle-assembler`'s `_dependency_usage`
(`R-ASSEMBLE-011`) only ever looked under `gen/<dependency>/`, so every
sealed dependency's usage card had been silently degrading to the
same empty string a dependency with no real code at all produces —
indistinguishable from each other. This never surfaced before now
because `criterion-compiler` is the only real sealed component in the
corpus, and this is the first real dependent that actually needed its
usage info.

## Decision

Fixed in `spec-bundle-assembler` (hand-authored, not yet self-hosted —
edited directly): new `_dependency_real_code_dir` helper checks a
dependency's own `component.md` for a `sealed: true` + `source_path`
pair first, falling back to the normal `gen/<dependency>/` location
otherwise. Confirmed directly: `_dependency_usage(repo_root,
"criterion-compiler")` now surfaces `compile`, `compile_criterion`, and
every other real public symbol by name and signature. A new regression
test (a synthetic sealed component with real code elsewhere) locks
this in; all 11 pre-existing `spec-bundle-assembler` tests pass
unchanged. `R-ASSEMBLE-011` documents the fix explicitly.

A second, separate bug was also found in the same candidate (its
capability-intersection fallback scanned capability files for a
`realizes:` field that only ever exists on *component* files) — a
plain implementation defect, not a spec gap, tracked for the next
retry rather than fixed here.

The buggy candidate was deleted before being committed, never swapped
in.

## Consequences

A retry, with this fix in place, is the next real test. This closes
the fourth distinct kind of "a real convention existed but a
generating model had no way to see it" gap this session (`D55`'s
import paths, `D61`'s component-id-to-slug mapping, `D67`'s var-based
external-input location, now `D76`'s sealed-dependency location) —
each one a different *kind* of fact, found only once a real second
consumer needed the specific answer.

Linter: 0 failures once this file exists. Pytest: 166 tests across all
fourteen real components re-verified unchanged, plus one new test in
`spec-bundle-assembler`'s own suite (12 now).
