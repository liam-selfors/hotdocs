# D201 — Criteria cover the tool-root fallback and the gaps mutation testing found

## Context

Regenerating `review-packet-builder` and `spec-completeness-assistant`
for `D199` passed every criterion in four seeds each, but never
reached the `0.8` mutation score: `0.59`–`0.68` and `0.66`–`0.71`.
Listing the surviving mutants showed why. No criterion exercised the
new tool-root fallback, so mutating its `gen` lookup changed nothing,
and both components had older untested branches: `--flag value`
parsing and a wrong verb for one, response-parsing edge cases for the
other, and a package-module loader neither needs.

## Decision

Each gets a requirement for the fallback, with a criterion that runs a
copy of the component's own module from a fake tool root, with and
without a project copy of the dependency. The CLI and parsing gaps get
concrete scenarios. `spec-completeness-assistant`'s dependencies are
flat module files only, so it carries no package loader.

A first rebuild under these criteria reached `0.77` and `1.0`. The
packet's survivors were sealed-from-birth components, deleted
overrides and key order, so those get scenarios and the packet's JSON
is sort-keyed. The assistant added a `rationale` key to a lint finding
it must pass through unchanged, so its report says so outright. Its
CLI said `argv` began with `assist`, while `hotdocs-cli` strips the
verb; the old code accepted both, the new code did not, so `argv` is
now the tokens after `assist`.

## Consequences

A surviving mutant now points at a behavior worth a scenario, the same
signal `D130` and `D160` acted on. The fake-tool-root criterion is the
pattern for any component whose fallback goes untested.

`spec-completeness-assistant` regenerated under these criteria and runs
from a project. `review-packet-builder` has not yet: its code passed
every mutant in four seeds, but each seed's generated tests had a
different fixture bug, so the committed code still predates this
decision.
