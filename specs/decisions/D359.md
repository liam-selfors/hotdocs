# D359 — A surface failure writes no provenance and reports its findings

## Context

`hotdocs generate` ended in a Python traceback for a component whose every
attempt failed the surface check. `generation-loop` runs no verification for
a `surface_failed` attempt (`R-LOOP-002`), so the loop's last result had
files and no verification report. `R-GATE-006` then called
`provenance-writer` because files existed, and `provenance-writer` raised
`MissingInputError`, since a manifest for generated files needs a report.
The case was found with the installed package: a component declared a
JavaScript asset whose `interface/assets/<file>.md` was missing, which
`surface-checker` reports as an `asset_error` on every attempt.

The result also gave the developer nothing to act on: `block_reason` was to
be `surface_check_failed`, and the findings that say why were dropped.

## Decision

`component-gate-runner` writes provenance on a non-sealed miss only when the
loop's last attempt produced both files and a verification report. A loop
that ends on a surface failure writes none: nothing was verified, so there is
nothing to record, and the attempt records already hold each candidate.

`ComponentPipelineResult` gains `surface_report`, the loop's last
`SurfaceReport` passed through unchanged, `null` when none was made and on
every path that runs no loop. The text output of `hotdocs generate` prints
one `surface: <message>` line per finding when `block_reason` is
`surface_check_failed`.

## Consequences

A surface failure ends as a blocked result with exit code `0`, like a
verification failure, and names what to fix. `component-gate-runner` is
regenerated; `provenance-tracker-ui` and `review-packet-builder` are
regenerated without spec changes, since `ComponentPipelineResult` is part of
their bundles. A missing asset interface is still found only after a
generation; finding it in `hotdocs lint` is recorded in `notes/backlog.md`.
