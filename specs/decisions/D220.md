# D220 — `llm-endpoint`'s HTTP seam, call-log record and config messages are exact

## Context

The first generation of `llm-endpoint` from its spec (seed 1, mutation
1.0) failed eight of eleven criteria. Most traced to how the criteria
fake HTTP: they replace `urllib.request.urlopen`, but the spec never said
the code must look it up there at call time, so the candidate imported it
by name and slipped past every fake, and tests that built a fake reply
guessed which attributes the code would read. The call log's fields were
"text's presence" in words only, so a test queried a `text` column, and
`AC-ENDPOINT-007` checked for "never" in a message the spec never
worded. One failure was a code defect: `complete()` let `load_config`'s
`ValueError` escape where `R-ENDPOINT-002` asks for
`ModelResolutionError`.

## Decision

`interface/library.md` gains a section fixing, from the hand-written
version: every request through `urllib.request.urlopen` looked up at
call time, a reply used only as a context manager and through `read()`,
which exceptions mean what, the Ollama probe's URL and timeout, the call
record's exact keys, and the secret-entry message's phrase. It repeats
that `complete()` raises `ModelResolutionError` for a bad config.

## Consequences

`llm-endpoint` is regenerated against it.
