# D246 — `Doc.rel_path` is a string, and a glossary definition drops its dash

## Context

The first generated `corpus-loader` (seed 4) passed its criteria, and
loading the real corpus with it and with the hand-written `load_corpus`
gave the same documents, components and index. Two things still
differed: `rel_path` was a `Path` where every consumer formats it as a
string (a `Finding.file`, a JSON report), and a glossary definition kept
its leading em dash in one and not the other. `Corpus.md` fixed neither.

## Decision

`Corpus.md` says `rel_path` is a `str` with `/` separators, and a
definition's text starts after the dash.

Seed 6 then passed, but kept each body's trailing newline where "joined
by `\n`" means none; `AC-CORPUS-001` now checks it.

## Consequences

`corpus-loader` is regenerated once more before the checkers build on it.
