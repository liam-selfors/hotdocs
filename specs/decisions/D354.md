# D354 — An asset kind's adapter module maps hyphens to underscores

## Context

`asset-kinds.md`'s Lookup named the adapter `kind_<kind>.py`, but a
hyphenated kind's component module is `kind_<kind with - as _>`, so
`D346` forbade hyphens in `new_kind` until the two agreed. A kind such as
`data-schema`, proposed in `notes/asset-kinds-survey.md`, could not be
scaffolded. A component declaring an undefined kind got only
`asset kind '<kind>' has no definition`, with no pointer to the fix.

## Decision

The adapter is `kind_<module>.py`, `<module>` being the kind with each `-`
replaced by `_` (`kind_data_schema.py` for `data-schema`), everywhere the
path is named: `asset-kinds.md`'s Lookup and adapter interface,
`R-LINT-034`, `R-ASSEMBLE-007`, `R-ASSEMBLE-016`, and `provenance-checker`'s
and `surface-checker`'s interfaces. `new_kind` accepts any kebab-case kind
except `python`. `R-LINT-034`'s message becomes
`asset kind '<kind>' has no definition; run hotdocs kind new <kind>`.

## Consequences

`spec-linter`, `spec-bundle-assembler`, `provenance-checker`,
`surface-checker`, `spec-scaffolder` and every component implementing
`asset-kinds.md` are regenerated. Existing kinds (`python`, `javascript`)
have no hyphen, so their adapters keep their names.
