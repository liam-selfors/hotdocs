# D351 — Re-ratify the secret allowlist after the D350 regeneration

## Context

Regenerating `provenance-tracker` for `D350` re-authored
`verification/provenance-tracker/generated-test/test_ac_track_013.py`,
whose fixture hash (a 16-character hex run repeated four times) the
scanner reads as a hex high-entropy string. The allowlist sealed by
`D349` did not cover it, so `provenance-tracker`'s new manifest recorded a
flagged scan.

## Decision

The allowlist is the scanner's own `propose()` output, checked by hand:
the 39 entries sealed by `D349` plus that one, `planted-fixture`. This
record carries its hash.

## Consequences

A full scan is clean again, and `provenance-tracker` is re-recorded so its
manifest carries the clean scan.
