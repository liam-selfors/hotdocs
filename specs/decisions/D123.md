# D123 — test-author must never assert fake usage via a guessed sys.modules key

## Context

With `D122` landed, two more `provenance-tracker` retries (different seeds) both reached 6 of 7 criteria passing, but `AC-TRACK-009` failed at two different seeds with the identical symptom: a generated test asserts a fake was used by reaching into `sys.modules["provenance_checker"]` (the bare module name) directly, even though the fake's own code already records every call it receives in a module-level `calls` list — a robust, already-present mechanism the test simply didn't use for this one assertion. The real loader (correctly, per `R-TRACK-011`/`R-VERIFY-013`) keys its cache by a `repo_root`-qualified or hashed name, never the bare module name, so the guess fails outright. Found at two different seeds with the same symptom — a confirmed, recurring pattern, not a one-off.

## Decision

New `R-AUTHOR-022`: a test MUST NEVER assert a fake was used via a guessed `sys.modules` key; it MUST rely on the fake's own recorded invocation instead. New `AC-AUTHOR-022`. `test-author` is cold-regenerated against this amendment; `provenance-tracker` is retried once more.
