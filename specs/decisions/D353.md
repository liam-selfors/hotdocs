# D353 — A fixture that reaches the stub reaches the code under test

## Context

`R-PROBE-005` classified every pytest `error` child as a `test_bug`. pytest
records an exception raised in a fixture as such an error, so a test whose
fixture calls the code under test was rejected even though it reached the
stub, as `D303` intends. Because `HotdocsProbeStubReached` is a
`BaseException`, pytest also cannot set up later tests in the same run:
each fails setup with a bare `AssertionError`. The final verifier rejected
three valid tests this way (`AC-GQE-003`, `AC-GQE-010`, `AC-KPY-005`), which
were re-authored without fixture calls as a stopgap.

## Decision

An `error` whose message contains `HotdocsProbeStubReached` reached the code
under test, as a failure does. An `error` whose message is exactly
`failed on setup with "AssertionError"`, after a `testcase` whose setup
reached the code, is pytest's fallout and reaches nothing: no finding.
Every other `error` is still a `test_bug`. The stub stays a
`BaseException`, so no `except Exception` in a test can swallow it.
`AC-PROBE-005` pins a fixture that calls the code.

## Consequences

`test-probe` and its dependents are regenerated: `test-author`,
`verifier-orchestrator` and everything downstream of them.
