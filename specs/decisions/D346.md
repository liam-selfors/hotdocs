# D346 — A new asset kind is scaffolded, never generated on its own

## Context

A component may declare only kinds that are defined: lint rejects any
other (`R-LINT-034`), and generation and verification stop on a kind
with no adapter. When a project needs a new kind, nothing helps it
start. Letting the pipeline invent the kind would let a model write the
strength check that then certifies every component declaring it, the
self-grading `D335` and issue #13 were about.

## Decision

`spec-scaffolder` gains `new_kind`, reached as `hotdocs kind new
<kind>`. It writes the kind's definition,
`specs/architecture/asset-kind-<kind>.md`, with the seven sections of
`specs/architecture/asset-kinds.md` as prompts for the author, and the
adapter component `comp-kind-<kind>` with the adapter interface, the
`Implements:` lines and a calibration-pair criterion to complete, plus a
draft decision for the kind. A person, or an agent following
`agent-skills/hotdocs-asset-kind/`, fills them in; the normal pipeline
then generates and verifies the adapter.

## Consequences

`spec-scaffolder` and `hotdocs-cli` regenerate in the running wave.
A kind name has no hyphen for now: asset-kinds.md's Lookup names the
adapter `kind_<kind>.py`, while a hyphenated kind's component module
would be `kind_<kind with underscores>`; the Lookup is corrected, and
hyphens allowed, with the next change to asset-kinds.md.
Pointing lint's undefined-kind message at the command, and detecting
embedded languages in `hotdocs spec check`, are later changes.
