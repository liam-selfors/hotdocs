# D305 — Cache only verified candidates

## Context

`generate()` wrote every successful model reply to the cache before the
candidate was verified. A candidate that failed verification was then
served again, at no cost and with no new attempt, to every later run
with the same spec bundle, seed-independent inputs and model: re-running
`hotdocs generate` returned the same failing code. The only escape was a
spec edit, which changes the bundle hash, or clearing the cache by hand.

## Decision

`generate()` reads the cache but never writes it. A new function,
`commit_cache(result, repo_root)`, writes a result under the same key,
and its caller calls it only once that candidate has passed
verification. `GATE_VERSION` becomes `generator@3.0.0`, since a cached
entry's meaning changes from "produced" to "produced and verified".

## Consequences

Every caller of `generate()` that verifies, the gate runner and the
bootstrap tool, must call `commit_cache` after a pass, or nothing is
ever cached; a re-run after a failure always makes a new attempt.
