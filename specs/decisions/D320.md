# D320 — A generated test carries the hash of the criterion it was written from

## Context

`verifier-orchestrator` reused any file already at a criterion's test
path (`R-VERIFY-002`), so after a criterion was corrected, `hotdocs
generate` kept running the test written from its old text until someone
deleted the file by hand (issue #4).

## Decision

`test-author` begins every test file it returns, a cache hit included,
with `# hotdocs-criterion: sha256:<hex>`, the hash of the criterion's
text and its covered requirement's text (`R-AUTHOR-028`).
`verifier-orchestrator` reuses a cached file only when that header
matches the current bundle (`R-VERIFY-019`); a mismatched or missing
header means the test is authored again. A test from before this
decision has no header, so it is authored once more; when its criterion
is unchanged, `test-author`'s own cache answers without a model call.

## Consequences

Editing a criterion is enough to get a new test. The first `generate`
after upgrading re-authors each existing generated test once.
