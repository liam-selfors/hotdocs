# D60 — spec-bundle-assembler resolves a sealed dependency's real code via its declared source_path

## Context

`_dependency_usage` only ever looked for a dependency's real code under `gen/<dependency>/`. A sealed dependency's real code lives elsewhere by design (e.g. `pipeline/<name>/`), so its usage card was silently degrading to the same empty string a dependency with no real code at all produces — indistinguishable from each other.

## Decision

`_dependency_real_code_dir` checks a dependency's own `component.md` for a `sealed: true` + `source_path` pair first, falling back to the normal `gen/<dependency>/` location otherwise.
