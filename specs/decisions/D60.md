# D60 — criterion-compiler, hand-authored per its permanent seal

## Context

`D59` cleared the ground: no real `kind: compiled` criterion existed
anywhere in the corpus to compile against, so this component's own
test suite was always going to need a synthetic fixture, exactly as
`constraints.md`'s "characterization coverage" clause already
anticipated. `criterion-compiler` is `sealed: true` permanently
(`component.md`'s Purpose) — the trust anchor for `compiled`-kind
criteria only holds if the compiler itself was never agent-generated,
so this is, and will always be, a hand-authored implementation, never
a `generator` candidate.

## Decision

Implemented `pipeline/criterion-compiler/criterion_compiler.py`:
parses a target component's real `acceptance/*.md`, resolves every
step against that component's real `interface/` contract (function
signatures from `library.md`, type fields from `interface/data/*.md`),
parses literal arguments with a small recursive-descent parser that
accepts JSON-like scalars/objects/arrays plus a bare identifier in a
leaf position (resolved at compile time against an earlier-bound
fixture) and rejects anything else — an operator, field/index access,
a call — as a located compile error (`R-COMPILE-007`). Emits
deterministic `pytest` scaffolding under
`verification/<component>/compiled/`, idempotently.

Several genuinely open design questions were resolved and documented
in `verification/criterion-compiler/BOOTSTRAP.md` rather than left
implicit: scenario grouping within one `gherkin` block, the implicit
fixture name for the `a <Type> with ...` template, `<args>` syntax for
`When` steps, and exactly what counts as a component's declared
interface surface.

One real bug was found by this component's own test suite before it
was considered done, not assumed correct by construction: a first
draft resolved a fixture reference to the Python *variable name*
(compile-time *validated*, since an unbound name is still rejected,
but not compile-time *inlined*). `AC-COMPILE-012` is explicit that the
generated code must contain no runtime lookup at all — fixed to
recursively substitute each fixture's own already-parsed literal
value in place, so `process(user_id, {"owner": user_id})` correctly
became `process("u1", {"owner": "u1"})`.

## Consequences

`criterion-compiler` is real for the first time; `merge-orchestrator`,
`capability-scenario-verifier`, and `verifier-orchestrator` (all of
which `depends_on` it) can now be assembled with a real
`dependency_usage`/`dependency_interfaces` surface for it, once their
own turn in the regen order comes. The `"the client calls <METHOD>
<path> with <args>"` template remains unvalidated against any real
HTTP-serving component, since none exists yet in this corpus — flagged
in `BOOTSTRAP.md`, not silently assumed correct.

Linter: 0 failures once this file exists. Pytest: 108 tests total
across all eight real components now built, 12 of them this
component's own.
