# D267 — A changed component is always `direct`; lint-clean headings

## Context

Seed 3 of `impact-analyzer` tagged a changed component that also
depends on another changed one `transitive-interface`, where
`AC-IMPACT-006`'s test expected `direct`; nothing said which reason
wins or that a component appears once. Another of its tests wrote
requirement files without the `# R-...` heading `R-LINT-007` needs, a
rule `SPEC_GUIDELINES.md` does not state.

## Decision

- `BlastRadiusReport.md`: each component appears at most once, and one
  named in the changed ids is always `direct`.
- `interface/library.md`'s lint-clean note gives the heading rule for
  requirement and guarantee files. `SPEC_GUIDELINES.md` is left alone,
  since editing it would change every bundle that includes it.

## Consequences

`impact-analyzer` is regenerated.
