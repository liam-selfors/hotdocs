# D147 — a brand-new already-sealed component must not count as a newly sealed exemption; HEAD~1 silently drops earlier commits

## Context

Nineteenth `review-packet-builder` retry (after `D145`'s markdown-
rendering worked examples): 11 of 12 pass, both of `AC-PACKET-012`'s
two new scenarios this round for the identical root cause, in two
different shapes.

**Scenario 1**: a repo with exactly one commit, whose `comp-foo` is
already `sealed: true` from that one and only commit, expected
`exemption_changes.sealed == []` — but got `["comp-foo"]`.
**Scenario 2**: a repo whose third commit adds a brand-new
`comp-other-service`, already `sealed: true` from birth, alongside a
genuine `comp-legacy-wrapper` transition (unsealed in commit 1,
sealed in commit 2) and a brand-new `.overrides.json` for
`comp-other-service`; expected the legacy wrapper's genuine
transition under "Sealed" and the new override under "Pinned
Overrides" — got only `comp-other-service` under "Sealed", the
legacy wrapper's real transition missing entirely.

Both trace to the same two compounding causes. First: the candidate's
sealed-detection is a crude "does any added diff line contain the
substring `sealed`" check — a brand-new file's own frontmatter is
entirely "added" lines in the diff, so its own `+sealed: true` line
matches even though there is no real prior state to transition from;
`R-PACKET-007` never said a transition requires the file to have
*existed* at the diff's base. Second (scenario 2 only): with three
linear commits and no feature branch, the `HEAD~1`-against-`HEAD`
fallback (`D142`) only ever shows the single most recent commit —
silently dropping the legacy wrapper's own transition, which happened
two commits back. `D142`'s own fallback was only ever validated
against an exactly-two-commit fixture; a third commit exposes that it
drops everything earlier than the last one.

## Decision

`R-PACKET-001`'s fallback changed from `HEAD~1`-against-`HEAD` to the
empty tree (`4b825dc642cb6eb9a060e54bf8d69288fbee4904`) against
`HEAD` — the whole accumulated history becomes "the PR" when no
feature branch exists, regardless of how many commits are involved,
rather than only ever the most recent one.

`R-PACKET-007` amended: a "changed `sealed`" exemption requires the
file to have existed at the diff's base commit with `sealed: false`/
absent there — a wholesale new file is never counted merely because
it already reads `sealed: true`. A new `.overrides.json` keeps its
existing rule unchanged, since its mere new existence is the complete
signal there.

`review-packet-builder` is retried next.
