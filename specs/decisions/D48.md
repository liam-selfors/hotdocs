# D48 — Real `cache-manager`

## Context

With a real `llm-endpoint` in place (`D47`), the next blocker on a real
`generator` is `cache-manager` (`R-GEN-005`/`006`'s cache-check-before-
call / cache-write-after-call behavior) and `spec-bundle-assembler`
(the actual input `generator` needs). `cache-manager` is fully specced,
entirely deterministic (`R-CACHE-001`–`009`, all `kind: compiled`, no
model calls), and a natural next real component.

## Decision

`gen/cache-manager/cache_manager.py` implements `R-CACHE-001`–`009`: a
content-addressed `get`/`put` store keyed by `(spec_bundle_hash,
gate_inputs_hash, gate_version, model_pin)`, with a local
`.hotdocs/cache/` fallback when `VAR-CACHE-STORE-URL` is absent
(`R-CACHE-009`) — the only backing v1 implements; a set
`VAR-CACHE-STORE-URL` is treated the same as any other unreachable
store (`R-CACHE-004`'s fail-to-miss), since no real shared-store client
exists in this project to target yet (`D18`/`D20`). Writes are atomic
(temp-file-then-`os.replace`), satisfying `G-CACHE-001`'s concurrency
guarantee. `put` validates payload shape against a minimal per-
`gate_type` key fingerprint (`R-CACHE-007`) — deliberately shallow, not
a full JSON-schema validator nothing in this corpus needs yet.

`get`/`put` gained a `repo_root` parameter (`interface/library.md`) —
the same pre-existing-gap pattern `llm-endpoint`'s `backend` and
`provenance-writer`'s `ProvenanceInputs` each already were;
`interface/cli.md`'s own `--repo-root` flag implied it all along.

This is the fifth hand-bootstrapped component, but — unlike
`llm-endpoint` — a temporary exception, not a permanent one: nothing
stops a real `generator` from cold-regenerating `cache-manager` later.

**One real concurrency bug found by actually running concurrent
writers**, not by reading the code: the atomic-write temp filename was
keyed by `os.getpid()` alone, so concurrent *threads* in one process
(sharing a pid) raced on the same temp path — `os.replace` raised
`FileNotFoundError` once a sibling thread's replace had already
consumed it. Fixed with a per-call `uuid4` instead. Caught by
`AC-CACHE-003`'s own test running eight concurrent writer threads for
real.

`R-CACHE-006`'s `stats()` reports the local store's current entry count
only — no persistent cumulative hit/miss counter is defined anywhere in
this component's own spec; flagged in `BOOTSTRAP.md`, not silently
claimed complete.

## Consequences

`generator` now has two of its three real dependencies
(`cache-manager`, `llm-endpoint`); `spec-bundle-assembler` remains.

Linter: 0 failures once this file exists (1 failure beforehand, the
`R-LINT-026` citation of this decision), 21 warnings (unchanged).
Pytest: all five suites (`spec-linter`/`graph-query-engine`/
`corpus-graph-builder`/`llm-endpoint`/`cache-manager`) run separately,
42/7/8/7/10 passed.
