# D41 — Tighten `spec-linter`; dedupe test boilerplate; add `R-LINT-027`

## Context

`D40`'s new `R-LINT-026` left `spec-linter` at 3994/4000
`component_doc_words` — six words of margin, the tightest any component
has run in this corpus. Used as the worked case study for
`notes/component-sizing-playbook.md`'s own Step 4 (tighten) and Step 2
(check for a real split precedent first): the split check came back
negative (`corpus-graph-builder` already reads `spec-linter`'s size-cap
findings rather than duplicating them — no hidden seam), so tightening
was the right move, not extraction.

A systematic per-file word audit (not just trimming the newest
addition) found two genuine duplicates, not just restatement to
compress: `R-LINT-020` and `R-LINT-021` each re-told the full "why this
became a graph query" narrative that `graph-query-engine.md`'s own
"Scope of adoption" section already carries in full.

Separately, the same conversation surfaced two further, related
findings: a recurring Python test-boilerplate pattern in
`verification/spec-linter/test_lint_rules.py`, and the risk that
trimming `R-LINT-020`/`021` down to pointers introduces exactly the
staleness risk `notes/audit-before-you-build.md` and `R-LINT-026`
were already concerned with, one level up: a prose pointer to another
document's *section*, not just another document's *existence*.

## Decision

**Trimmed `R-LINT-020`/`021`** to their normative claim plus a pointer
at `graph-query-engine.md`'s "Scope of adoption" section, recovering
163 words with no information loss — the fuller reasoning still exists,
once, where it already lived.

**Added `R-LINT-027`**: every `` `<file>`'s "<Section>" section ``
pointer in a live document must resolve — the file must exist, and
must contain a heading matching the quoted text exactly. This directly
closes the staleness gap the trim above introduces: if
`graph-query-engine.md`'s sections are ever renamed, or the file moves,
this now fails loudly instead of leaving a dangling, silently-wrong
pointer. Normalized the one pre-existing bare-filename reference
(`R-GRAPH-009`) to the full-path convention this rule checks against,
and fixed a second instance missed by `D40`'s rename (`R-GRAPH-009`'s
"spec-bundle word count," different wording than the literal token
`D40`'s mechanical replace caught).

**Deduped `test_lint_rules.py`'s boilerplate** — the read→replace→write
pattern repeated across 14 call sites — into one `_patch()` helper.
Pure test-code change, no spec or behavior implication.

**Named a fifth recurring convention**: "This is an implementation
requirement, not a behavioral one" appears independently in five
requirements (`R-LINT-020`, `R-LINT-021`, `R-IMPACT-009`, `R-GRAPH-009`,
`R-PACKET-011`). Documented in `notes/narrow-exception-pattern.md` as a
convention to cite by name going forward, not re-derive per instance.

## Consequences

`spec-linter` ends this decision at 3957/4000 `component_doc_words` —
tighter than its pre-`D40` baseline (`R-LINT-026`/`027` both added real
content), but with a real margin again, not six words. The playbook's
own tightening toolbox held up under actual use as a case study, and
gained a new entry of its own (duplicate-narrative removal across a
component and its architecture doc, distinct from trimming restated
reasoning *within* one component).

Linter: 0 failures, 17 warnings (unchanged count). Pytest: 42 passed
(one new case). See `R-LINT-020`/`021`/`027` for the current,
authoritative text.
