# D41 — A per-call dynamically-loaded dependency module must be registered in sys.modules before its code runs

## Context

A real candidate's dynamic dependency-loading technique (a deliberate, reasonable choice to correctly support generation being invoked against different repo roots within one process) crashed inside a dependency's own `@dataclass` class-body evaluation, which looks up `sys.modules[cls.__module__]` during that exact evaluation. A plain implementation mistake in one candidate, but the correct technique was never documented anywhere a future candidate choosing the same legitimate approach would see it.

## Decision

An implementation choosing per-call dynamic loading from a repo root (rather than a static `sys.path`-relative-to-`__file__` import, which remains valid) must register the loaded module in `sys.modules` before `exec_module`.
