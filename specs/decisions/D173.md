# D173 — Two provenance-writer criteria left test authors a guess

## Context

Regenerating `provenance-writer` for `D170` passed both new sealed
criteria on the first round and failed two older ones, neither a defect
in the candidate. `AC-PROV-014`'s generated test collected manifests
with a glob, `*.provenance.json`, which never matches the hidden file
`.provenance.json`, so it found none and failed any correct writer.
`AC-PROV-015`'s "a required upstream result missing" test set a null
`verification_report` beside generated files and expected
`MissingInputError`; the criterion never said which field was meant.

## Decision

`AC-PROV-014` now states the exact manifest path and that it is hidden
(the same glob then broke `AC-PROV-004`, so the rule moved into
`interface/library.md`, which every criterion's bundle includes);
`AC-PROV-015` names the missing field (`license_scan_result`).

My first wording of that fix called a null `verification_report`
optional, and was wrong: `ProvenanceInputs.md` makes it null only when
nothing was generated, and the next candidate rightly raised
`MissingInputError` for a null report beside generated files. The data
document now says so, and the criterion's valid documents always carry
a populated report when they carry files. The earlier landing of
this component passed both only because its test author happened to
guess differently.

## And a third

The next round's `main` expected `argv` to start at `write`, the verb
`provenance` already stripped, and so rejected the `["provenance",
"write", ...]` its criterion passes. `interface/cli.md` never said what
`main` receives; the dispatcher (`D184`) keeps these two words for this
verb, as the previously landed writer assumed. It now says so.

## Mutation testing found what behavior tests did not

Once every criterion passed, `provenance-writer` scored 0.67 on mutation
(`provenance-checker`, 0.74 a round earlier, had the same shape): 24 of 73
mutants survived, most in `write_sealed_provenance`'s field-by-field
validation, whose `or` conditions flip to `and` unnoticed unless a test
supplies a wrong *type* for each field in turn. Both components gained a
one-field-at-a-time criterion (`AC-PROV-020`, `AC-PROVCHECK-013`). The
rest of the writer's survivors were older, uncovered behavior:
rewriting an existing manifest (`AC-PROV-021`), the
`--repo-root <dir>` form (`interface/cli.md`, `AC-PROV-015`), and an
object with a method or private attribute (`AC-PROV-016`). Some
backstory was trimmed from `R-PROV-014`–`017` to stay under the word
cap; their normative text is unchanged.
