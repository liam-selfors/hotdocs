# D126 — R-AUTHOR-020's arity check must explicitly resolve aliases, never skip them as unresolvable

## Context

The real candidate regenerated against `D125` correctly detected `name = other_name` aliases as a distinct category (marking each one), but then explicitly skipped every marked alias when comparing arities — `continue`d past it — never resolving it to its target function's own real arity at all. The aliased name (`do_thing`, the one a real dependency signature actually names) was therefore never checked; only the underlying helper's own name (`_fake_do_thing`, never itself matching any real dependency name) was. Confirmed directly against the hand-maintained suite's existing `AC-AUTHOR-020` wrong-arity test, which failed cleanly once this was in place.

## Decision

`R-AUTHOR-020` is amended: aliases MUST be resolved to their target function's own arity before comparing, never skipped as unresolvable. `test-author` is cold-regenerated against this amendment.
