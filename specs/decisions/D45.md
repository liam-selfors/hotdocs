# D45 — Model-call subagents; `corpus-graph-builder` cold-generated

## Context

`D44` closed the gap between `spec-linter`'s graph rules and a real
implementation, but left the deeper gap this whole repo has carried
since its own first commit: `generator`, `test-author`,
`spec-completeness-assistant`, and the `llm-judge` callable each depend
on a real model call through `llm-endpoint`, and none of those exist —
every component beyond `spec-linter`/`graph-query-engine` is spec-only.
Building a real `llm-endpoint` first (a direct Anthropic API client)
was the obvious path, but every one of those four components' own
acceptance criteria already test the *model call* boundary via an
injected mock (`generator`'s R-GEN-001–008, `test-author`'s mirror of
the same pattern) — meaning the actual network client was never
required to validate any of their logic, only to run them for real
against production inputs.

A simpler path existed: this session already runs inside a real,
authenticated Claude Code session. A Claude Code subagent, scoped to
exactly the boundary `llm-endpoint.complete(prompt, model) ->
ModelResponse` occupies — pure text in, pure text out, no filesystem
access — is a real model call, not a mock, without writing a single
line of networking code.

## Decision

**Four subagent definitions** (`.claude/agents/*.md`, gitignored — see
Consequences), each scoped to exactly one real model-call boundary this
corpus already specs, each citing the requirement IDs it must honor:

- **`generator`** — simulates `comp-generator`'s model call (R-GEN-001–
  004, R-GEN-012). No tools: R-GEN-001's cold-mode purity rule means it
  must never see anything beyond its assembled `SpecBundle`, including
  this component's own real `gen/` content elsewhere in this repo —
  giving it `Read` would make that rule unenforceable.
- **`test-author`** — simulates `comp-test-author`'s model call
  (R-AUTHOR-001/002/006/012-equivalent purity). No tools, same reasoning:
  R-AUTHOR-002 requires it never see the target's real `gen/` source.
- **`judge`** — simulates the single injectable `llm-judge` callable
  wired into `spec-linter` (R-LINT-015), `verifier-orchestrator`
  (R-VERIFY-003), and `capability-scenario-verifier` (R-SCENARIO-001).
  Read-only tools (`Read`/`Glob`/`Grep`): unlike the two above, its real
  callers sometimes need it to inspect real `gen/` output
  (`R-SCENARIO-001` is explicit that this must be "the actual
  regenerated system," not a prediction) — but never `Write`/`Edit`,
  since judging is not fixing.
- **`spec-completeness-assistant`** — simulates its two judgment calls
  (R-ASSIST-004 completeness, R-ASSIST-005 redundancy). Read-only tools,
  deliberately broader than `judge`'s scoped-to-what-it's-told access:
  its actual job (unlike the other three) is searching the *rest of the
  corpus* for overlaps, which is unavailable if everything must arrive
  pre-bundled.

**One real cold-generation test**, not just the definitions: assembled a
real `SpecBundle` for `corpus-graph-builder` (fully specced, zero
model calls needed for its own verification — all nine acceptance
criteria are `kind: compiled` — and nothing hand-written for it yet, so
this was a genuine test, not a comparison against an answer already
known) and dispatched it to the `generator` subagent. The result —
a `corpus_graph_builder` package implementing R-GRAPH-001–009 — was
placed under `gen/corpus-graph-builder/` and verified two ways: against
this repo's real corpus (node count 30, edge count 86, and all three
orphan rates, each independently cross-checked by hand — exact match
every time) and against a synthetic fixture built to exercise every
`AC-GRAPH-*` criterion the real corpus can't currently exercise (its own
orphan rates are all `0.0` today). Determinism (R-GRAPH-008) confirmed:
two runs produce byte-identical output.

`component.md`'s `depends_on` was missing `comp-graph-query-engine` —
the same drift `D44` found and fixed for `spec-linter` — fixed here too,
along with `specs/architecture/pipeline-decomposition.md`'s own
dependency table (the authoritative decomposition declaration,
`SPEC_GUIDELINES.md` §3.2), which had the identical gap.

**One real bug found only once a real `.provenance.json` existed to
query:** `component_provenance`'s `generated_at` field auto-detects as
`TIMESTAMP WITH TIME ZONE`; materializing that type requires `pytz`,
never installed because nothing had ever read a real provenance
manifest through this view before. Not a bug in the generated code (it
correctly used the shared view, R-GRAPH-009) — a transitive dependency
gap in `graph-query-engine` itself, invisible until exercised with real
data, the same discovery pattern `D42`/`D43`/`D44` already established
for this component. Fixed by declaring `pytz` as a real dependency
rather than fighting DuckDB's type system (confirmed by hand that
`read_json`'s `columns` parameter forces a closed schema, the same
intersection-only behavior `D44` already found for `read_yaml`'s
equivalent — not a usable workaround here either). See `R-GQE-005`.

## Consequences

`corpus-graph-builder` is the first component in this corpus whose
`gen/` code was actually produced by a generation step, not hand-written
— a real, if simulated-via-subagent-rather-than-raw-API-call, exercise
of the methodology's own central claim. `spec-linter`/`graph-query-engine`
remain hand-bootstrapped; this is a different, and arguably stronger,
category: not a declared exception, an actual (if small) generation.

`.claude/agents/` is gitignored (session-local Claude Code tooling
configuration, not a spec-driven artifact) — the four subagent
definitions themselves are therefore not committed to this repository.
This is a real, deliberate tension worth naming rather than glossing
over: the mechanism that produced `corpus-graph-builder`'s code is not
itself reproducible from a fresh clone of this repo, only from a
session that still has these local files. Revisiting this (e.g.
committing the definitions somewhere `.gitignore` doesn't reach, or
documenting them in prose even if the files themselves stay local) is
flagged in `notes/backlog.md`, not resolved here.

A structural choice worth naming, not silently normalized: the
generated code is a `corpus_graph_builder/` package with its own
`pyproject.toml`, not the flat single-file style `spec-linter`/
`graph-query-engine` use — nothing in `interface/library.md` mandates a
layout, so this was the model's own reasonable choice given only the
spec, not an error.

`AC-GRAPH-007` ("runs on every merge to main") has no corresponding
unit test — a CI-cadence requirement, not a property `build_corpus_graph()`
itself can satisfy, and no real CI pipeline exists here to test against.

Linter: 0 failures once this file exists (3 failures beforehand, all
`R-LINT-026` citations of this decision), 20 warnings (one more than
`D44`'s 19 — `R-GQE-005`'s new prose crossed the per-file warn
threshold). Pytest: `verification/spec-linter/` 42 passed,
`verification/graph-query-engine/` 7 passed, `verification/
corpus-graph-builder/` 8 passed (all three suites run separately — the
`conftest.py` bare-name collision `D44` already documented now applies
across three directories, not two).
