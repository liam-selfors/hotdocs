# D210 — `spec_bundle_hash` is an exact function of the files a bundle reads, and a bundle carries the documents its component implements

## Context

Two gaps surfaced while planning to regenerate every component and
record provenance for each.

`spec_bundle_hash` was "a content hash of the full assembled bundle", so
its value depended on how an implementation rendered each field. Every
provenance key contains it. A regenerated `spec-bundle-assembler` could
hash the same specs differently and stale every manifest, and since the
assembler's own bundle includes usage cards from `spec-linter`'s and
`graph-query-engine`'s code, no order of regeneration could settle all
three.

`spec-linter` implements `SPEC_GUIDELINES.md`, `criterion-compiler`
implements `specs/architecture/step-phrase-grammar.md`, and
`graph-query-engine` implements `specs/architecture/graph-query-engine.md`.
None of those documents reached their bundles, so a cold generation
could only guess the thresholds, field rules and grammar its spec
pointed to. The hand-written versions had been written by someone who
read them.

## Decision

`R-ASSEMBLE-007` defines the hash over the raw bytes of the files the
bundle reads, by path in sorted order, with the mode first. Any correct
implementation computes the same value. A code directory's dotfiles and
`__pycache__` never count, so writing `.provenance.json` changes no
dependent's hash.

A sealed dependency's code is read from its `source_path` only, for the
hash and for its usage card alike; `R-ASSEMBLE-011` had said it fell back
to `gen/`, which the hash rule did not, and a candidate (seed 52) followed
one reading while its test followed the other.

`R-ASSEMBLE-014` adds an opt-in `Implements:` line to a component's
`interface/library.md`. Each document it names is appended to both
bundles' `interface`, so `generator` and `test-author` read it without
any change to either. The three components above declare theirs.

## Consequences

Every existing hash changes once, which is why the assembler is
regenerated first and every manifest written afterwards. A change to a
dependency's code still changes its dependents' hashes, by design
(`R-ASSEMBLE-011`). `tools/bootstrap_component.py` copies
`SPEC_GUIDELINES.md` into each sandbox.
