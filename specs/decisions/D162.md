# D162 — Every documented CLI needs a requirement pinning its argument parsing

## Context

Five components in a row (`provenance-writer` in `D130`,
`decision-drift-detector` in `D136`, `review-packet-builder` in `D145`,
`spec-completeness-assistant` in `D160`, `provenance-tracker-ui` in
`D161`) reached a passing verdict with their CLI entry point untested,
and each time mutation testing found it, one round at a time. Even
once a CLI requirement existed, the same details kept surfacing as
survivors: whether a flag takes its value as the next argument, what a
flag given last with no value does, whether `--model`-style flags
actually reach the library call, what a wrong subcommand does. Nothing
in `SPEC_GUIDELINES.md` asked for any of it, and nothing checked.

An audit of the 21 components with an `interface/cli.md` found 11 with
no requirement citing it at all.

## Decision

`SPEC_GUIDELINES.md` §5 gains a rule: a component with an
`interface/cli.md` must have a requirement citing it by path that pins
each flag's accepted forms, the no-value case, unknown arguments and
subcommands, flag pass-through, and every exit code, with a criterion
exercising each.

`spec-linter` gains `R-LINT-031`, which checks the mechanical half:
some requirement cites the CLI document by path, and some criterion
covers it. Whether that requirement is thorough stays a review
question.

`R-LINT-031` is a warning, not a hard failure, for now. Making it fail
would require amending the specs of every uncovered component at once,
which marks each of them stale until it is regenerated. The backlog is
instead covered one component at a time, each with its next
regeneration, and the rule is promoted to a hard failure once the
backlog is empty. `component-gate-runner`, the one uncovered component
not yet built, is covered before its first build.

To make room under `spec-linter`'s own 4000-word cap, backstory was
trimmed from `R-LINT-022`, `R-LINT-023`, and `R-LINT-024`; their
normative content is unchanged.
