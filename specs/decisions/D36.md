# D36 — A rejected candidate is never hand-patched; the real defect is fixed at its true source, and generation is retried

## Context

Every real self-hosted component build in this corpus follows the same discipline when a generated candidate fails verification: the candidate itself is never hand-patched to make it pass. This has been followed consistently throughout the self-hosting arc, but was never actually written down anywhere — a load-bearing rule that existed only as an unwritten, if universally followed, convention.

## Decision

When a real candidate fails verification, the defect is fixed at its true source — the component's own spec text, a dependency's spec, the generator's own prompt, or `SPEC_GUIDELINES.md` itself, whichever actually caused the failure — never by editing the rejected candidate's generated code directly. The candidate is deleted and generation retried once the true fix lands. This preserves the methodology's own central claim (`P-ZERO-EDIT`): generated code is never hand-edited into correctness, because doing so would mean the spec no longer actually describes what the real code does.

## Consequences

Distinguishing a plain implementation mistake (no spec change needed, just retry) from a genuine spec ambiguity (needs a real fix first) is a judgment call, confirmed most reliably when the same failure recurs independently across two or more separately-generated candidates.
