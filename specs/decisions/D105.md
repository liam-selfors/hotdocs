# D105 — test-author's synthetic-fixture guidance states the status enum, applies frontmatter rules to every document type, and requires acceptance coverage

## Context

With `R-AUTHOR-015`'s self-check safeguard (`D104`) now live, a further real `spec-bundle-assembler` retry reproduced exactly the legible, immediate failure that safeguard exists to produce: `AC-ASSEMBLE-010`'s synthetic fixture failed with a full, structured finding list instead of a confusing downstream error. That list named three distinct, previously unstated gaps, all independent of `R-AUTHOR-012`–`014`'s existing fixes:

- `status 'active' is not one of draft|ratified|deprecated` — on **two different components**, in **two independent real regenerations** (this is the same mistake `D102` first found and believed fixed; it recurred because `R-AUTHOR-012` stated that `status` is required, but never stated which values are valid).
- `specs/decisions/D13.md ... missing required frontmatter field 'owners'` — a synthetic *decision* fixture, not a component, missing the same universal field `R-AUTHOR-012` already requires on `component.md`. `R-AUTHOR-012`'s own text said "component.md (or other spec file)" but never named decision records or `VAR-*.md` files concretely enough for the model to apply the same rule to them — the same gap `AC-ASSEMBLE-003`'s still-unresolved VAR-fixture failure independently confirms.
- `R-BAR-001 has zero covering acceptance criteria` / `R-FOO-001 has zero covering acceptance criteria` — every declared requirement in a synthetic fixture needs at least one acceptance criterion covering it (`R-LINT-008`), for every component the fixture constructs, not only the one under test.

## Decision

`R-AUTHOR-012` is amended in place with three additions, each narrow and independently stated: (1) `status` MUST be exactly one of `draft`, `ratified`, or `deprecated` — stated as the literal enum, not just "required"; (2) the required-frontmatter rule (`id`/`title`/`status`/`owners`) applies to **every** frontmatter-bearing document a fixture constructs, explicitly naming `component.md`, `specs/vars/VAR-*.md`, and `specs/decisions/D<N>.md` as the three kinds this corpus actually has — not only `component.md`; (3) every file a fixture writes under a component's `requirements/` MUST have at least one corresponding file under that same component's `acceptance/` with a matching `Covers:` tag, for every component the fixture constructs, not only the target.

`test-author` is cold-regenerated against this amendment; `spec-bundle-assembler`'s `AC-ASSEMBLE-003`/`010` are re-authored and re-verified once in place. This is the last planned round for `spec-bundle-assembler` specifically — any further individual gap found after this one is recorded as a known limitation rather than chased immediately, consistent with the diminishing-returns judgment already exercised once this same investigation (`D103`'s context).
