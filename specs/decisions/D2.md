# D2 — Behavioral guarantees are part of the contract; capability scenarios are a permanent backstop

## Context

A component's real contract with its dependents isn't only types — swapping an implementation detail (e.g. a backing store) can silently change a consistency guarantee a dependent actually relies on, invisible to blast radius.

## Decision

`interface/guarantees/G-<comp>-NNN.md` holds one behavioral/non-functional guarantee per file. A dependent's `depends_on_guarantees: [G-<comp>-NNN, ...]` is strictly opt-in — silence gets the safe, coarse default (any `interface/` change propagates blast radius). Capability scenarios are executed against the real assembled system as a permanent gate, never superseded once guarantees are explicit — documentation of foreseeable guarantees can never be complete, and under-declaring reliance (a false-negative blast-radius miss) is exactly the risk this backstop exists for.
