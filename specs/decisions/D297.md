# D297 — Re-record provenance for unchanged components after the allowlist update

## Context

After `D294` sealed an allowlist covering the rebuild's planted
fixtures, a full secret scan was clean, but every manifest still
recorded the flagged scan it ran when its component landed, so
`hotdocs verify` reported the tool not ready. Regenerating every
component to re-record its scans would change code that is already
verified and cascade through every dependent's bundle.

## Decision

`tools/rerecord_provenance.py` re-records a component's manifest
without regenerating it, and only when the code it describes is
unchanged: the manifest's `spec_bundle_hash` must equal the bundle's
current hash. It re-verifies the code in the real repo with
`verifier-orchestrator`, now measuring mutation there (`D280`, `D287`),
against the committed generated tests; re-runs the license and secret
scans; and has `provenance-writer` write the manifest, carrying the
original generation's model, prompt version and retry feedback, and
each criterion's `test_authoring` record while its test file is
unchanged. A component whose hash changed or whose fresh verification
fails is left alone. `generated_at` is the write time, as `R-PROV-008`
defines it.

## Consequences

The manifests describe the code as it stands, with every gate result
re-derived, rather than the state of the allowlist when each first
landed.
