# D30 — cache-manager is a narrow, cost-avoidance-only store

## Decision

`cache-manager` has no role in deciding whether verification is skipped (that's `provenance-checker`'s job) — only whether a redundant model call is avoided. It is a content-addressed `get`/`put` store keyed by `(spec_bundle_hash, gate_inputs_hash, gate_version, model_pin)`, with atomic (temp-file + rename, unique per call) concurrent-safe writes. Its backing store is optional — absent, it falls back to a local `.hotdocs/cache/` directory; this is correctness-neutral now that cache-manager no longer gates verification.
