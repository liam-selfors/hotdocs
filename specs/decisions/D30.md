# D30 — `llm-endpoint`: a vendor-agnostic transport for every model call in the pipeline

## Context

Proposed as a scope exploration: every agent/generation pass could share
one reconfigurable model-dispatch component, and DuckDB could hook into
it as a UDF for in-database judge evaluation. The UDF half was analyzed
separately and deliberately deferred (purity/determinism conflicts with
the rest of this corpus's DuckDB adoption — see the analysis preceding
this decision). This decision covers only `llm-endpoint` itself.

The coupling it closes was verified as real, not assumed: `generator`
and `test-author` each independently declared
`uses_var: [VAR-ANTHROPIC-API-KEY]`, and `merge-orchestrator`'s `judge`
wiring (`R-MERGE-004`) was "a direct call to the configured model" with
no component behind it at all. `R-GEN-004` already treats the model
*identifier* as a vendor-agnostic parameter, but nothing owned the
*mechanics* of actually calling whatever it names — swapping vendors
meant touching at least three places.

## Decision

New component `llm-endpoint`: `complete(prompt, model, **params) ->
ModelResponse`. Resolves a model identifier to a backend internally
(`R-ENDPOINT-002`) — callers never name or configure a backend, only a
model; an unresolvable identifier fails immediately as a usage error,
never a silent fallback. v1 ships exactly one backend, Anthropic
(`R-ENDPOINT-003`) — no multi-vendor machinery built in for vendors
nothing calls yet, the same anti-premature-abstraction stance `D18`
applied to `criterion-compiler`'s single emit target. No
retry-with-backoff (`R-ENDPOINT-004`) — the same posture `D21`
established for `generator`, now owned at the layer that actually
touches the network. Credential never reaches any caller
(`R-ENDPOINT-005`).

Deliberately out of scope: prompt construction and response parsing for
any specific task stay with each caller (generation vs. judge prompts
are still each caller's own concern) — `llm-endpoint` only knows "send
this text to this model."

## Consequences

`generator`, `test-author`, and `spec-completeness-assistant` drop
`uses_var: [VAR-ANTHROPIC-API-KEY]` and gain `comp-llm-endpoint`;
`R-GEN-004`/`008`/`011` now reference `llm-endpoint` instead of
restating vendor-SDK reasoning independently. `R-AUTHOR-008`'s
credential-leak guard strengthens from "must not leak" to "cannot
leak" — the credential no longer reaches that component at all.
`merge-orchestrator` gains the same dependency to back its `judge`
wiring; its `fan_out` moves 14 → 15, a genuinely new leaf dependency
behind wiring it already owned, not a repeat of `D25`'s crowding
signal — `spec_bundle_words` is unaffected, so `R-LINT-022` still sees
exactly the two dimensions it already saw.

**A real design debt opened, not closed, by this decision:** `D21`'s
"trust the vendor SDK's own bound" reasoning was anchored to one
vendor's behavior. `R-ENDPOINT-004` states the uniform guarantee every
caller now relies on, but a future non-Anthropic backend must *provide*
that bound itself (imposing a client-side timeout if its vendor/
self-hosted runtime doesn't guarantee one natively) — not resolved
generically here, because no second backend exists yet to resolve it
against.

See `specs/components/llm-endpoint/` for the current, authoritative
rules.
