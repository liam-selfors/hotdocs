# D360 — The tool version is read from the tool root, which also holds the guides

## Context

The version was written three times: in `pyproject.toml`, and as the literal
`TOOL_VERSION = "0.1.0"` in the specs and code of `hotdocs-cli` and
`hotdocs-init`. A release under another version, a pre-release such as
`0.1.0a1` for example, would have left `hotdocs --version` and a project's
`.hotdocs-tool.json` naming a version that was never published, unless both
components were regenerated for every release.

A walk through the installed package as a new user found a second gap.
`hotdocs init` ends by pointing at `QUICKSTART.md`, but an installed package
held no guide: `QUICKSTART.md`, `AUTHORING.md` and `agent-skills/` went only
into the sdist (`D358`), and a project receives no copy (`D199`).

## Decision

The tool version is the `[project]` `version` of `<tool_root>/pyproject.toml`,
read when needed and `unknown` when it cannot be read
(`specs/architecture/tool-version.md`). `hotdocs-cli` prints it and
`hotdocs-init` writes it to `.hotdocs-tool.json`; neither holds a literal.

The packaged tool root gains `pyproject.toml`, `QUICKSTART.md`,
`AUTHORING.md` and `agent-skills/`, copied by `tools/build_dist.py` beside
`gen/`, `pipeline/`, `examples/` and `requirements.txt`. `hotdocs init` ends
by naming `<tool_root>/QUICKSTART.md`, the guide of the version that is
installed.

## Consequences

A release changes one line of `pyproject.toml` and regenerates nothing.
`hotdocs-cli` and `hotdocs-init` are regenerated once for this decision. A
project initialised by an install that has no `pyproject.toml` in its tool
root records `unknown`; the marker file is not read back for its version
today. The guides in the package match the installed version, and need no
network or access to the repository.
