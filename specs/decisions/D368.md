# D368 — Readiness says why a capability is not passing

## Context

A capability with no scenarios never passes (`R-SCENARIO-001`): its report
has `overall` `"fail"` and an empty `scenarios` list. `hotdocs capability
new` lays out a capability without one (`D364`), so a developer who follows
`QUICKSTART.md`, writes a component, generates it and runs `hotdocs verify`
was told `not ready` with `<capability id>: capability scenarios failed`,
when nothing had run and nothing had failed. That wording was the generated
code's own: `R-TRACK-010` said only that a failing capability is named. A
capability with a failing scenario got the same line, without the
scenario's id. `QUICKSTART.md` also called the scenario optional, which was
wrong.

## Decision

`provenance-tracker` states the `not_ready_reasons` entry for a capability
whose report is not passing (`R-TRACK-010`):

- `<capability_id>: has no capability scenarios; add a CS- scenario to its file under specs/product/`
  when the report's `scenarios` list is empty;
- otherwise `<capability_id>: capability scenarios failed: <ids>`,
  naming each scenario whose `result` is `"fail"`.

The rule is the same for a committed record that hits and for a fresh run.
`capability-scenario-verifier` is unchanged: a capability that verifies
nothing still never passes.

## Consequences

`provenance-tracker` is regenerated, and `component-gate-runner`,
`provenance-tracker-ui` and `review-packet-builder` are regenerated without
spec changes because its code is in their bundles. `QUICKSTART.md` says a
capability needs a scenario before `hotdocs verify` can report it ready.
`hotdocs capability new` still writes no scenario: a placeholder would be
sent to a test author as written.
