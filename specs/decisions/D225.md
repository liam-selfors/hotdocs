# D225 — The `claude-cli` backend returns every message of a long reply

## Context

Three of four attempts to generate `spec-linter` came back as one file
or none, and one `criterion-compiler` attempt came back as three small
fragments. Running the generator's exact prompt through the `claude`
command showed why: the reply began in the middle of a function. A
reply longer than one message's output limit continues in another
message, and `claude --print` prints only the last. Every generation
large enough to need a second message lost its beginning, silently,
since the generator saw well-formed text and parsed what file blocks it
could find.

## Decision

`claude-cli` passes `--output-format stream-json --verbose` and joins the
text blocks of every `assistant` message in order (`R-ENDPOINT-003`). A
`result` line marked `is_error` is a failure. Output that is not the
stream, such as a test's stand-in printing plain text, is taken as the
reply. The hand-written `llm-endpoint` in use for the bootstrap gets the
same change directly, and `component.md`'s change log is condensed to
make room.

## Consequences

Large components generate whole. Earlier "truncated" candidates were
this, not the model's output limit.
