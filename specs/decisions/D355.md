# D355 — The agent sandbox runs the project's Python environment

## Context

`D344` lets a project commit `environments/python/requirements.lock`, and
verification then runs its code in `.hotdocs/env/python/`. The agent
sandbox (`agent-sandbox.md`) still ran the model's `check_import` and
`run_scratch_tests` under `sys.executable`, the environment `hotdocs`
runs in. So in agentic mode the model's own checks could import packages
the project never declared, or miss ones it did.

## Decision

`check_import` and `run_scratch_tests` run the `interpreter` that the
`python` adapter's `provision(repo_root)` reports, provisioned once per
`generate_agentic` call. Without a lock that is still `sys.executable`. The
sandbox's readable prefix is that interpreter's own `sys.prefix`, so a
project environment inside the repository stays readable while the rest
of the repository does not. A failing `provision` has already ended
generation before any model call. `AC-AGENT-004` pins the interpreter used.

## Consequences

`agentic-generator` and its dependents are regenerated. Nothing changes
for a project without a lock.
