# D163 — One canonical provenance key, owned by provenance-checker

## Context

Auditing `component-gate-runner`'s spec before its first build found
that nothing it writes could ever satisfy `hotdocs verify`, for two
independent reasons.

**`spec_bundle_hash` had two definitions.** `generator` records the
`SpecBundle`'s own hash (`R-ASSEMBLE-007`), and `provenance-writer`
copies it into `.provenance.json` (`R-PROV-002`). `provenance-tracker`
instead computed its own hash over the component's spec files, minus
`acceptance/`, plus the glossary. For `license-scanner` the two
differed. A `.provenance.json` written after a real generation could
never match what `hotdocs verify` compared it against.

**`gate_versions` had no definition at all.** `provenance-checker`
requires the manifest's `gate_versions` to equal the supplied map
exactly, key set included (`R-PROVCHECK-001`). `provenance-tracker`
always supplied `{}`; `provenance-writer` records whatever map its
caller passes. No component could report the current versions without
running every gate, so no caller could have supplied a correct map.

This is exactly what `SPEC_GUIDELINES.md` §10 forbids: one fact,
computed in two places, silently diverging.

## Decision

`provenance-checker` gains `current_provenance_key(component_id,
repo_root)`, the one definition of what a provenance hit compares
against:

- `spec_bundle_hash` is `spec-bundle-assembler`'s cold-mode bundle
  hash for the component — the same value `generator` records.
- `gate_versions` maps each gate whose result a hit reuses to its
  current version: `compiler` (`criterion-compiler`), `generated_test`
  (`test-author`), `verifier` (`verifier-orchestrator`'s own mutation
  harness and dispatch), `license_scanner`, and `secret_scanner`.

`check_provenance` is unchanged: it still compares against
caller-supplied values. Every caller, `provenance-tracker` and
`component-gate-runner` alike, obtains those values from
`current_provenance_key`, and `component-gate-runner` passes the same
`gate_versions` into `provenance-writer`, so what is written and what
is later compared come from one function.

Each gate must report its version without running: `license-scanner`
and `secret-scanner` each gain a `gate_version(repo_root)` function
returning exactly the string their scan results carry, and
`verifier-orchestrator` gains a `GATE_VERSION` constant.
`criterion-compiler` and `test-author` already expose one.

Built in dependency order, each regeneration also covering that
component's CLI per `D162`.

`provenance-tracker`'s first regeneration round passed six of seven,
including `AC-TRACK-009`, previously a known limitation. The seventh
failed because a test placed its fixture at
`specs/components/comp-widget/` and the candidate, deriving ids as
`comp-<directory>`, reported `comp-comp-widget`. A component's id
lives in its `component.md` frontmatter; `R-TRACK-009` now says the
whole-corpus scope reads it from there.
