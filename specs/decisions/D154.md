# D154 — provenance-tracker-ui becomes a build-time snapshot, not a DuckDB-WASM page

## Context

Read before its first generation attempt, `provenance-tracker-ui`'s
spec contradicted itself in a way no candidate could satisfy. Each node
must be colored by `provenance-tracker`'s `check_readiness` result
(`R-UI-002`), yet the page was a static DuckDB-WASM page that "never
calls `check_readiness` itself" (`R-UI-007`) and reads nothing under
`specs/`/`gen/` (`R-UI-004`), while `AC-UI-007` asserted the page *does*
call `check_readiness` again on a scope switch. A provenance hit or
miss cannot be derived client-side at all: it needs
`provenance-checker`'s spec-bundle hashing and `impact-analyzer`'s
blast radius, both Python reading `specs/` and git. Separately,
`AC-UI-001` required a real browser running DuckDB-WASM with the
`duckpgq` extension. No browser exists in this pipeline's
verification environment, and a generated candidate can only emit text
files, so it cannot vendor a multi-megabyte WASM binary; loading one
from a CDN would break the page's own no-network constraint.
`component.md`'s own prose ("most are `compiled`") had also drifted
from its criteria (all `generated-test`).

A second gap surfaced while choosing a replacement: `check_readiness`
with `model=None` raises `UsageError` on any capability provenance
miss rather than reporting it, so a no-model build would fail on
exactly the fresh checkout this component's constraints call the
common case.

## Decision

Decided by the project owner, from two options each:

- **Build-time snapshot.** `hotdocs track ui build` calls
  `check_readiness` once in Python, reads `corpus-graph.json` for
  topology and `.hotdocs/attempts/` for history, and writes one
  self-contained `index.html` with every datum inlined as JSON and
  plain JavaScript only. DuckDB-WASM and `duckpgq` are dropped. The page
  shows state as of its last build; changing scope or refreshing means
  rebuilding. Because nothing is fetched at view time, the page opens
  directly from `file://`, which removes `R-UI-006`'s CORS rationale
  for a local server: `hotdocs track ui serve` is retired.
- **The build takes `--model`.** It passes straight through to
  `check_readiness`, exactly as `hotdocs verify --model` does, so a
  capability miss gets a real scenario run. Without it, a capability
  miss exits with the same usage error `hotdocs verify` gives.
  `provenance-tracker` itself is unchanged; adding a check-only mode
  there was considered and declined, as it would mean regenerating a
  component that took over thirty decisions to land.

Every requirement and criterion is rewritten to match, pinning the
inlined snapshot's exact shape and the page's per-node markup with
worked examples (`interface/data/TrackerSnapshot.md`).
