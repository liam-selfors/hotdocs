# D103 — R-AUTHOR-012 defaults synthetic fixtures to sealed:true, sidestepping realizes/capability-linkage entirely

## Context

`D102`'s fix (stating the required `component.md` frontmatter fields) got several of `spec-bundle-assembler`'s own test authorings past the crash it was written to close, but a further real retry surfaced the next layer of the same underlying problem one rule at a time: `realizes` was present but an empty list, which `spec-linter`'s own `R-LINT-006` correctly rejects (a non-sealed component must name at least one real `P-<id>`) — a rule `R-AUTHOR-012` never stated, and one of many `spec-linter` structural rules a synthetic fixture could trip in turn. Enumerating every such rule individually in `test-author`'s prompt, one real failure at a time, does not scale and was already showing diminishing returns after two rounds.

`realizes`'s own condition (`SPEC_GUIDELINES.md` §2) is "required unless `sealed: true`" — and a `sealed` component is exempt from `realizes` *and* the cold-regen/capability-linkage machinery entirely. A synthetic test fixture whose own criterion has nothing to do with capability linkage has no reason to engage with `realizes` at all; defaulting it to `sealed: true` (with any non-`gen/` `source_path`, e.g. a short fabricated path) sidesteps this entire class of rule in one step, rather than needing to also supply a resolvable `P-<id>` and (by further extension) a matching product-capability spec file just to satisfy an incidental precondition unrelated to what the test actually checks.

## Decision

`R-AUTHOR-012` is amended in place (not superseded, the same pattern `D97` already used for `R-AUTHOR-010`): the required-frontmatter instruction now states that a synthetic fixture SHOULD default to `sealed: true` (with a short, clearly-fake `source_path` not under `gen/`) unless the criterion under test specifically concerns `realizes`/capability-linkage behavior — in which case the fixture MUST instead supply a `realizes` list naming at least one `P-<id>`, understanding that `spec-linter`'s own traceability-closure checks then require a matching real or fixture-constructed product-capability spec for that id to resolve.

`test-author` is cold-regenerated against this amendment (generate-only, verified via the hand-maintained suite, never `bootstrap_component.py`'s own staged driver, per the standing `D58` exception); `spec-bundle-assembler`'s still-failing criteria are re-authored and re-verified once this fix is in place.
