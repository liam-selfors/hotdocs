# D69 — Applying D67's lesson before spending a call to rediscover it

## Context

`secret-scanner`'s own spec (`R-SECRET-001`) requires its pattern
database to be sourced exactly the way `license-scanner`'s reference
corpus is — "a maintained, continuously-updated external reference
set, never hand-rolled and frozen into this spec," the same text
pattern, citing `R-LICENSE-001` directly. `D67` already found that a
real `generate()` candidate for `license-scanner`, given no named
location for that kind of input, defaults to `.hotdocs/` —
`SPEC_GUIDELINES.md`-forbidden for anything a gate's pass/fail
decision depends on.

Given `secret-scanner` shares the identical shape, spending a real,
billed `generate()` call to rediscover the identical gap would add no
new information — the outcome is predictable from `D67` alone.

## Decision

Added `VAR-SECRET-PATTERNS-PATH`, mirroring `VAR-LICENSE-CORPUS-PATH`
exactly, before the first real `generate()` attempt for this
component. `R-SECRET-001` now names it directly. Also fixed this
component's own stale "every criterion is `kind: compiled`" claim
(`D59`'s reclassification), found while already in this file.

## Consequences

This is the first case in this sequence where a finding from one
component's real generation attempt was applied *pre-emptively* to a
different, not-yet-attempted component, rather than discovered fresh
each time. A reasonable judgment call, not a new general policy: done
here because the two components' specs literally cross-reference each
other's requirement by id, making the shared shape explicit rather
than inferred.

Linter: 0 failures once this file exists. Pytest: all 140 tests across
all eleven real components re-verified unchanged (spec-only edit).
