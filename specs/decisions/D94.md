# D94 — test-author's prompt gets a nonce-delimited single-file output protocol, mirroring generator's D38 fix

## Context

The first real, non-mocked use of `test-author`'s `author_test` against a genuine downstream criterion (bootstrapping `provenance-tracker`, the first of the seven still-unbuilt components) surfaced a real, previously undiscovered gap: `test-author`'s own `_build_prompt` says only "Output only the test code," and `author_test` takes `response.get("text")` as the literal file content with no extraction step. Against five real criteria, this produced two distinct failure shapes: one response wrapped the real code in a markdown ```python fence (invalid Python once written verbatim to disk); the other four produced partial transcripts of an attempted tool call ("**Tool: Bash**", "I'll check the repo layout...") instead of the test code itself, since nothing in the prompt told the model it has no tool or file access and must work only from the bundle content given.

Both failure modes trace to the same root cause: `test-author`'s output extraction is "trust the raw response text completely," which generator's own `R-GEN-003`/`D38` already found unreliable for exactly this reason and fixed with a per-call nonce-delimited marker format. `test-author`'s own `AC-AUTHOR-*` suite never exercised this path for real — every one of its criteria is verified with an injected mock backend returning clean text directly (`D58`'s bootstrap account), so this gap was invisible until a genuine model response had to survive the round trip.

## Decision

`test-author`'s prompt (`_build_prompt`) gains the same per-call nonce-delimited single-file marker format `generator` already uses (`D38`), wrapping the one test file instead of several, plus an explicit statement that the model has no tool or file access and must produce its answer from the bundle content given — nothing invented about the target component's real code, nothing explored on disk. `author_test` extracts the file content strictly from between the markers; a response with no matching markers (model ignored the instruction, or emitted a `model_call_error`-free empty/malformed reply) is treated as a authoring failure, not written to cache or disk, same distinct-failure-mode posture `R-AUTHOR-007` already states for a real `model_call_error`.

New requirement `R-AUTHOR-009` states the marker format and the no-tool-access instruction normatively. `PROMPT_VERSION` bumps to `v2`. `test-author` is cold-regenerated against its own updated spec bundle; its `AC-AUTHOR-*` suite (verified via injected mock backends, `D58`) gains one new criterion (`AC-AUTHOR-009`) asserting the new extraction behavior, including stripping an unsolicited markdown fence or narration a mock backend places around the delimited block.
