# D356 — spec-linter's command line is a requirement with a criterion

## Context

`spec-linter`'s `interface/cli.md` had no requirement citing it, which
`R-LINT-031` reports as a warning, and no criterion exercised `main`.
Regenerating `spec-linter` for `D354` re-authored every test, and the
fresh suite left `main`'s argument handling, output and exit codes
untested: nine of the 23 surviving mutants were there, and the score was
0.79 against 0.8. The first fresh suite also built a fixture corpus with a
stray fail finding, since `spec-linter` had no `testing.md`.

## Decision

`R-LINT-035` requires `main` to implement `interface/cli.md`, and
`AC-LINT-041` checks its exit codes, `--strict` and JSON output.
`spec-linter`'s `testing.md` gives a lint-clean fixture corpus, verified
to produce no findings, with one edit that adds exactly one `warn` and one
that adds exactly one `fail`. To pay for the new text, the change log
lists decision ids only and `R-LINT-019` keeps one line of rationale.

## Consequences

`spec-linter` no longer warns about its own `cli.md`.
