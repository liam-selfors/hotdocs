# D85 — A principle already ratified for dependencies, never applied to the target itself

## Context

Alongside the dependency-contract audits that found `D81`-`D84`, a
second audit specifically targeted prompt efficiency: whether
`generator`'s real prompt (built from `spec-bundle-assembler`'s
`assemble()`) carries content that does not help the model write
correct code, for both token cost and the general risk that excess
context distracts a model from what actually matters.

The clearest finding: the target component's own `component.md` is
included in full, every call, via `_component_spec_text()`'s
`comp.root.body`. Measured directly across real components: the
`## Rationale`, `## Open questions`, and `## Change log` sections
alone are 60% of `criterion-compiler` body, 35% of
`merge-orchestrator`, 15-20% for smaller components. None of this
explains what the model must build -- only why past decisions were
made, a human-audit concern.

The telling part: `R-ASSEMBLE-002` already states exactly the right
principle, just for the wrong half of the bundle -- "a dependent needs
the contract, not the internal rationale" -- and enforces it correctly
in real code for every dependency (confirmed: dependencies get only
`_component_interface_text()`, never requirements/constraints/
component.md). The target itself was simply never held to its own
rule.

## Decision

`R-ASSEMBLE-001` now states the target's own `component.md` excludes
`## Rationale`, `## Open questions`, and `## Change log` specifically
-- `Purpose`, `Scope`, `Definitions`, and the `Behavior`/`Interfaces`/
`Data`/`Acceptance criteria`/`Non-functional constraints` pointer text
stay, since (unlike a dependency, where only the public contract
matters) the target's own Scope and Definitions genuinely describe
what to build.

New `AC-ASSEMBLE-012` and a real test confirm the gap against the
current, unfixed `gen/spec-bundle-assembler/spec_bundle_assembler.py`
-- the fixture gained distinctive marker text in each of the three
sections specifically to make the leak checkable; the test correctly
fails. The actual code fix (splitting `component.md`'s body by
heading and filtering) still needs a real `generate()` call, blocked
on exhausted API credits as of this decision.

## Consequences

The most direct, measurable result of this session's prompt-efficiency
audit, and -- unlike `D81`-`D84` -- not itself an instance of the
"undocumented cross-component convention" gap class; it is closer to
"an already-ratified rule simply was not applied symmetrically."
Expected to meaningfully shrink every future generation prompt, with
the biggest absolute savings for components with the longest decision
histories (this session's own work has been adding to several of those
histories all along).
