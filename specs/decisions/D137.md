# D137 — decision-drift-detector mutation score needed two more scenarios, tie-break and CLI defaults

Fifth through ninth real cold-generation attempts for
`decision-drift-detector` all passed behaviorally once `D134`'s edge
direction clarification landed, but `mutation_score` oscillated
between `0.58` and `1.0` across different test-authoring seeds against
the identical spec and candidate — never reliably at or above `0.8`.
Diagnosed directly by running the real mutation harness against a
representative round (seed 3, score `0.735`): the nine consistently
surviving mutants cluster in three functions no existing scenario's
fixture ever exercises precisely: `_latest_by_ratification` (the
tie-break among *multiple* decisions that each supersede the same
cited one — every existing scenario has only a single superseder in
the chain), `_discover_repo_root` (the no-`--repo-root`-given default
path — every CLI scenario so far always passes one explicitly), and
`_parse_args` (an invalid `--format` value — never tried).

Rather than add new requirements for behavior `R-DRIFT-001`/
`R-DRIFT-005` already specify, this decision adds the missing
scenarios directly to the existing acceptance criteria: `AC-DRIFT-001`
gains a two-superseder tie-break scenario (`D32` ratified after `D31`,
both citing `supersedes: [D17]` — `D32` must win); `AC-DRIFT-005`
gains a no-`--repo-root` default-discovery scenario and an invalid
`--format` scenario. Retrying generation next.
