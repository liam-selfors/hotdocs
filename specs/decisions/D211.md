# D211 — `SPEC_GUIDELINES.md` defines how each size-cap dimension is measured

## Context

`SPEC_GUIDELINES.md` §4 gives each size-cap dimension a threshold but,
for `interface_surface`, pointed at a docstring in `spec-linter`'s
hand-written code for what counts. `generated_code_loc` was not defined
anywhere. Once `spec-linter` is generated from its spec, with the
guidelines in its bundle (`D210`), a definition living only in old code
is lost, and two correct implementations could report different numbers.
The hand-maintained tests for the count called that private function, so
they could not run against any other implementation.

## Decision

§4 gains "How each dimension is measured": the exact rule for every
dimension, written from what the hand-written linter computed, so the
numbers do not change. The surface-count tests now go through `lint()`:
they copy a real component's `interface/` into a minimal corpus, pad it
past the warn threshold, and read the count back from the finding.

## Consequences

A regenerated `spec-linter` reports the same sizes as the one it
replaces, and the tests check that through the public interface.
