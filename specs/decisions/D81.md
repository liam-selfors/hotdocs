# D81 — Caught before generation, by auditing dependency contracts proactively instead of reactively

## Context

Following this session's string of "unwritten cross-component
convention" findings (D61, D62, D65, D67, D69, D76, D80), the real cost
of discovering each one only after a failed real `generate()` call
prompted a different approach: before ever calling `generate()` for
the next batch of components, proactively audit every not-yet-built
component's dependency contracts for the same gap class, using forked
parallel audits across the whole corpus (15 built components'
consumer/dependency edges, plus all 6 not-yet-built components).

One of those audits, covering `spec-completeness-assistant`'s
dependency on `generator`, found a real, severe gap before a single
token of real generation was spent on it: `spec-completeness-assistant`'s
entire purpose (`R-ASSIST-003`) is producing a non-destructive
`hint`-mode preview of a feature-branch spec change. But `generator`'s
real, already-swapped-in `generate()` checks `bundle.hint_code` only to
add it to the model prompt (`R-GEN-002`) — never to gate whether it
writes to `gen/<component>/` or to `cache-manager`. Both writes happen
identically in `hint` and `cold` mode.

Direct inspection of `spec-bundle-assembler`'s real code confirmed the
severity is worse than simple destructiveness: `spec_bundle_hash` is
computed with `hint_code` deliberately excluded
(`gen/spec-bundle-assembler/spec_bundle_assembler.py`, `_compute_hash`),
and `R-GEN-005`'s cache key (`spec_bundle_hash`, `gate_inputs_hash`,
`gate_version`, `model_pin`) depends on none of `hint_code` either. A
`hint`-mode and `cold`-mode call for the same spec state therefore
compute the *same* cache key — an unsuppressed `hint`-mode write could
let a later `cold` build, which must see no prior code at all
(`R-GEN-001`, `D1`), silently reuse a candidate the model produced
while looking at old code. That breaks the cold-build invariant itself,
not just a cache freshness guarantee.

## Decision

New `R-GEN-016`/`AC-GEN-017`: in `hint` mode, `generate()` MUST NOT
write to `gen/<component>/` or to `cache-manager` — it returns the
candidate (or cache hit) in the `GenerationResult` only. Reading the
cache stays enabled in `hint` mode (a hit can only exist for a hash
already matching some committed, canonical state, so reuse is safe and
exactly what a fast preview should do) — only the *write* path needed
gating. Cross-referenced into `interface/library.md` and `interface/cli.md`.

Two new real tests (`test_ac_gen_017_*`) confirm the gap against the
current, unfixed `gen/generator/generator.py` — both correctly fail: a
fresh hint-mode call writes to `gen/foo/` and to the cache; a cache-hit
read in hint mode still (incorrectly) leaves a `gen/foo/` write behind
too. The actual code fix is not applied yet — that requires a real
`generate()` call for `generator` itself, which is blocked on exhausted
API credits as of this decision. The spec fix and failing tests are
committed now so the next real call has a correct target to build
toward.

## Consequences

Sixth occurrence of the same root gap class this session, now caught
*before* spending a real call on it rather than after. This is the
concrete first result of the "audit dependency contracts proactively,
not reactively" process change — the audit that found this also
surfaced four more real findings (`merge-orchestrator`'s undocumented
`judge`/`test_author` callable contract, `provenance-writer`'s two
orphaned manifest fields, `capability-scenario-verifier`'s undefined
capability-scenario cache convention, `R-MERGE-011`'s unnamed
`blocked`/`flagged` fields), each to be addressed as its own fix before
its component is ever generated.

Also incidentally confirmed, by direct measurement while trimming
`component.md` to stay under `R-LINT-012`'s hard-fail word threshold:
the same session's prompt-efficiency audit's finding (component.md's
Rationale/Scope/Change-log prose is dead weight for generation) is real
and immediately actionable — `generator`'s own spec was already at the
hard-fail boundary before this fix, and trimming that exact content
bought the headroom this fix needed without losing any decision's real
record (each full narrative still lives in its own `D<N>.md`).
