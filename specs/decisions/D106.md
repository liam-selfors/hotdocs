# D106 — author_test tolerates a CriterionBundle missing an optional field; verifier-orchestrator's own duplicate bundle builder is a tracked, separate gap

## Context

The next real `spec-bundle-assembler` bootstrap retry (`D105`'s round) did not reach a clean pass/fail result at all — it crashed the whole run with an uncaught `AttributeError: 'CriterionBundle' object has no attribute 'dependency_interfaces'`, inside `test_author.py`'s `_field()` helper (`_criterion_content_hash` → `author_test`).

Diagnosis traced this to a second, independent `CriterionBundle` producer that `R-AUTHOR-011`/`D100` never accounted for: `verifier-orchestrator`'s own `verify()` builds its *own* internal `CriterionBundle` dataclass via `_build_criterion_bundle()` (`gen/verifier-orchestrator/verifier_orchestrator.py`), used whenever `verify()` authors a `generated-test` against a component's *own* acceptance criteria — the exact path every `bootstrap_component.py` run exercises for the target component's own criteria, and the normal live `hotdocs verify` pipeline exercises for every component. This bundle predates `D100` and has never carried `dependency_interfaces`; `spec-bundle-assembler`'s `assemble_criterion()` (the producer `D100` actually fixed) is a *different*, parallel path, only reached from `test_author.py`'s own CLI entry point and the hand-maintained test suite — not from `verifier-orchestrator.verify()` at all.

`test_author.py`'s `_field()` helper does `getattr(bundle, name)` with no default for a non-dict bundle, so any bundle missing any field it reads — not just `dependency_interfaces` — crashes outright rather than degrading gracefully. `CriterionBundle` was already established as duck-typed (`D94`); this is the first time two independently-shaped real producers both reached `author_test` in the same investigation.

## Decision

New `R-AUTHOR-016`: `author_test` MUST treat every `CriterionBundle` field access as optional, reading a missing field as absent (empty/`None`) rather than raising. This is `author_test`'s own responsibility as the consumer with more than one legitimate producer, not a contract either producer must individually satisfy. New `AC-AUTHOR-017`.

`verifier-orchestrator`'s own `_build_criterion_bundle()` never populating `dependency_interfaces` — meaning self-verification test-authoring never gets `D100`'s actual quality fix, only the crash-avoidance here — is a real, separate gap. It is deliberately **not** fixed in this decision: `verifier-orchestrator` is an already-built, currently-working component outside this bootstrap campaign's scope, and reconciling its internal bundle-building with `spec-bundle-assembler`'s canonical shape (by depending on it directly, or by duplicating `dependency_interfaces`-population logic) is a design choice for whenever `verifier-orchestrator` is next revisited, not a one-line patch. Recorded here as a known, tracked limitation per this session's diagnose-fix-safeguard-scrub discipline, rather than silently left for the next person to rediscover.
