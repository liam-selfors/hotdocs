# D311 — A surface check between generation and verification

## Context

`tools/bootstrap_component.py` rejected candidates that did not import
or that used names their dependencies lacked (`D288`), long before the
expensive verification ran. Those gates lived only in the tool's own
bootstrap, so a user's `hotdocs generate` had none. Command-line
mistakes, a traceback for a usage error or a silent exit (`D292`), were
found only when someone ran the command.

## Decision

A new component, `surface-checker`, runs three cheap checks on a
candidate: it imports; every name it uses on a direct dependency exists;
and a component implementing `specs/architecture/cli-conventions.md`
answers an unknown argument with exit `2`, a `usage error:` line and no
traceback. `generation-loop` runs it after generation and treats a
finding as a failed attempt.

## Consequences

The bootstrap tool's own consumer-surface gate stays: it checks the
names the tool's other components use, which only the tool's own
repository can know.
