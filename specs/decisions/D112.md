# D112 — test-author must use dual access when reading the target's own return value too, not only a faked dependency's

## Context

With `R-TRACK-011`'s fix (`D111`) landed, the next `provenance-tracker` retry confirmed the fix works exactly as intended — the candidate's dependency loader is now cleanly `repo_root`-relative, and the new `AC-TRACK-011` criterion exercised two separate `repo_root`s with distinct fakes in one process. But three other criteria (`AC-TRACK-007`/`009`/`010`) newly failed with `AttributeError: 'dict' object has no attribute '...'`.

Diagnosis: the real candidate's `write_attempt_record`/`check_readiness` return plain dicts, not dataclasses — a fact nothing in either function's documented interface (`AttemptRecord.md`, `VerifyReport.md`) states either way, consistent with this corpus's established duck-typing convention (`D94`). Comparing the generated tests for this one batch directly: `AC-TRACK-004`'s test already used a dual dict-or-attribute access helper (`_get(record, "component_id")`) and passed; `AC-TRACK-007`/`009`/`010`'s tests used bare attribute access (`record.component_id`, `report.scope`, `report.ready`) and crashed. This is the same model, in the same generation batch, applying the correct defensive pattern to one criterion and not to three others — evidence it already knows the pattern, not that it needs to be taught it for the first time, so the fix is an unconditional instruction rather than a new worked example.

Separately, `AC-TRACK-011`'s own generated test also failed, for an unrelated reason confirmed not to implicate the candidate: its fake `impact-analyzer` module was a maximally-permissive "chameleon" object (`__getattr__` returning `True` for any unmatched attribute name, to dodge not knowing the real return shape) — which made the candidate's own `precondition_error` check see a truthy value for every unanticipated lookup, masking a real precondition check as a fake failure. The hedge instinct (don't assume a dependency's shape) was right; defaulting unmatched lookups to `True` instead of `None`/absent was not. `AC-TRACK-011`'s own Gherkin is tightened to require the fake match the real documented signature exactly, closing the ambiguity that invited the chameleon design, rather than adding a new test-author rule for this narrower, one-off case.

## Decision

New `R-AUTHOR-021`: the prompt MUST instruct that every field read from a value the target component itself returns — not only a faked dependency's data — MUST use dual dict-or-attribute access, never assumed to be one shape. New `AC-AUTHOR-021`.

`test-author` is cold-regenerated against this amendment; `provenance-tracker` is retried once more.
