# D100 — CriterionBundle gains dependency_interfaces; AttemptRecord's in-memory generation/verification fields match the on-disk JSON shape

## Context

A fourth real `provenance-tracker` cold-generation (after `D95`-`D98` closed every previously-found gap) passed `AC-TRACK-004`/`008` but failed three criteria for three new reasons, none of them candidate bugs — in every case the real candidate called a dependency exactly as that dependency's own `interface/library.md` documents, and the *test* got it wrong:

- `AC-TRACK-010`'s authored test faked `provenance-checker`'s `check_provenance` with the wrong arity (2 positional parameters instead of the real 4: `component_id, spec_bundle_hash, gate_versions, repo_root`) — the real signature is fully documented in `provenance-checker`'s own `interface/library.md`, but `test-author`'s `CriterionBundle` never includes a dependency's `interface/` content, only the target component's own (`R-ASSEMBLE-009`/`R-AUTHOR-002`). `generator`'s own `SpecBundle` has carried exactly this information as `dependency_interfaces` since `R-ASSEMBLE-002`; `test-author` never received the equivalent.
- `AC-TRACK-009`'s authored test faked `impact-analyzer`'s `compute_blast_radius` returning a bare list, when the real, fully-documented return type (`BlastRadiusReport`, `interface/data/BlastRadiusReport.md`) is an object with an `impacted` field — again, information that exists in the dependency's own documented contract, never given to `test-author`.
- `AC-TRACK-007`'s authored test asserted `record.generation.model_call_error` (attribute access) on the `AttemptRecord` `write_attempt_record` returns in memory, but the real candidate's `generation`/`verification` fields are the same JSON-equivalent plain-dict form written to disk (`_to_jsonable`-converted) — a reasonable, undocumented implementation choice, since `AttemptRecord.md` only ever specified the *on-disk* JSON shape, never stating whether the in-memory returned object matches it exactly or echoes the original caller-supplied object's own type.

## Decision

**`CriterionBundle` gains `dependency_interfaces: dict[str, str]`** — one entry per id in the target component's `depends_on`, each value that dependency's full `interface/` content, exactly the same content and the same `R-ASSEMBLE-002` rule `SpecBundle.dependency_interfaces` already follows (interface only, never `requirements/`/`constraints.md`/`component.md`). This does not reopen `R-AUTHOR-002`'s independence boundary — that boundary is about the *target* component's own implementation, never about a third party's already-public, already-documented contract; knowing a dependency's real signature cannot help a test author "cheat" on verifying the target's own behavior, it only prevents writing a fake that doesn't match reality. `R-ASSEMBLE-009` is amended to include it; `test-author`'s new `R-AUTHOR-011` states that the prompt MUST include each dependency's interface content and instruct the model to match any fake it writes against the real documented signature/return shape, never inventing one.

**`AttemptRecord.md`/`R-TRACK-007` are clarified**: the `AttemptRecord` returned in memory by `write_attempt_record` carries `generation`/`verification` in the exact same JSON-equivalent form written to disk — a plain dict matching `AttemptRecord.md`'s own documented shape, never the original caller-supplied `GenerationResult`/`VerificationReport` object echoed back by reference. A caller needing the original object already has it, having passed it in.

`spec-bundle-assembler` is cold-regenerated via the sandboxed `bootstrap_component.py` driver — a purely additive change to `assemble_criterion` only, `assemble()`/`SpecBundle` untouched — and verified against its full existing `AC-ASSEMBLE-*` suite (confirming no regression) plus new criteria for the new field before being swapped in, given how foundational this component is to every other real generation/verification/authoring call in the corpus. `test-author` is then cold-regenerated again against the updated spec, and `provenance-tracker`'s three remaining failing criteria are re-authored and re-verified.
