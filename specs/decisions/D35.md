# D35 — Build the `context` property: `component_context` view, `dependency_context` field, `Purpose` length cap

## Context

`notes/backlog.md`'s `context` property idea had three open questions
left once `D34` made `Purpose` dependent-safe by construction: whether
the view is new or folded into an existing one, how `R-ASSEMBLE-002`'s
blanket `component.md` exclusion gets its necessary exception, and
whether `Purpose` needs a hard length cap now that it can't carry
rationale padding. This decision resolves all three.

## Decision

**`component_context`** (new, fifth view in `graph-query-engine.md`'s
Query surface): one row per component, just its `Purpose` text,
extracted from `component_docs` the same way `R-LINT-002` already
extracts `Open questions`.

**`spec-bundle-assembler` adopts it** (`R-ASSEMBLE-010`): each
dependency's `Purpose` text now rides alongside its `interface/`
content as a **new, separate** `dependency_context` field —
`dependency_interfaces` itself is untouched, staying exactly what
`R-ASSEMBLE-002` already defines (the contract). `R-ASSEMBLE-002` is
amended to name this as the single, explicit exception to its "never
`component.md`" rule, scoped to exactly `Purpose`.

**`R-LINT-025`** (warn 80 / fail 150 words) makes `SPEC_GUIDELINES.md`
§3.4's existing "one paragraph" rule for `Purpose` a checked fact
rather than an unenforced description — the same reasoning `R-LINT-023`
already applied to oversized unit files.

**Found and fixed while verifying:** `impact-analyzer`'s `Purpose`
mixed a dependent-facing description with implementation rationale
(which DuckDB extensions it's built on) — moved to a new `Rationale`
section, even though it held no literal decision citation `R-LINT-024`
would have caught. The length cap caught what the citation check
couldn't.

## Consequences

The `context` property backlog item is fully implemented. A generating
model now sees, for every dependency, not just its contract
(`interface/`) but what it's for (`Purpose`) — closing the original
risk that motivated this: a call that's type-correct per signature but
wrong per an intent nothing previously shared with dependents.

See `specs/architecture/graph-query-engine.md`'s "Query surface"
section and `specs/components/spec-bundle-assembler/requirements/
R-ASSEMBLE-010.md` for the current, authoritative rules.
