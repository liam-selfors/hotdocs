# D50 — Real `generator`

## Context

`D47`/`D48`/`D49` built real `llm-endpoint`/`cache-manager`/
`spec-bundle-assembler` — `generator`'s three declared dependencies.
`generator` is the last piece needed for genuine (non-subagent-
simulated) cold regen to exist in this corpus at all.

## Decision

`gen/generator/generator.py` implements `R-GEN-001`–`012`:
`generate(bundle, model, retry_feedback=None, *, repo_root=None,
llm_backend=None) -> GenerationResult` constructs a frozen, versioned
prompt (`PROMPT_VERSION = "v1"`) from exactly the bundle's fields —
cold/hint/retry_feedback each a distinctly labeled section, never
merged with each other; checks `cache-manager` before any model call
and writes through it only on success; enforces the sealed/pinned-
override precondition before ever calling a model; dispatches through
`llm-endpoint`, never holding a credential itself.

Two real, pre-existing interface gaps, found by actually wiring this
component rather than by reading its spec: `generate()` had no
`repo_root` — `R-GEN-009`'s precondition check needs a component's real
`component.md` frontmatter and `.overrides.json`, neither reachable
from `SpecBundle` alone (`R-ASSEMBLE-001` excludes frontmatter by
construction) — and no injectable-backend parameter, despite every one
of this component's own acceptance criteria requiring "an injected mock
model." Both added to `interface/library.md`. A third gap found one
level down: `cache-manager`'s `gate_type` registry never listed
`"generator"`, even though `cache-manager`'s own `Purpose` names it as a
consumer — added as a sixth type.

`R-GEN-009`'s pinned-override check is implemented whole-component, not
per-file — a deliberate, documented interpretation: `R-GEN-009`'s own
prose describes a per-file exemption, but `AC-GEN-009`'s own Gherkin
tests a simpler, more conservative behavior (any non-empty
`.overrides.json` refuses the whole component). Implemented what the
acceptance criterion actually demands, flagged in `BOOTSTRAP.md` as an
interpretation rather than silently assumed to match the fuller prose.

This is the seventh hand-bootstrapped component, but — like
`llm-endpoint`, unlike `cache-manager`/`spec-bundle-assembler` —
structurally permanent: nothing could cold-regenerate the component
that does the cold-regenerating.

Verified entirely on an injected mock backend, at zero cost: 10/10
tests pass, one per `AC-GEN-*` criterion with a defined acceptance file
(`R-GEN-007`/`010` have none, both superseded by `D31`'s retired
best-of-k loop — nothing to test against).

## Consequences

Every component a real `generator` needs now has a real implementation.
The next natural step — attempted separately, not here — is using this
real `generator` for an actual cold-generation attempt against the real
corpus, closing the loop `D45`'s subagent simulation only approximated.

`spec-bundle-assembler`/`generator`) run separately,
42/7/8/7/10/10/10 passed.
