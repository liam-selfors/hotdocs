# D91 — A second decision-to-decision relationship, distinct from supersedes

## Context

`supersedes` (`D87`) models exactly one relationship: full
replacement. Many decisions in this corpus build on a prior one's
reasoning without replacing any of it — informally, in prose, today
("D55 built on D44's..."). The user asked for this to be a structured
fact a tool can walk too, not only something a human has to parse out
of narrative.

## Decision

New, optional, list-valued frontmatter field `builds_on`: the `D<N>`s
a decision's own reasoning depends on. Unlike `supersedes`,
many-valued and carrying no status-flip obligation on either side —
`builds_on` never implies the referenced decision is obsolete. New
`R-LINT-030` validates every entry resolves to a real decision (the
same frozen `D1`–`D14` exemption `R-LINT-029`/`026` already use),
minus `R-LINT-029`'s status-consistency half, since that half only
makes sense for a replacement relationship.

## Consequences

Decision records now have two distinct graph relationships
(`supersedes`, `builds_on`), both validated the same way. Neither has
a real population yet — this decision adds the capability; using it
retroactively on the corpus's many informal "built on" references is
a separate, not-yet-done pass, the same bar `D87`'s own retroactive
`supersedes` formalization was held to (only one confirmed case
touched then, not a blanket sweep-and-apply).
