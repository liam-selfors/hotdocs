# D91 — hotdocs generate is component-gate-runner's CLI verb; generator retires its own standalone CLI

## Context

`D86` named `component-gate-runner`'s new developer-invoked command `hotdocs prepare`, to avoid colliding with `generator`'s own existing `hotdocs generate <component-id> --model=...` (the narrower, single-candidate-producing step). In practice, nobody has a reason to run just that narrower step directly anymore — the full gauntlet (provenance check, generate-on-miss, verify, scan, write provenance) is what a developer actually wants, every time. Inventing a second verb ("prepare") for what is, from a developer's own perspective, simply "make this component's code and its proof current" adds a name to learn for no real benefit.

## Decision

`hotdocs generate <component-id>` is `component-gate-runner`'s CLI verb — it replaces `hotdocs prepare` everywhere that name was used. `generator` keeps its real role (the component owning the actual model-call mechanics, `R-GEN-*` unchanged) but retires its own standalone CLI entirely; its `generate()` function is now called only internally, by `component-gate-runner`, never invoked directly by a developer.
