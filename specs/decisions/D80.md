# D80 — Two independent candidates, two different wrong answers, confirming a real gap

## Context

`D79` fixed a real bug in `criterion-compiler` (sealed) and, in doing
so, documented for the first time the execution-environment contract
its emitted output requires. Retrying `verifier-orchestrator`'s
`generate()` call with that fix in place produced a candidate that
correctly honored it, but surfaced two further, separate problems:

1. A wrong line selected out of pytest's own assertion-rewriting
   output when building `failure_detail` for a `compiled` criterion
   (grabbed the last `E `-prefixed line, which can be a `+  where
   ...` explanation rather than the actual `assert X == Y` line) —
   a plain bug, fixed by deleting the candidate and retrying with
   `retry_feedback=[R-VERIFY-012]`; the retry's replacement candidate
   used `pytest`'s own `reprcrash` API instead of regexing captured
   text, and got it right.

2. `R-VERIFY-002`'s "from cache if already authored for this
   criterion's content" check needs to predict the exact file path a
   `generated-test` criterion's authored test lives at, before ever
   calling `test_author`. The first candidate wrote/checked
   `ac_foo_002.py` (dropping `test-author`'s own `test_` prefix); this
   second, otherwise-much-improved candidate invented an entirely
   different scheme — a private `verification/<component>/
   generated-test/cache/<criterion_id>-<content_hash>.py` — that would
   never find a file `test-author`'s own real, already-swapped-in
   implementation (`gen/test-author/test_author.py`,
   `_relative_output_path`) actually writes.

## Decision

(1) is a one-off implementation mistake — not promoted to a spec
change. (2) is promoted: two independent candidates each getting this
detail wrong, in two different ways, confirms what was really going
on — the deterministic filename formula (`test_<criterion_id,
lowercased, '-'->'_'>.py`, no further nesting, no hash suffix) was
already used identically by both `criterion-compiler`'s own compiled
output and `test-author`'s real implementation, but had never been
written down as a *rule* anywhere a `SpecBundle` surfaces — only
implied by one illustrative JSON example in `test-author`'s own
interface data (`TestAuthoringResult.md`), technically bundle-visible
to a dependent but never stated as a cross-component contract.

Promoted to `glossary.md` as "Criterion test filename," and
cross-referenced from `R-AUTHOR-006` (tightens "written under
`verification/<component>/generated-test/`" to the exact filename
formula) and `R-VERIFY-002` (states explicitly that this component's
own pre-dispatch cache check is a plain file-presence check at that
exact predictable path, never a self-invented scheme).

## Consequences

This is the same recurring gap class as `D61`/`D62`/`D65`/`D67`/`D76`
— a fact two or more components independently need, never promoted to
anywhere a `SpecBundle` actually surfaces. Fifth occurrence now.
`verifier-orchestrator` itself is not yet swapped in — this decision
covers only the spec-text fix; the next `generate()` retry, and
whatever real outcome it produces, is its own separate decision.
