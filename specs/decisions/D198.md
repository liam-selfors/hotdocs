# D198 — test-author takes the modules under test explicitly for capability scenarios

## Context

`capability-scenario-verifier` asks `test-author` for a capability
scenario's test with `component_id` `capabilities/<P-id>`, so the file
lands under `verification/capabilities/<P-id>/`. `test-author` derives
the module to import from that id (`D189`), giving
`import capabilities/P_SLUGS`, which is not Python. Every capability
scenario in every project failed this way.

## Decision

A criterion bundle may carry `module_names`. When it is non-empty,
`test-author` names those modules as the ones under test instead of
deriving one. `capability-scenario-verifier` passes each realizing
component's module, in component id order. Component criteria are
unchanged.

## Consequences

The output path still comes from `component_id`, so capability tests
stay where they were. The field is optional, so bundles from
`spec-bundle-assembler` need no change.
