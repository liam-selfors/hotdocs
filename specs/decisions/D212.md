# D212 — `cache-manager`'s CLI, stats and shared-store behavior are exact

## Context

Regenerating `cache-manager` from its spec (seed 2) passed all ten
criteria but reached a mutation score of only 0.43. The survivors sat in
code the criteria never reached, because the spec left it open: what a set
`VAR-CACHE-STORE-URL` does (the candidate invented `file://` support),
what `stats` counts ("aggregate hit/miss counts", with nowhere to keep
them), and the CLI, which named a `hotdocs cache` verb that `hotdocs-cli`
has never routed. The hand-written version had no CLI at all and
treated a set URL as unreachable.

## Decision

The spec states what the hand-written version did, plus the CLI it never
had. A set `VAR_CACHE_STORE_URL` makes `get` miss and `put` store nothing
after validating, since no shared-store client exists. `stats` reports
the local store's current entry count. The CLI is `python -m
cache_manager` with `main(argv)`, `inspect` and `stats` printing one JSON
line each, and exit `2` for any usage error. The library gains `stats()`, names `SchemaValidationError`, and makes
`Miss` instances equal, all of which the hand-maintained tests already
used. `CacheKey.md` states that `gate_version` is `<gate_type>@<version>` and
that a result's `gate_type` must match it, which a generated test (seed 3)
got wrong. `AC-CACHE-006` becomes
concrete, and `AC-CACHE-011` and `AC-CACHE-012` cover `stats` and the
shared-store case.

## Consequences

`notes/metrics.md`'s cache hit rate still has no source; a counter is a
new decision once a shared store exists.
