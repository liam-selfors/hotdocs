# D7 — generator has no custom retry/timeout logic for infrastructure-level failures

## Decision

`generator` runs no internal retry-with-backoff and invents no timeout duration for the underlying model call — it trusts the model SDK's own bounded timeout. A single call either succeeds or fails within that bound; any failure is reported as a `model_call_error` exactly once. This is distinct from, and unaffected by, whatever policy governs retrying generation itself after a candidate fails verification.

## Consequences

A future non-Anthropic backend must provide this bound itself if its own runtime doesn't guarantee one natively — not resolved generically, since no second backend exists yet to resolve it against.
