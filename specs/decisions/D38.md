# D38 — Resolve three remaining `D31`/`D32` audit gaps

## Context

`notes/backlog.md` tracked four gaps found during the `D31`/`D32`
corpus-wide audit. `D36` resolved the first (`GoldenScenarioReport`'s
missing `rationale`, as part of the capability-scenario rename). This
decision resolves the remaining three.

## Decision

**`license-scanner`/`secret-scanner`'s webhook notification.**
`notified` conflated "a notification was due" with "a notification was
delivered" — no way to tell a successful webhook call from one that
silently failed. Resolved by adding `notification_delivery_error`
(`{category, message}` or `null`, mirroring `model_call_error`'s shape
from `D32`) to both `LicenseScanResult` and `SecretScanResult`.
`notified` keeps its existing, precondition-only meaning; delivery
outcome is the new field's job. The webhook call itself is now
explicitly a bounded, no-retry-with-backoff call, the same posture
`R-ENDPOINT-004` already established for model calls — a real HTTP
call deserves the same discipline this corpus already applies
everywhere else. `AC-LICENSE-009`/`AC-SECRET-011` test the failure
case directly.

**`compiled`-kind verification failures.** `VerificationReport.
criteria[].result` gave a failing `compiled`/`generated-test`
criterion no detail beyond `fail`, unlike `llm-judge`'s `rationale`.
Resolved by adding `failure_detail` (`{message, expected, actual}`,
`R-VERIFY-012`) — populated whenever the underlying check is a direct
equality/containment match, which the step-phrase grammar's own
templates make true for every `compiled` criterion unconditionally.
Deliberately **not** threaded through `requirement_results` or
`retry_feedback`: both already have an explicit content boundary
(`R-VERIFY-011`, `R-GEN-012`) protecting `spec-bundle-assembler`'s
`acceptance/` exclusion, and `failure_detail` does not reopen it —
it is exposed on `criteria[]` for provenance/review-packet/human
consumption only. `AC-VERIFY-013` tests the new field.

**`spec-completeness-assistant`'s `redundancy_flags`.** Had no defined
shape for a populated entry. Resolved as `{new_requirement,
overlaps_with, rationale}` (`R-ASSIST-005`): both `R-id`s identifying
the draft requirement and the pre-existing one it restates, and a
mandatory `rationale` — mandatory, not optional like
`VerificationReport.criteria[].rationale`, because `redundancy_flags`
only ever holds entries from a judgment call that actually fired
(unlike `criteria[]`, which mixes ran and not-ran entries in one
array), so there is no "fired but unexplained" state to accommodate.

## Consequences

All four `D31`/`D32` audit gaps are now closed (`D36` + this
decision). Two of the three fixes here reuse an existing structured-
error shape (`model_call_error`) rather than inventing a new one;
the third extends the `{result, rationale}` pattern this corpus has
now applied four times (`Finding`, `VerificationReport.criteria[]`,
`CapabilityScenarioReport.scenarios[]` via `D36`, and now
`redundancy_flags`) to its last remaining gap.

Linter: 0 failures, 17 warnings (unchanged from before this decision).
Pytest: 39 passed. See the individual component specs for the current,
authoritative text.
