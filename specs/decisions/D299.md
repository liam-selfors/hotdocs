# D299 — A `spec-scaffolder` component for decisions and new components

## Context

No tool helped a user record a decision: allocating the next id, writing
the frontmatter and section skeleton, ratifying it, flipping a superseded
record to `deprecated`, and filling `last_ratified_commit` with the commit
that landed it, which cannot be known while the record is written. Every
decision in the tool's own corpus was written by hand. The only
scaffolding tool, `tools/scaffold_component.py`, is bound to the tool's
own repository and is not a `hotdocs` verb, so a user's project cannot
use it.

## Decision

A new component, `spec-scaffolder`, provides `next_decision_id`,
`new_decision`, `ratify`, `record_commit` and `new_component`, exposed as
`hotdocs decision new`, `decision ratify`, `decision record-commit` and
`component new`. It writes structure and frontmatter only and never
commits. `tools/scaffold_component.py` becomes a thin wrapper over it.

`specs/architecture/cli-conventions.md` states the command-line contract
this and later components implement: `main` returns an int, a usage error
prints one `usage error: <cause>` line to stderr and returns `2`, and no
traceback is printed.

## Consequences

The component has no dependencies, so landing it forces no regeneration.
`hotdocs-cli`'s verb table gains its rows in a separate change.
