# D64 — impact-analyzer's first real generate() call exposes a genuine git-ref gap

## Context

A real `generate()` call for `impact-analyzer` (after a real 600s
timeout bump — see below) produced a well-structured candidate: correct
`depends_on`/`uses_var`/`realizes` edge construction from real
frontmatter, a sensible DuckDB-with-`duckpgq`-with-plain-SQL-fallback
design for the one-hop lookups `R-IMPACT-009` requires. But it never
compared anything against git history at all, despite
`R-IMPACT-002`/`003`/`008`'s own text requiring detection of a changed
`interface/cli.md`/`library.md`/`data/*`/`guarantees/*` "relative to
the prior commit." Instead it tried to infer interface-vs-internal
from the *shape* of a `--changed` id — which can never work, since
every real caller (every `AC-IMPACT-*` criterion's own Gherkin,
`merge-orchestrator`'s `R-MERGE-002`) only ever supplies component-
level ids, never anything finer-grained.

Confirmed by direct test against the real repo (already lint-clean):
`compute_blast_radius(["comp-cache-manager"], Path("."))` returned only
a `direct` entry — no `transitive-interface` propagation to any of
`cache-manager`'s real dependents (`generator`, `spec-bundle-
assembler`, several others), regardless of what had actually changed.
Root cause, checked directly: "the prior commit" is not defined
anywhere in this corpus — not in `impact-analyzer`'s own spec, not in
`merge-orchestrator`'s, not in `SPEC_GUIDELINES.md`. A real candidate,
lacking anywhere to look this up, implemented no git comparison at all
rather than guess at an unspecified git ref.

A second, smaller gap found in the same candidate: its output used the
bare slug (`"cache-manager"`) as `component_id`, where
`BlastRadiusReport.md`'s own example shows the full `comp-<slug>`
form. The example was never backed by an explicit requirement stating
this — a candidate reading only the prose, not cross-checking the
JSON example character-by-character, had a real way to miss it.

Separately, this same `generate()` call first hit `D52`'s 300-second
timeout floor twice before succeeding at 437 seconds once tested with
600 — `impact-analyzer` is a meaningfully larger, more structurally
complex component than any built so far, and the floor set when
`llm-endpoint`'s own smaller bundle needed it no longer covers this
corpus's largest real components. Fixed directly in code
(`ANTHROPIC_TIMEOUT_SECONDS` 300 → 600, still satisfying `R-ENDPOINT-
004`'s "at least 300 seconds" floor) — a one-line operational fix, not
itself a new finding worth a dedicated decision, recorded here only
for the full timeline.

## Decision

New `R-IMPACT-010` (acceptance: `AC-IMPACT-010`): "the prior commit"
resolves to the merge-base between `HEAD` and the repo's default
branch — the commit this branch actually diverged from, not `HEAD~1`
(meaningless after more than one commit) and not the default branch's
current tip (would miss changes it picked up after this branch
forked). Per-file change detection for `R-IMPACT-002`/`003`/`008` MUST
be a real git content comparison against that commit, never inferred
from a `--changed` id's shape.

`BlastRadiusReport.md` now states explicitly that `component_id` is
always the full `comp-<slug>` form, matching a caller's own `--changed`
argument — not left to an implicit reading of one JSON example.

The buggy candidate's `gen/impact-analyzer/` output was deleted before
being committed, never swapped in.

## Consequences

A retry, with both fixes in place, is the next real test — done
separately, not assumed here. This is the fifth real gap this
self-hosted-generation sequence has found in an unwritten or
underspecified corpus convention (`D55`, `D57`, `D61`, `D62`, now
`D64`) — each one found only because a real candidate had a real,
concrete reason to need the answer and nowhere to find it.

Linter: 0 failures once this file exists. Pytest: all 118 tests across
all nine real components re-verified unchanged (spec-only edit plus
one `llm-endpoint` constant, no `impact-analyzer` code exists yet to
re-test).
