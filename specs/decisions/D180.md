# D180 — llm-endpoint speaks six providers over one contract

## Context

`llm-endpoint` reached exactly one backend, the `claude` command. A tool
meant for other people's projects cannot assume every user has that
command, or a Claude subscription. The seam existed for this
(`R-ENDPOINT-002`/`003`); the second backend had simply never been
needed until now.

## Decision

Six providers behind the unchanged `complete(prompt, model, *, backend=None,
**params)`: `claude-cli`, `anthropic`, `openai`, `openai-compatible`
(OpenLLM, vLLM, LM Studio, LiteLLM, OpenRouter and similar, at a required
`base_url`), `gemini`, and `ollama`. The four HTTP providers use
`urllib.request` only: no SDK, no new dependency. Each adapter returns a
`model_call_error` for every failure and never raises, retries, or echoes
a key (`R-ENDPOINT-004`/`005`).

## What was checked against current provider documentation, and what was not

Fetched this session from the vendors' own pages:

- **Anthropic.** `POST /v1/messages`; `x-api-key`, `anthropic-version:
  2023-06-01`, `content-type` (the docs' own curl example); required body
  `model`, `max_tokens`, `messages`; the reply is a list of content
  blocks and the docs' own examples select the `type == "text"` blocks,
  which is why the adapter ignores thinking blocks. Errors: 401
  `authentication_error`, 403 `permission_error`, 429 `rate_limit_error`,
  504 `timeout_error`, 529 `overloaded_error`.
- **OpenAI.** `POST /v1/chat/completions`, `Authorization: Bearer`,
  `choices[0].message.content` (a string, or `null`); `max_tokens` is
  deprecated for `max_completion_tokens` and unusable with o-series
  models. The pages fetched did not state the auth and rate-limit status
  codes; 401 and 429 are assumed.
- **Gemini.** `POST /v1beta/models/{model}:generateContent`; body
  `contents[].parts[].text`; reply `candidates[0].content.parts[].text`;
  the `x-goog-api-key` header appears in Google's current quickstart
  (the `generateContent` reference shows a `?key=` query form, which the
  adapter avoids so a key cannot surface in a URL). 403 `PERMISSION_DENIED`
  and 429 `RESOURCE_EXHAUSTED` confirmed. An invalid key is documented
  inconsistently, as a 400 on one page and a 401 on another, so both are
  mapped to `auth`.
- **Ollama.** `POST /api/chat` with `stream: false`, reply
  `message.content`, `GET /api/tags` as the liveness probe, default
  `http://localhost:11434`.

**Not confirmed from documentation:** the Gemini `thought: true` marker on
reasoning parts (the adapter skips such parts); Ollama's error body shape;
that Ollama truncates an over-long prompt unless `num_ctx` is set; and
that the model suggestions work on every plan (`gpt-6-astra`,
`gemini-4-argon` are the vendors' listed flagships; `llama3.2` is the
name in Ollama's own examples; `claude-sonnet-5` is the repository's
model pin). The Anthropic default of `max_tokens` 32000 is a judgement:
generation needs room for a whole component, while Anthropic's docs warn
that a very large non-streaming request risks a dropped connection.
