# D135 — graph-query-engine's library.md must state the literal yaml extension install incantation

Third real cold-generation attempt for `decision-drift-detector`
(after `D134`'s two fixes): all four criteria failed identically with
`InvalidInputException: Installing extension 'yaml' failed ... already
installed but the origin is different` — a real, machine-level DuckDB
extension-registry conflict, not a logic bug. Diagnosed directly:
every existing caller of `graph-query-engine`'s `load_views`
(`spec-linter`, `spec-bundle-assembler`, `verification/graph-query-
engine/conftest.py`) already installs the extension as `INSTALL yaml
FROM community`, never a bare `INSTALL yaml` — but
`interface/library.md` only said "the `yaml` community extension"
in prose, never the literal incantation. The candidate wrote a bare
`INSTALL yaml`, which defaults to a different extension registry and
conflicts outright once the community-origin extension is already
cached on a given machine from any prior install — the same "prose
alone has repeatedly proven insufficient" lesson recurring yet again
(`R-AUTHOR-010`/`R-TRACK-010`/`R-DRIFT-001`), this time against a
dependency's own documented contract rather than a component's own
requirement.

`interface/library.md` amended with the literal snippet:
`INSTALL yaml FROM community` then `LOAD yaml`, never a bare
`INSTALL yaml`. No code change needed in any already-built caller —
each already does this correctly; only the documentation a *new*
caller's generation prompt actually receives was incomplete. Retrying
`decision-drift-detector`'s generation next.
