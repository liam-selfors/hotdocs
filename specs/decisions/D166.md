# D166 — component-gate-runner's spec rewritten before its first build

## Context

`component-gate-runner` is the last unbuilt component. Auditing its
spec against what its dependencies actually expose, before spending a
single generation on it, found it could not be built correctly as
written:

- **`AC-GATE-002a` contradicted the spec.** It passed an already-wired
  `test_author` into `run_component_gates`, which since `D86` builds
  its own closures and has no such parameter.
- **`ComponentPipelineResult` could not express a block.** `R-GATE-004`
  requires a block reason; the data shape had no field for one.
- **No dependency call list**, the gap `D156` closed for
  `spec-completeness-assistant`: which function of which dependency,
  with which arguments, and how `ProvenanceInputs` is assembled.
- **No judge contract.** This component builds the `judge` closure,
  yet nothing said what prompt it sends or how a reply becomes
  `{result, rationale}`.
- **A failed attempt could never be retried.** Provenance is written
  for every attempt, and any hit short-circuited regeneration, so a
  failed attempt's own record would block every later `hotdocs
  generate` until the spec changed.
- **`R-GATE-001` and `R-GATE-005` contradicted each other** on whether
  a hit runs the scanners.
- No CLI requirement (`D162`); merge-era wording throughout.

## Decision

The spec is rewritten around `D163`'s canonical provenance key.
`interface/library.md` lists every call in order. Only a hit recording
a passing, unblocked attempt short-circuits; anything else proceeds
as a miss. Provenance is written only when a candidate reached
`gen/`; the attempt record is written for every miss.
`ComponentPipelineResult` gains `component_id`, `blocked`, and
`block_reason`. New `R-GATE-009` covers the CLI, and `R-GATE-010` the
judge: one `complete` call carrying the criterion, the requirement, the
interface, and the component's `gen/` code, answered as JSON, with any
failure reported as `fail`, never as a pass.

## Found along the way, not resolved here

- A sealed component never receives a `.provenance.json` here, so
  `provenance-tracker`'s whole-corpus check reports it not ready
  indefinitely.
- `capability-scenario-verifier`'s built code has no
  `run_capability_gates`, although `R-SCENARIO-004` requires it and
  `provenance-tracker` calls it on any capability miss. Its tests pass
  only because they predate that requirement.
