# D331 — Two capability scenarios state the fixture facts their tests guessed

## Context

The corpus-wide `hotdocs verify --model` after the demo-fix
regeneration authored fresh tests for every capability scenario. A
scenario's test author sees only the scenario. `CS-AMBIGUITY-001`'s test
gave its fixture requirement files headings like `# R-FOO-001: Store a
widget`, which `R-LINT-007` rejects, so lint failed for the wrong
reason. `CS-COMPLIANCE-001`'s test faked `check_readiness` with
`components` as a list, where `VerifyReport` keys it by id, and
`review-packet-builder` crashed. The tests these replaced still pass
against the current code.

## Decision

`CS-AMBIGUITY-001` states that each requirement file's first heading is
exactly its id. `CS-COMPLIANCE-001` states that a stand-in
`check_readiness` returns `components` and `capabilities` as mappings
keyed by id. Product specs enter no component's bundle, so no
component's provenance changes.

## Consequences

Both capabilities' gates run again.
