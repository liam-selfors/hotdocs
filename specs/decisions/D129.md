# D129 — test-author must truncate its own write-time window bounds to the field's documented precision

Second real cold-generation attempt for `provenance-writer` (seed 1,
retry-feedback `R-PROV-014`): 11 of 14 criteria passed (up from 6 of
12 — `R-PROV-014` landed cleanly, confirmed by `AC-PROV-014` itself
passing). `AC-PROV-008` failed with
`before(2026-10-29T14:56:18.579785+00:00) <= parsed(2026-10-29T14:56:18+00:00)`
— `False`. Diagnosed directly: the candidate's `generated_at` uses
`strftime("%Y-%m-%dT%H:%M:%SZ")`, whole-second precision, exactly
matching `interface/data/provenancemanifest.md`'s own documented
example (`"2026-01-01T00:00:00Z"`, no fractional digits). The
generated test captured its own `before`/`after` window bounds with
full microsecond precision via plain `datetime.now(timezone.utc)`,
then compared the parsed, truncated-to-the-second `generated_at`
directly against those microsecond-precision bounds — a correctly
implemented candidate fails this comparison on almost every real run,
since truncating down to the start of a second makes the written
timestamp numerically less than `before` whenever `before`'s own
microsecond component is nonzero (true the overwhelming majority of
the time).

This is a reusable test-authoring gap, not specific to
`provenance-writer`: any future component with a wall-clock "own
write time" field documented at whole-second precision can hit the
identical failure. New `R-AUTHOR-023` (`test-author`) states the
general fix: a write-time window test MUST truncate its own
`before`/`after` bounds to the field's own documented precision
before comparing.

Two other issues from the same retry are not spec-fixed by this
decision: `interface_drift=True` (the candidate added an undocumented
`now` keyword parameter to `write_provenance`, not declared in
`interface/library.md`) is an isolated generation mistake already
covered by the general, cross-cutting interface-drift rule
(`SPEC_GUIDELINES.md` §6) — no new requirement needed, retrying
without it should simply not recur. `AC-PROV-002` failed test-author's
own static arity check (`fake_signature_mismatch`) against an
unnecessary fake for `cache-manager`'s `get`, a dependency
`provenance-writer`'s own code never calls (`library.md`: "this
component does not call any of those components itself") and that
criterion's own Gherkin never references — plausible one-off model
noise on a component shape (a pure aggregator with an otherwise-inert
`depends_on`) this corpus has not had before. Retrying plain first;
only worth a new requirement if it recurs.
