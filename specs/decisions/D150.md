# D150 — nested per-entry markdown sub-headings repeatedly broke test-authoring's own section parsing

## Context

Across several `review-packet-builder` retries, `AC-PACKET-007`'s and
`AC-PACKET-012`'s own markdown-rendering scenarios have repeatedly
failed with the identical shape: a generated test's own section-
extraction helper (grouping markdown body lines under the nearest
preceding heading) finds an empty body for "## Verification Results"
or "## Capability Scenarios", because the candidate (reasonably)
renders each entry under its *own* nested sub-heading
(`### comp-foo`, `### P-ZERO-EDIT`) — which a generic heading-boundary
parse treats as a new section, silently detaching the entry's real
content from the section a reviewer (or a test) is looking under.
Different rounds wrote different section-parsing helpers, all
equally naive about nesting, so the failure kept recurring rather
than resolving on retry.

## Decision

`R-PACKET-012` amended: "## Verification Results" and "## Capability
Scenarios" MUST render each entry as a flat line directly under that
one heading, never a nested per-entry sub-heading — the same shape
"## Residual Risk"/"## Exemption Changes" already use without
incident. This removes the structural ambiguity outright rather than
hoping a future test-authoring round avoids it. `review-packet-builder`
is retried next.
