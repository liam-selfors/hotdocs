# D63 — Third retry lands, after fixing two real upstream gaps

## Context

The first real `generate()` call for `provenance-checker` surfaced
`D61`'s `component_id`-to-slug gap; the second, with that fixed,
surfaced `D62`'s output-layout gap (and a cache-key process mistake,
fixed in the same commit). Neither candidate was swapped in — each
finding was fixed at its real source (`glossary.md`, `generator.py`'s
own prompt and `GATE_VERSION`), never patched into the candidate
itself, consistent with every self-hosted-generation decision since
`D54`.

## Decision

A third retry, with both upstream fixes in place, produced a correct,
well-reasoned top-level package
(`provenance_checker/{__init__,core,cli}.py`). Notably, its own code
comments cite `glossary.md`'s new "Component id / component slug"
entry and the prior bug by name — direct evidence the `D61` fix
actually reaches a cold-mode bundle and gets read. Verified against
all 8 `AC-PROVCHECK-*` criteria for real (9 tests: `AC-PROVCHECK-005`'s
"trust is true" claim is worth two distinct tests — an explicit `true`
and the documented absent-default — both passed). Swapped in.

One interface deviation judged acceptable without a retry:
`check_provenance` gained an optional `trust_judge_provenance: bool |
None = None` keyword parameter beyond `interface/library.md`'s exact
signature, defaulting to the same environment-resolution behavior the
spec documents when omitted. Every required positional parameter
matches exactly; the addition narrows nothing an existing caller would
rely on.

## Consequences

Ninth real component built. `provenance-checker` has no dependents
among the batches still to come except `merge-orchestrator` (the
last), so this candidate's real `dependency_usage` surface won't be
exercised by another component's generation until then.

Linter: 0 failures once this file exists. Pytest: 118 tests across all
nine real components, 9 of them this component's own.
