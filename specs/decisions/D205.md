# D205 — An initialised project is one that holds `.hotdocs-tool.json`

## Context

`hotdocs init --reconfigure` exits `1` on "a directory that is not an
initialised project" (`interface/cli.md`), but nothing said what made
a directory one. Regenerating `hotdocs-init` for `D203` showed the gap:
the candidate tested for `.hotdocs-tool.json`, and its generated test
built a project out of a bare `specs/` directory, so each was right by
its own reading. Two other criteria were open the same way, on whether
`init` may read an existing `hotdocs.toml` when it skips the provider
step, and whether a `__pycache__` left under the tool root counts as
writing.

## Decision

A directory is an initialised project when `<dir>/.hotdocs-tool.json`
exists: the file `R-INIT-002` writes first and never rewrites. `R-INIT-006`
says so, and `AC-INIT-006` refuses a directory that holds only `specs/`.
`AC-INIT-004` states that skipping the provider step leaves `save_config`
uncalled while `load_config` may still read the file (`R-INIT-003` needs
the provider). `AC-INIT-007`'s "nothing is written" means under `<dir>`;
importing `llm-endpoint` to list providers for the usage message may
leave bytecode under the tool root. `AC-INIT-002` checks `gen` is empty
beside the other entries `R-INIT-001` writes, not that it is alone.

## Consequences

`--reconfigure` on a directory `init` never set up fails the same way
everywhere, whatever else the directory holds.
