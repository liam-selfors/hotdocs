# D366 — A missing corpus graph names the command that builds it

## Context

`hotdocs docs-site build` and `hotdocs track ui build` read
`verification/corpus-graph.json`. In a new project the file does not
exist until `hotdocs corpus-graph build` has run. `docs-site build`
answered with the operating system's "No such file or directory", and
`track ui build` with `usage error: missing <path>` and its usage line.
Neither said what to run.

## Decision

Both name the command. `docs-site build` prints one line,
`error: <path> is missing; run hotdocs corpus-graph build first`, and
returns `1` as before (`R-DOCS-007`). `track ui build` keeps its usage
error and exit code `2`, with the cause `missing <path>; run hotdocs
corpus-graph build first` (`R-UI-009`).

## Consequences

`docs-site-renderer` and `provenance-tracker-ui`, both leaves, are
regenerated. Their interfaces are unchanged, so only the two criteria
that cover these requirements are re-authored. Building the graph on
demand was not chosen: a page built from a graph the developer never
saw written would hide a file that is committed.
