# D181 — Provider choice lives in a committed hotdocs.toml that never holds a secret

## Context

Choosing a provider has to survive between runs and be shared by a
team, so it belongs in a committed file. A committed file is also where
a pasted API key would do the most harm.

## Decision

`hotdocs.toml`'s `[llm]` table holds `provider`, `model`, and optionally
`base_url`, `api_key_env`, and `timeout_seconds`. `api_key_env` is the
*name* of the environment variable holding the key. The file is found
through `VAR-HOTDOCS-CONFIG`, else the current directory. Validation
rejects an unknown entry, an entry named like a secret, a name that is
really some environment variable's value, a timeout under 300 seconds
(`R-ENDPOINT-004`'s floor), and `claude-cli` with a `base_url`.
`save_config` runs the same validation, keeps any other content of an
existing file, and writes through a temporary file so a failure leaves the
old file intact. The OpenAI and Gemini keys are declared as vars beside
Anthropic's, and, like it, use the vendor's own variable name.
