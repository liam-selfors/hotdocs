# D219 — `criterion-compiler`'s emitted literals, covers comment and error file are exact

## Context

Seed 8 of `criterion-compiler` (mutation 1.0) failed three criteria, each
on a form the spec left open. It emitted `'u1'` where a test expected
`"u1"`; nothing said how a literal is written. `R-COMPILE-004` asked for
the `Covers:` id "as metadata" without saying how, and `AC-COMPILE-001`
asked an error to name its file, which `CompileReport` gave no field for.
The hand-written compiler had used `json.dumps` for every scalar, which
also wrote `true` and `null` into Python source, a latent bug.

## Decision

`interface/library.md` defines a literal's emitted form: strings and
numbers as `json.dumps` gives them, booleans and null as `True`, `False`
and `None`, and fixed separators for objects and arrays. `R-COMPILE-004`
names the comment line `# Covers: <id>`. An error entry in `CompileReport`
carries `file`, the acceptance file, and its message starts with the line.

## Consequences

The installed compiler gains correct boolean and null literals.
