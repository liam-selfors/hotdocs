# D53 — Tool isolation is structural, not a system-prompt convention

## Context

Working around `D52`'s discovery (`llm-endpoint`'s own stale 120s bound
blocking its own regeneration under the new 300s floor) meant
dispatching one regeneration call through a temporary orchestration
backend rather than the stale generated code. That attempt surfaced a
materially more serious finding: the response showed the model had used
real tool access to inspect this actual repository's live git state —
noticing an uncommitted spec edit and an untracked decision file — and
answered as a normal assistant exploring a repo, not as an isolated
text-completion engine working from exactly the prompt it was given.

Root cause, confirmed by hand: the temporary backend never forwarded
`system_prompt` to the `claude` invocation at all (an orchestration bug
in that one-off script, not in `generator`'s own code). But the deeper
fact it exposed is real regardless: even when a `system_prompt` *is*
passed correctly, `claude --print` retains its normal tool access
(`Read`, `Bash`, etc.) and `CLAUDE.md`/repo-context auto-discovery by
default. A system prompt instructing the model not to explore is a
request the model is expected to honor, not a structural barrier
preventing it from doing so — exactly the distinction `R-ENDPOINT-005`
already draws for credential handling ("a structural guarantee, not
merely a checked one"), now found missing here too.

## Decision

`R-ENDPOINT-003` now requires every `claude`-CLI dispatch to pass
`--tools ""` (disables all tool access) and `--bare` (skips `CLAUDE.md`
auto-discovery, hooks, memory, and settings files) unconditionally —
confirmed by a direct, minimal test: the same `--system-prompt`
instruction, with these two flags added, produced exactly the
instructed isolated completion, no repo exploration. This is a
structural fix, not a prompt-wording fix — the backend can no longer
retain tool/context access regardless of what the system prompt says or
omits.

Any `generate()` call made before this fix landed in the *generated*
code (not just in this session's own temporary orchestration backend)
carries the same theoretical exposure — in practice, every one of
`D45`'s and `D51`'s real generation calls produced clean, correctly-
scoped output with no visible evidence of repo exploration, but
"no visible evidence" is not the same guarantee this decision now
provides structurally. Flagged, not silently assumed fine in hindsight.

## Consequences

The next regeneration of `llm-endpoint` (and any future regeneration
through the `claude`-CLI backend) carries this fix forward
automatically, once generated code reflecting it replaces the
currently-deployed version — tracked as part of this same decision's
own resulting commit, not deferred.
