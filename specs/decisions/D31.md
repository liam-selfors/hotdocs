# D31 — Retire automatic best-of-k retry; human-gated re-generation via merge re-run

## Context

`D17` explicitly considered and rejected dropping best-of-k retry
entirely, because a failure is frequently a generation miss on an
otherwise-adequate spec, and losing the recovery path would push real
spec-authoring overhead onto every transient miss. This decision
reopens that question deliberately, with a different answer than the
one `D17` rejected: not "no retry," but "retry stays free, just no
longer automatic or silent."

## Decision

`merge-orchestrator` calls `generator` **exactly once** per cache-miss,
non-sealed component per merge attempt. If that attempt doesn't produce
a passing candidate — `model_call_error` or a failing
`VerificationReport` — the component is blocked immediately
(`R-MERGE-006`). Nothing calls `generator` again within the same merge;
no seed variation, no `retry_feedback`, no best-of-k loop at all.

The recovery path is **not removed**, it moves outside this component
entirely: re-running the merge (`R-MERGE-018`, unaffected) is still free
for every component that already passed. The difference from before is
that a failure now forces a stop, giving a human a deliberate pause to
look at *why* the one attempt failed — via `D32`'s per-attempt record —
before deciding whether to just re-run unchanged (treating it as a
transient miss) or fix the spec first (treating it as a genuine gap
the failure exposed). `D17`'s concern about pushing overhead onto every
transient miss is answered, not ignored: a transient miss still costs
only one extra conscious re-run, not a mandatory spec investigation.

## Consequences

Retired entirely: `R-MERGE-016` (`k`'s value), `R-GEN-010`
(`retry_feedback`), the `best_of_k` frontmatter field, and
`seed`/`sample_index`/`retry_feedback` from `GenerationResult`/
`MergeResult`/the provenance schema. `R-VERIFY-011`
(`requirement_results`) is kept — it was never only about feeding the
retry loop; it stands on its own as a requirement-level diagnostic
summary, now read by a human instead of fed to `generator`.

`R-LICENSE-007`/`R-SECRET-004`'s "never erase a flagged result"
guarantee used to hold via multiple best-of-k samples sharing one
provenance manifest; a blocked merge commits no provenance at all
(`R-MERGE-012`), so that guarantee now depends on `D32`'s per-attempt
persistence layer existing — this decision and `D32` are tightly
coupled, not independently optional.

See `specs/components/merge-orchestrator/requirements/R-MERGE-005.md`
and `specs/components/generator/requirements/R-GEN-011.md` for the
current, authoritative rules.
