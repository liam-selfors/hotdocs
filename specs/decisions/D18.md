# D18 — `criterion-compiler`: single fixed emit target for v1, formalized as a two-phase split

## Context

Resolved the open question of which test framework compiled acceptance
criteria emit scaffolding for.

## Decision

A single fixed target (`pytest`) for v1 — no multi-target machinery
designed in now, consistent with this project's anti-premature-abstraction
stance. What made this safe to decide quickly: the step-phrase grammar
(`specs/architecture/step-phrase-grammar.md`) was already written in
target-independent terms before this question was raised — each
template's "compiles to" column describes a bound fact, never literal
pytest syntax.

`R-COMPILE-011` makes the separation formal: parse+bind (grammar
matching, `interface/` resolution — target-independent) vs. emit
(literal source text for one `--target`). Any `--target` other than
`pytest` MUST fail as a specific usage error (exit `2`), never a silent
fallback.

## Consequences

A future second target is an additive emitter function, not a grammar
rework or a change to `R-COMPILE-001`–`010`.

See `specs/components/criterion-compiler/requirements/R-COMPILE-011.md`
and `interface/cli.md` for the current, authoritative rule.
