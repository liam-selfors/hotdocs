# D319 — A test that could not be written is not a failing requirement

## Context

When the model call authoring a `generated-test` criterion's test
dropped, the criterion was recorded `fail` and the attempt ended
`verification_failed`, exactly like a defect in the generated code.
`QUICKSTART.md` sends a person to fix the spec on that outcome, and
`hotdocs track feedback` offered the covered requirement as retry
feedback (issue #3).

## Decision

`verifier-orchestrator` retries a `test_author` call once when it
returns a `network`, `timeout` or `rate_limit` error. A criterion whose
test still cannot be authored is `fail` with `failure_origin` `"test"`
and the message `test authoring failed: <category>: <message>`; every
other failure has `failure_origin` `"implementation"`, the field this
round's agentic branch also uses. `component-gate-runner` blocks with
`"test_authoring_failed"`, exiting `1`, when every failed criterion has
origin `"test"`, and `last_requirement_failures` leaves such
requirements out of its feedback.

## Consequences

A dropped call no longer reads as a spec defect, and a re-run is the
advertised remedy. Readiness is unchanged: such a candidate still never
lands.
