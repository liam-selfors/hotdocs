# D381 — Components read the spec rules they check from small rules-only documents

## Context

`SPEC_GUIDELINES.md`, about 6,700 words, was named on the `Implements:`
line of five components: `spec-linter` (`D210`), `size-checker`,
`citation-checker`, `impact-analyzer` (`D265`) and
`verifier-orchestrator` (`D282`). `R-ASSEMBLE-014` appends a named
document whole, so each of their generator bundles and all 97 of their
criterion bundles carried it: about 680,000 words a regeneration pass.
The spec review of 2026-11-26 found that each needs between about 330
and 2,250 of those words, that 35% of the guide is explanation and
history, and that the reasons `D265` and `D282` added it no longer hold:
`impact-analyzer`'s `testing.md` and `verifier-fixtures.md` now state
what their tests need. Every edit to the guide, history included, also
regenerated 21 components.

## Decision

The guide's machine-checked rules move, without their explanations,
into five documents under `specs/architecture/`: `spec-frontmatter.md`,
`spec-layout.md`, `acceptance-criteria.md`, `size-caps.md` (with
`D380`'s caps) and `glossary-and-citations.md`. Each component names
only those it checks:

| Component | Names |
| --- | --- |
| `spec-linter` | all but `size-caps.md` |
| `verifier-orchestrator` | `acceptance-criteria.md` |
| `size-checker` | `size-caps.md` |
| `citation-checker` | `glossary-and-citations.md` |
| `impact-analyzer` | none |

`SPEC_GUIDELINES.md` stays the human rulebook, pointing to each moved
rule's new home, so no rule is stated twice.

## Consequences

Those bundles drop about 4,500 to 6,700 words each. No component names
`SPEC_GUIDELINES.md`, so editing it forces no regeneration; editing one
of the five documents regenerates only the components naming it.

Regenerated: the five components and the components their code hashes
reach.
