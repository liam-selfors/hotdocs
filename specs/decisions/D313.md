# D313 — The provenance key names the generator's version

## Context

A component's provenance hit when its spec bundle hash and the gate
versions matched its manifest. The generator's own version and prompt
version were not in the key, so a component generated by an old
generator, with an old prompt, still counted as ready after the
generator changed: the strongest claim the manifest makes, that this
code is what the current pipeline produces from this spec, went
unchecked for the one stage that writes the code.

## Decision

`ProvenanceKey.gate_versions` gains `generator`, the generator's
`GATE_VERSION` and `PROMPT_VERSION` joined by `+`. Both modes render the
spec bundle through the generator, so its version covers both; the
agentic prompt version is recorded in the manifest's `generation`
block but is not in the key.

## Consequences

Every existing manifest misses once, deliberately: the round ends with a
regeneration of the whole corpus, after which every hit means the
current generator produced the code.
