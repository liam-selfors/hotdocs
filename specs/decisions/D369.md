# D369 — An undeclared asset path is a test bug the probe catches

## Context

Issue #21. A test author wrote one criterion's test for a component's
declared JavaScript asset `static/viewer.js` with the repository path
`gen/erd-viewer-render/static/viewer.js`. The verifier's `asset_runner`
fixture knows only declared paths and raised a bare `KeyError` during
setup of every test in the file. `test-probe`'s stub fixture accepts any
path (`R-PROBE-007`), so the test passed its probe, and the verifier
blames a test that passes its probe on the implementation
(`R-VERIFY-019`). The criterion failed with `failure_origin`
`"implementation"`, the faulty test was committed and reused on every
later attempt, and the mutation score left the criterion out.

## Decision

`test-probe`'s `probe` takes `assets`, the paths the component declares,
or `None` when the caller does not know them. Its stub `asset_runner`
raises `HotdocsProbeUndeclaredAsset`, a `KeyError`, for a path that is
not declared: one not in `assets`, or with `assets` `None`, a path that
begins with `gen/` or `/` or has a `..` part. A test whose failure names
that exception is a `test_bug` (`R-PROBE-005`, `R-PROBE-007`). The
exception is a `KeyError` so that a test asserting an undeclared path
raises `KeyError` still passes, as the real fixture behaves.

`verifier-orchestrator` passes `assets` (`R-VERIFY-019`), so a cached
test with an undeclared path fails its probe, is authored again once,
and if still faulty fails with `failure_origin` `"test"`. `test-author`
calls `probe` without `assets`; its repair loop sees the finding while
the test is written. The real fixture's `KeyError` names the path and
the declared ones (`specs/architecture/verifier-fixtures.md`).

## Consequences

`test-probe` and its twelve dependents are regenerated. Accepting
`gen/<slug>/<path>` as the declared asset is not done: it changes
`specs/architecture/asset-kinds.md`, which twelve components implement,
and is recorded in `notes/backlog.md` for the next full wave.
