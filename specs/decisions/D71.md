# D71 — First real call lands on the first try; a real .gitignore gap found

## Context

`docs-site-renderer` is a genuinely different kind of deliverable from
every component built before it — real static HTML/CSS/JS output, not
Python logic consumed programmatically. The first real `generate()`
call produced a correct, well-structured candidate: `render_docs_site`
never reads `verification/corpus-graph.json` itself (a separate
`load_corpus_graph`, wired together only in the CLI layer, does that),
a clean reading of `R-DOCS-004`'s "pure function of the graph"
requirement; correct `owners`-list exclusion (`R-DOCS-002`); a working
client-side search.

Building this component's own test suite found one real gap, not in
the generated code: `R-DOCS-005` requires the rendered output never be
committed, and the CLI's own default output path is `dist/docs-site/`
— but `.gitignore` had no `/dist/` entry at all, anywhere in this
repo, checked directly. A careless `git add -A` after a local render
could have committed build output.

## Decision

Fixed `.gitignore` directly (added `/dist/`) — the generated code
already does the right thing; this gap was repository configuration,
not implementation. Verified against all 6 `AC-DOCS-*` criteria for
real, including a real `git check-ignore` call confirming the default
output path is now actually excluded. Swapped in.

## Consequences

Thirteenth real component built. Batch 1 has one component left:
`test-author`.

Linter: 0 failures once this file exists. Pytest: 158 tests across all
thirteen real components, 6 of them this component's own.
