# D102 — test-author's prompt states the required component.md frontmatter schema for any synthetic fixture it constructs

## Context

The retried `spec-bundle-assembler` cold-generation (`D101`'s fix) passed 7 of 13 criteria but failed 6 more, all with the same underlying cause: `assemble`/`assemble_criterion` both call `_require_lint_clean`, so any test exercising either function against a synthetic, test-constructed `specs/` tree needs that tree to actually lint clean — and six of the thirteen authored tests built a synthetic `component.md` missing required frontmatter (`title`, `owners`, sometimes `realizes`), which doesn't fail as a clean lint finding but as an unhandled `BinderException` (`graph-query-engine`'s `nodes` view hardcodes a `title` column that a single-document corpus missing that key never produces). The seven that passed either reused a copy of the real, already-lint-clean corpus, or happened to build a fixture with the right fields by chance.

`test-author` had no stated schema to follow — `SPEC_GUIDELINES.md` §2's frontmatter table (`id`/`title`/`status`/`owners` always required, `realizes` required unless `sealed: true`) is a corpus-wide authoring rule, not something test-author's own `CriterionBundle` carries, and nothing in its prompt ever pointed there or restated it. This is a distinct, narrower problem from `D96`/`D97`'s dependency-loading convention and from `D100`'s dependency-signature gap — those were both about *dependencies*; this is about the *shape of a spec file itself* whenever a test has to fabricate one.

(A latent robustness gap in `graph-query-engine`'s `nodes` view — crashing instead of reporting a graceful lint finding when a corpus's only component lacks `title` — is a real, pre-existing issue surfaced along the way, but out of scope here: real production corpora always have `title`, so nothing in actual use is affected, and fixing it would mean another cold-regeneration of a different foundational, hand-authored component. Noted, not pursued today.)

## Decision

New requirement `R-AUTHOR-012`: whenever the prompt's own target-component or dependency context implies a test will need to construct a synthetic `specs/components/<slug>/component.md` (or any other spec file) from scratch, the prompt MUST state the frontmatter fields `SPEC_GUIDELINES.md` requires unconditionally (`id`, `title`, `status`, `owners`) and the one condition most likely to apply (`realizes` required unless `sealed: true`), as a fixed, always-included instruction — the same "cross-cutting, not bundle-derived" category `R-GEN-015`/`R-AUTHOR-010` already use. `test-author` is cold-regenerated against this spec; `spec-bundle-assembler`'s six still-failing criteria are re-authored and re-verified once this fix is in place, with `--retry-feedback` citing their covering requirements.
