# D384 — The test author's prompt includes the criterion's test spec

## Context

`D341` added `CriterionBundle.testing`: a component's `testing.md`, its
`Uses:` documents and each asset kind's test-author guidance, the one
place fixture mechanics live. `test-author` hashes it into the criterion
header but never puts it in the prompt: `R-AUTHOR-001` lists what a test
is written from and was not amended, so the generated code left it out.
No test author has seen a test spec since. The `D373`–`D383` wave
showed it: spec-linter's and spec-bundle-assembler's tests rebuilt
their fixtures from guesses in every seed, dropping the requirement
heading `R-LINT-007` checks, whatever `testing.md` said.

## Decision

`R-AUTHOR-031`: the prompt includes the bundle's `testing` text under
`## Test spec`, after the dependency interfaces, whenever it is not
empty. `R-AUTHOR-001` names it among the inputs.

## Consequences

Fixture recipes, `Uses:` documents and asset-kind and test-driver
guidance reach the tests they were written for. `test-author` lands
early in the wave that carries this, before the components whose tests
need their test specs. No criterion header changes, since `testing`
was already hashed.

Regenerated: `test-author` and the components its code hash reaches.
