# D325 — The generator's prompt layout is stated exactly

## Context

Regenerating `generator` for the demo-build fixes failed on every seed,
each on a different criterion, with no defect in the candidates:

- `R-GEN-001` listed six bundle fields as the prompt's whole input, so
  tests planted a marker in `dependency_context` and failed the
  candidate for sending it, though the generator always has.
- The prompt's section headings (`## HINT_CODE`, `## RETRY_FEEDBACK`)
  were stated nowhere, yet the hand suite pins them.
- Following the general fixture default of `sealed: true`, a test built
  a sealed component, which `R-GEN-009` refuses before any model call,
  and then found its mock model never called.

## Decision

`specs/architecture/generator-prompt.md`, named on `generator`'s
`Implements:` line, gives the prompt's sections exactly (headings,
order, which are conditional, how a mapping renders), a section reader
for tests, and that a component a test generates is unsealed.
`R-GEN-001` lists every field the prompt holds, `dependency_context`
and the non-empty `dependency_usage` entries included.

## Consequences

The prompt is unchanged, so `PROMPT_VERSION` stays. A criterion checks
a section by its heading, and a regeneration cannot pass by naming a
section differently.
