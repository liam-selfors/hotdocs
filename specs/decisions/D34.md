# D34 — A dedicated `Rationale` section so `Purpose` stays dependent-safe, enforced by `R-LINT-024`

## Context

Arose from discussing `notes/backlog.md`'s `context` property idea — a
compiled, outward-facing description dependents could reference instead
of raw `interface/` files. The one open design question: a view can
mechanically extract `Purpose`, but `Purpose` sections across this
corpus routinely mix "what this is" with "why it was decided this
way" (decision citations, historical justification) — exactly the
"internal rationale" `R-ASSEMBLE-002` already says a dependent shouldn't
see. Two options were on the table: extract only a clean first
paragraph (implicit convention), or require one via a lint rule. The
decision made here improves on both: explicit structural separation.

## Decision

`component.md` gains an optional `Rationale` section
(`SPEC_GUIDELINES.md` §3.4), placed right after `Purpose`. `Purpose`
MUST now be dependent-safe: what a unit does and why it exists, never
how that design was arrived at. Decision citations, historical
justification, and cross-references to the discussion that produced
the current design move to `Rationale` instead — optional, since a
component whose `Purpose` genuinely needs no supporting history can
omit it.

Enforced mechanically, not left as convention: `R-LINT-024` fails any
component whose `Purpose` section contains a decision citation
(`D<N>`, bare or backtick-wrapped) — the same "codify the lesson as a
real check" pattern `R-LINT-022`/`D28` already established.

All 13 components whose `Purpose` mixed what/why with decision history
were retrofitted: `cache-manager`, `corpus-graph-builder`,
`criterion-compiler`, `docs-site-renderer`, `generator`,
`golden-scenario-verifier`, `license-scanner`, `llm-endpoint`,
`merge-orchestrator`, `merge-tracker-ui`, `secret-scanner`,
`spec-completeness-assistant`, `test-author`.

## Consequences

`Purpose` is now guaranteed clean by construction and lint-checked
going forward — the eventual `context` view (still on the backlog,
`notes/backlog.md`) can extract it verbatim, with no fragile
"first-paragraph" regex needed. The remaining open questions for that
idea (new view vs. `spec-bundle-assembler` querying `component_docs`
directly; the narrow exception `R-ASSEMBLE-002` would need) are
unaffected by this decision and still open.

See `SPEC_GUIDELINES.md` §3.4 and `specs/components/spec-linter/
requirements/R-LINT-024.md` for the current, authoritative rules.
