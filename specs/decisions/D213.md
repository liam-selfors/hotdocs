# D213 — `spec-bundle-assembler` falls back to the tool root for its own dependencies

## Context

`D199` keeps the tool's components out of a project: a component that
loads another falls back to the tool's own `gen/` when the project has
none. The rule was written into each consumer's spec, but never into
`spec-bundle-assembler`'s; the hand-written and first generated versions
fell back anyway. The version regenerated under `D210` (seed 53) looked
only under `repo_root`, so the next bootstrap run, for `cache-manager`,
crashed with "spec-linter dependency code not found", and in a user's
project every `hotdocs generate` would have failed the same way.

## Decision

`R-ASSEMBLE-015` states the fallback for `spec-linter` and
`graph-query-engine`, and `AC-ASSEMBLE-017` checks a corpus with no
`gen/` at all. `tools/bootstrap_component.py` now copies the
dependencies of the machinery it always copies, so an in-sandbox copy of
the assembler finds them under its own tool root, the sandbox.

## Consequences

The assembler is regenerated again; the seed-53 version stays in place
only until then, and is not pushed.
