# D88 — merge-tracker becomes provenance-tracker — a live provenance query, not a per-merge log, with hotdocs verify as its CLI

## Context

With `merge-orchestrator` gone (`D87`), nothing ever calls `write_tracking_record` again — `TrackingRecord` existed specifically to give a developer visibility into *merge attempts*, a concept that no longer exists as a distinct automated action. Keeping it would mean maintaining a write path with no real caller. What a developer actually needs now is different and more useful: a live answer to "which components and capabilities currently have valid provenance, and is a merge ready" — not a historical log of past attempts.

## Decision

Renamed `provenance-tracker` (`provenance-tracker-ui` for its renderer). `write_tracking_record`/`TrackingRecord`, its `.hotdocs/tracking/` store, and `hotdocs track query` are removed entirely (`R-TRACK-001`/`002`/`003`/`005`/`006` and their acceptance criteria). `write_attempt_record`/`AttemptRecord` and `last_requirement_failures` are unchanged in role (`R-TRACK-004`/`007`/`008`) — a developer's `hotdocs generate` attempt history and retry-feedback convenience are still genuinely useful and still get surfaced, now in `provenance-tracker-ui`.

New: `provenance-tracker` gains a live query over current provenance state — for a given scope (a blast radius via `impact-analyzer`, or the whole corpus), reads `provenance-checker`'s result for every component in scope and `capability-scenario-verifier`'s own provenance (`D89`) for every capability whose `realizes`-set intersects it, and reports one pass/fail verdict plus the per-item detail behind it. This is exposed as `hotdocs verify [--changed=<spec-id>...] [--repo-root=<dir>] [--format=json|text]` — omitting `--changed` checks the whole corpus. A pass means every checked item has current, passing provenance; nothing about an actual merge depends on this command having been run, same posture `R-TRACK-005` always held for the old `TrackingRecord` write — it answers a question, it does not gate anything.

`provenance-tracker-ui` renders this as an interactive graph (`corpus-graph-builder`'s existing graph as the base layout), with navigation/filtering between a blast-radius view and a whole-corpus view, and per-node drill-down into `AttemptRecord` history and `last_requirement_failures` for anything currently failing or missing provenance.
