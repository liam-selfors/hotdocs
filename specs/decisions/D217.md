# D217 — `criterion-compiler`'s spec says how it reads an interface and what substitution emits

## Context

Seed 5 of `criterion-compiler` (mutation 1.0) failed two criteria. A
generated test declared a function as `def create_widget(...)` in its
fixture's `library.md`, which no implementation was told how to read:
the hand-written compiler matched `name(params)` lines in plain fenced
blocks, and data types by a ``# `Type` `` heading and a JSON example,
but the spec never said so. And a second candidate in a row emitted a
bound fixture's name where `R-COMPILE-007` asks for its literal, since
"resolves it at compile time" did not say what the emitted code holds.

## Decision

`interface/library.md` states how `compile` reads an `InterfaceSurface`,
exactly as the hand-written compiler did. `R-COMPILE-007` says the
emitted code holds the literal itself, with an example. `component.md`'s
change log is shortened to one line per decision to make room.

`AC-COMPILE-007`, rewritten for `D214`, said the payload appears exactly
once; with substitution it also appears in the call that uses it, as
seed 6 showed. The criterion now asks that every occurrence be inside a
string literal.

## Consequences

`criterion-compiler` is regenerated against the clarified spec.
