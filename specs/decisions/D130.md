# D130 — provenance-writer's CLI entry point had no requirement or acceptance criterion at all

Third real cold-generation attempt (after `D128`'s `R-PROV-014` fix
landed clean: 14 of 14 criteria passed behaviorally, `interface_drift`
back to `False`). `verify()` still failed: `mutation_score=0.57`
against the `0.8` bar. Diagnosed directly, not assumed: ran the real
mutation harness's own mutant generator against the candidate and
found 14 mutable nodes, 8 of which only exist inside `main()`/argument
parsing (lines 104–123) or the `if __name__ == "__main__":` guard
(line 151) — code no acceptance criterion's test ever calls. Every
one of the fourteen criteria so far exercises `write_provenance`/
`build_manifest` directly as a library call; none goes through
`main()`.

Root cause: `interface/cli.md` documents a real CLI
(`hotdocs provenance write <component-id> [--repo-root=<dir>]`,
exit codes `0`/`1`/`2`) that no `requirements/` file or
`acceptance/` criterion has ever covered — a gap in the original
spec, not something any candidate did wrong. New `R-PROV-015`/
`AC-PROV-015` close it, stating `main`'s exact behavior per
`cli.md` and testing every exit path. Retrying generation next.

This is the second real round in a row for `provenance-writer` where
mutation testing (not a failing behavioral assertion) caught the real
gap (`D129`'s window-truncation fix was found by a behavioral
assertion; this one only by mutation score) — evidence the `D124`
union-score fix is doing real, continued work: a documented interface
surface with zero behavioral coverage shows up as a depressed score
precisely because it genuinely isn't tested, not as an averaging
artifact.
