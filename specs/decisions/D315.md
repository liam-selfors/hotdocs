# D315 — An opt-in live-provider suite that never feeds a gate

## Context

Every criterion runs against a mock model or a replaced
`urllib.request.urlopen`, so nothing in verification shows that a real
provider still answers in the shape the wire formats assume, or that a
real model can drive the tool loop and the agentic sandbox end to end.
The `claude-cli` isolation flags in particular depend on a command whose
behavior changes between releases.

## Decision

Hand suites gain tests that call real providers, each skipped unless
`HOTDOCS_LIVE=1` is set and its provider is available: a one-word reply
and a long reply through `llm-endpoint`; a tool loop that writes one
file through `llm-tool-endpoint`; and an agentic generation of the
slugify example. They are run by hand (`HOTDOCS_LIVE=1 pytest
verification/<component>/test_live_*.py`), cost real tokens, and never
run in a bootstrap, a gate, or `hotdocs verify`; their result is
evidence for a person, not provenance. This round runs them only with
`claude-cli`.

## Consequences

A provider whose wire format drifts is found by a person running the
suite, not by a landing that fails for reasons the spec cannot explain.
