# D192 — A real detection source for license-scanner

## Context

`D193` stops the license gate from passing a scan that checked nothing.
That leaves it with no signal at all until a reference corpus exists, and
`license-scanner`'s design needs someone to curate one: precomputed
9-token SHA-256 window hashes of known-licensed code, from "a maintained,
continuously-updated external reference set" (`R-LICENSE-001`) that nobody
has supplied. `D168` took the opposite route for secrets, adopting a
maintained library. This record asks whether the same is possible here.

What the product promises (`P-COMPLIANCE-GATE`): *generated code that
matches a known-licensed-code fingerprint* is caught. That is copied-code
detection, not a dependency inventory and not a header check.

## What was tested

Everything below was installed in scratch environments, never the
project's, and run unless marked **not run**.

| Tool | Detects | Result here |
| --- | --- | --- |
| **ScanCode Toolkit** 32.5.0 (Apache-2.0, plus CC-BY-4.0 data) | License text, notices, SPDX tags, copyrights in files; offline | Installs (82 packages, 680–714 MB). **Did not run.** `pluggy` 1.7.0 breaks its plugin loading (`ValueError: did not find any 'pre_scan' hooks`; its metadata requires only `pluggy>=1.0.0`; pinning `pluggy<1.6` fixed that on Python 3.12). It then needs a system `libmagic`, which has no PyPI build for macOS arm64 (`typecode-libmagic` installs but provides none; `python-magic-bin` has no arm64 wheel) and macOS embeds it inside `/usr/bin/file` with no loadable library. Even `licensedcode`, the matcher, imports the file-typing layer at load. So on this machine it needs `brew install libmagic`, which I did not do. Detection quality is **not verified**. |
| **SCANOSS** `scanoss-py` 1.54.3 (MIT) | Copied code, by fingerprinting source into winnowing hashes and matching them against a server's index of open-source projects | Fingerprinting **works offline**: 0.6 s for `gen/license-scanner`, output is per-line hash lists, no source. Matching goes to `https://api.osskb.org` by default; `scan --apiurl` accepts another server, `--obfuscate` exists. **I did not call any server, so nothing was sent and match quality, rate limits and terms are not verified.** Its hash format is unrelated to this repo's k-gram hashes, so the two corpora cannot be shared. |
| **pip-licenses** 5.5.5 (MIT) | The declared license of each installed Python package | Works offline. On the project's venv (read-only): 14 packages, one weak-copyleft (`certifi`, MPL-2.0). The same license appears under several spellings (`MIT License`, `MIT`, `Apache Software License`, `BSD-3-Clause`), so a normalization table is required. |
| **reuse** 6.3.0 (Apache-2.0 AND GPL-3.0-or-later components) | Whether files declare licensing, per the REUSE standard | Runs. Flags every file lacking SPDX headers: a declaration lint, not copied-code detection, and it would flag nearly every file in a project that does not use SPDX tags. Its GPL components matter if embedded as a library. |
| **licensecheck** 2026.0.8 (MIT) | Dependency-license compatibility | Crashed with a traceback when run in a directory with no project metadata. Overlaps `pip-licenses`. |

**Not tested:** `licensee`, FOSSology, askalono (not installed, not
Python), and commercial services.

## Findings that shape the choice

- Only a corpus or a service can find code copied **without** its notice,
  which is how a model reproduces licensed code. ScanCode finds declared
  licenses; it would catch a pasted GPL header, not a silently copied
  function.
- Of the real options for copied code, only SCANOSS is a maintained
  existing tool. It needs a network call and its answers change as its
  index grows, so a result is neither deterministic nor safe to reuse by
  `gate_version` alone (`constraints.md` requires determinism).
- The cheap, verified, offline signal is the dependency inventory, a real
  and common licensing risk, though not the one the product spec names.

## Recommendation

1. **Done (`D193`):** the gate says `not evaluated` instead of passing.
2. **Next, small to medium:** add an offline dependency-license check using
   `pip-licenses`, with an SPDX normalization table and the same three risk
   tiers (strong copyleft high, weak copyleft such as MPL medium, permissive
   low). A package with unknown license is reported unknown, never as clean.
   It needs a new requirement and result field and one regeneration.
3. **Then, medium to large, and a user decision:** SCANOSS as an **opt-in**
   second provider for copied code, local fingerprinting plus hashes only to
   a configured `--apiurl`. It needs: a rule that a service that does not
   answer is `evaluated: false` with its own reason; recording the service
   response in provenance instead of relying on a cache key; a privacy
   review of sending hashes of a project's code; and test fakes that patch
   `subprocess`/`urlopen`.
4. **Not recommended now:** `reuse` and `licensecheck` for the reasons
   above. **Defer** ScanCode until it can be run and judged: it would need
   `libmagic` installed through the system package manager and a `pluggy`
   pin, and a Linux CI runner may suit it better than a developer Mac.

## Decisions for the user

- Is a network call acceptable in the license gate, as an opt-in?
- Do dependency licenses count as "license risk" for the product, or only
  copied code?
