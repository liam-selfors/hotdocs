# D119 — verifier-orchestrator must use spec-bundle-assembler's own assemble_criterion, not a second, independently-built CriterionBundle

## Context

Chasing `provenance-tracker`'s own remaining real test-authoring failures (recurring wrong-arity and wrong-shape fakes, even after `R-AUTHOR-011`/`R-AUTHOR-020`'s fixes) led to checking what `dependency_interfaces` `test-author` actually receives during a real `bootstrap_component.py` run. It is always empty: `verifier_orchestrator.verify()` builds the bundle passed to `test_author` via its own `_build_criterion_bundle()`, whose `CriterionBundle` dataclass has never had a `dependency_interfaces` field at all — a second, independent producer alongside `spec_bundle_assembler.assemble_criterion()`, tracked as a deferred, known limitation twice already (`D106`, `D112`).

This is not actually a gap in the spec — `R-VERIFY-009` already states `test_author` must be dispatched "passing exactly the `CriterionBundle` `spec-bundle-assembler` produces for that criterion." The real, already-built candidate simply never implemented this; it built its own narrower, divergent `CriterionBundle` type instead, and `depends_on` was never amended to list `comp-spec-bundle-assembler` at all despite the requirement needing it. Every dependency-shape-guessing failure test-authoring hit for any real component bootstrapped this session — not just `provenance-tracker` — traces back to this: `R-AUTHOR-011`/`R-AUTHOR-020`'s investment was applied to a prompt that never carried real dependency information for this call path, the whole time.

**Noted, not acted on**: every `AC-VERIFY-*` file declares `Kind: generated-test`, directly contradicting `component.md`'s own "Acceptance criteria" section, which claims all thirteen are `kind: compiled`. A real, pre-existing inconsistency, out of scope for this fix — not required to resolve it, since this fix is validated against the existing hand-maintained suite directly (the same `D58`-precedent exemption `test-author` itself uses, for the same reason: this component implements `verify()` itself, so using the full `bootstrap_component.py` self-verification cycle on it is circular).

## Decision

`verifier-orchestrator`'s `depends_on` gains `comp-spec-bundle-assembler`. `R-VERIFY-009` is amended to state explicitly that this component MUST NOT build its own, independent `CriterionBundle` — it MUST call `spec_bundle_assembler.assemble_criterion(component_id, criterion_id, repo_root)` and pass that bundle to `test_author` unchanged. `verifier-orchestrator` is cold-regenerated directly (via `generator.generate()`, not the full self-verifying bootstrap cycle, for the reason above) and validated against its own hand-maintained suite, extended with a new test proving `dependency_interfaces` now carries a real dependency's real, documented interface text.
