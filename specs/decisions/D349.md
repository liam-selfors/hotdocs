# D349 — Re-ratify the secret allowlist after the asset-kinds regeneration wave

## Context

The regeneration wave for `D332`–`D348` replaced many generated tests.
Two new ones hold planted fixtures the allowlist sealed by `D330` did not
cover: `verification/secret-scanner/generated-test/test_ac_secret_015.py`
(a fake AWS access key) and
`verification/provenance-writer/generated-test/test_ac_prov_020.py` (a
16-character hex run repeated four times). Because re-recording scans the
whole repo, every manifest recorded in the wave recorded `flagged`.
Twenty-one entries matched files or secrets that no longer exist.

## Decision

The allowlist is the scanner's own `propose()` output, checked by hand:
the existing entries plus those two, both `planted-fixture`, with the 21
entries that match nothing removed. This record carries its hash.

## Consequences

A full scan is clean again. Every component whose manifest recorded the
flagged scan is re-recorded so its manifest carries the clean scan.
