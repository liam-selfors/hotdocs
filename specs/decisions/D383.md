# D383 — The verifier is split into run environment, test supply and mutation scoring

## Context

`verifier-orchestrator` carried four jobs: dispatching criteria and
deciding the verdict, provisioning asset environments and the
`asset_runner` plugin (`D343`, `D344`), supplying each generated test
(the criterion header, re-authoring, probing; `D307`, `D319`, `D341`),
and mutation scoring (`D124`, `D159`, `D324`). It sat at 3,997 of 4,000
counted words, with 33 criteria, and its generator read about 14,900
words, mostly the eight documents its `Implements:` line appended. Test
drivers (`D373`) would add a fifth job to the same component. The spec
review of 2026-11-26 found the three seams clean: each part's rules
already lived in their own architecture document.

## Decision

Three new components, each with a narrow interface:

- `run-environment`: `prepare(component_id, repo_root)` and
  `prepare_capability(capability_id, repo_root)` provision the asset
  kinds and test drivers, report their provenance entries, and write the
  pytest plugin (`specs/architecture/run-environment.md`).
- `test-supply`: `supply(...)` returns one criterion's test, committed or
  authored afresh and probed, or why none is sound; `discard(...)`
  deletes a committed test shown faulty (`specs/architecture/test-reuse.md`).
- `mutation-scorer`: `score(...)` runs `specs/architecture/mutation-runs.md`
  over the given tests and reports faulty tests when the baseline fails.

`verifier-orchestrator` keeps dispatch, the criterion runs, the drift
check, the bar and the report, calling the three. The process-tree
timeout rule moves to `run-environment.md`, the faulty-test rule to
`mutation-runs.md`. The verifier's `GATE_VERSION` becomes
`verifier-orchestrator@4.0.0`, and a change to the mutation sites or
runs still bumps it.

The interface drift check stays in the verifier: it compares the
component's own interface with its code, while `surface-checker` checks
the code's use of its dependencies, so the review's suggested merge
would join two different checks.

## Consequences

The verifier's generator bundle drops from about 12,000 words (after
`D381`) to about half that, and a change to one part regenerates that
part and, through `D379`, re-verifies the rest. Test drivers land in
`run-environment`, so `capability-scenario-verifier` gets them by
calling the same `prepare_capability`.

Ten verifier criteria move, rewritten against the new interfaces:
mutation (`AC-VERIFY-015`, `-016`, `-020`, `-022`, `-025`, `-026`,
`-032`) to `mutation-scorer`, test supply (`-009`, `-023`, `-024`) to
`test-supply`. The verifier keeps integration criteria for each part.

Regenerated: the three new components, `verifier-orchestrator`,
`capability-scenario-verifier`, and the components their code hashes
reach.
