# D390 — Graph edges coloured by tokens; browser criteria leave screenshots for the review packet

## Context

`D386` left two things open. The docs site's DAG took its edge colours
from its script (`layoutGraph` returned hex values), outside the
stylesheet and its contrast rules. And a reviewer of a regeneration saw
no page at all: the browser driver's screenshots stayed in each test's
temporary directory, and the review packet listed none.

## Decision

- **Edges.** `layoutGraph` returns a class per edge kind
  (`edge-depends-on`, `edge-realizes`, `edge-other`); `init` sets it on
  each line and no `stroke`. `comp-ui-style` gains the three
  `--color-edge-` tokens, light and dark, each at least 3 against the
  background, and one rule per class (`visual-style.md`, "Edges").
- **Screenshots.**
  - The browser session's `close()` saves a full-page PNG of every page
    still open, `final-<n>.png` (`test-driver-browser.md`).
  - `run-environment` copies them, for a criterion run of the code
    itself and never a mutation run, to
    `.hotdocs/screenshots/<slug>/<test file stem>/`, replacing that
    test's folder each time (`R-RUNENV-007`). `prepare` writes nothing
    there: `provenance-checker` calls it to read versions, and a clearing
    `prepare` wiped the screenshots at every provenance check. The rule lives in that component's own
    requirements, not in `run-environment.md`, so its readers do not
    regenerate.
  - The review packet lists them per regenerated component in a
    `## Screenshots` section (`R-PACKET-014`). They are local,
    git-ignored files: the packet says to attach them to a PR.

## Consequences

Regenerated: `driver-browser`, `run-environment`, `ui-style`,
`docs-site-renderer`, `provenance-tracker-ui` (it implements
`visual-style.md`) and `review-packet-builder`; the rest re-verify
(`D379`). `tools/bootstrap_component.py` copies a landing candidate's
screenshots into the real repo, since it verifies in a sandbox.
