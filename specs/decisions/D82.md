# D82 — llm-endpoint falls back to --safe-mode, never --bare, when no API key is configured

## Context

`D35` mandates `--tools ""` and `--bare` on every `claude`-CLI dispatch, found necessary by a real cold-mode purity violation: without them, a call retains tool access and CLAUDE.md/repo-context auto-discovery even with a system prompt instructing otherwise. `AnthropicBackend` additionally hard-requires `VAR-ANTHROPIC-API-KEY` to be set at all, short-circuiting with an `auth` `model_call_error` otherwise — meaning a project with no API key configured, only a Pro/Max subscription login, could never dispatch a real call, despite `VAR-ANTHROPIC-API-KEY`'s own spec documenting unsetting the key as a legitimate way to bill a Pro/Max plan instead.

Confirmed by direct, empirical testing (not assumed): `--bare` itself unconditionally refuses any non-API-key credential — the `claude` CLI's own `--help` states this plainly ("OAuth and keychain are never read" under `--bare`), and a live test dropping `--bare` restored subscription billing but also leaked real `~/.claude/CLAUDE.md` content into the call, reproducing the exact contamination `D35` exists to prevent. `--safe-mode` was then tested as a substitute: it disables CLAUDE.md, hooks, plugins, custom commands, and "more" — the same class of contamination `--bare` targets — without touching auth resolution at all. Combined with the already-mandatory `--tools ""` (which independently blocks the tool-based exploration the original violation actually exploited), a live call under `--safe-mode` showed zero CLAUDE.md leakage, zero tool invocation, and `apiKeySource: "none"` — billed through the subscription login, not an absent API key.

## Decision

`AnthropicBackend` no longer short-circuits on a missing `ANTHROPIC_API_KEY`. Instead: if the env var is set, dispatch with `--tools "" --bare` exactly as `D35` already established (unchanged — maximum isolation, metered API billing). If it is absent, dispatch with `--tools "" --safe-mode` instead of `--bare`, and let the call proceed — whatever credential the `claude` CLI itself resolves (a Pro/Max subscription login, or genuinely none) determines the outcome, classified the same way any other backend failure already is (`R-ENDPOINT-004`'s `model_call_error` vocabulary — a "not logged in" response is an `auth`-category failure, same as before), never pre-empted by this component guessing the outcome in advance. `--safe-mode` and `--bare` are not interchangeable in general — `--safe-mode` leaves auth resolution open where `--bare` deliberately closes it — but for this component's specific purity requirement (no CLAUDE.md/hooks contamination, no tool access), the two are equivalent, and `--safe-mode` is the one that also works without an API key.
