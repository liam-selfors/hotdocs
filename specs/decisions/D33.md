# D33 — Restore `retry_feedback` as a developer-supplied input, correcting `D31`'s overreach

## Context

`D31`'s actual point was narrow: no *automatic* retry loop deciding,
on a component's behalf, to call `generator` again within the same
merge. Implementing it removed `retry_feedback` entirely, which was
broader than necessary — the feedback mechanism itself (a bare `R-id`
list telling a retry what failed last time) is useful independent of
whether the decision to use it is automatic. Removing it was overreach,
caught and corrected here rather than left standing.

## Decision

`generator` regains an optional `retry_feedback` parameter
(`R-GEN-012`) — restored to its pre-`D31` content boundary, cold-mode
compatibility, and cache-key incorporation, except for one change: it
is now explicitly a **caller-supplied** input, never one `generator` or
`merge-orchestrator` computes or decides to include itself.

`merge-orchestrator`'s `run_merge` gains an optional `retry_feedback`
mapping (`component_id -> R-id list`, `R-MERGE-022`), supplied by
whoever invokes the merge, passed through verbatim to `generator`'s one
call for the named component. `merge-orchestrator` MUST NOT derive this
mapping from `.hotdocs/attempts/` or anywhere else itself — the
decision to retry informed, and the content of that information, stays
entirely with the human (or script) initiating the call. New CLI flag:
`--retry-feedback=<component-id>=<R-id>[,<R-id>...]`.

`merge-tracker` gains `last_requirement_failures` (`R-TRACK-008`) and
`hotdocs track feedback <component>` — a pure, read-only convenience
telling a developer what a component's last attempt failed on, so they
know what they *could* pass. Never called by the merge pipeline itself:
it answers "what failed," it never decides "retry with this."

**Also fixed while here:** `R-GEN-007`/`AC-GEN-007`, a genuine leftover
`D31` missed — entirely about `seed`/`sample_index`, which stay retired
(only `retry_feedback` returns; there is still only ever one `generate`
call per component per merge, so no sample variation exists to
record).

## Consequences

The net effect versus `D31`'s original state: no automatic retry loop
(unchanged, the actual point stands), but the diagnostic feedback that
loop used to compute is available again, now surfaced to and
controlled entirely by the developer deciding whether a blocked
component's failure is transient or a genuine spec gap — exactly the
workflow `D31`/`D32` were meant to enable, completed rather than
undermined by also having the informative retry available on request.

See `specs/components/generator/requirements/R-GEN-012.md` and
`specs/components/merge-orchestrator/requirements/R-MERGE-022.md` for
the current, authoritative rules.
