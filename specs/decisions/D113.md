# D113 — R-AUTHOR-020's arity check must also scan string-literal fake source, and R-AUTHOR-011 needs a worked return-shape example

## Context

With `D112` landed, a fresh `provenance-tracker` retry (new seed, forcing fresh test-authoring) surfaced three more real issues:

- `AC-TRACK-010` crashed at runtime with `TypeError: check_provenance() takes from 1 to 2 positional arguments but 4 were given` — the exact bug class `R-AUTHOR-020`'s static arity check exists to catch, yet it passed verification uncaught. Diagnosis: the fake's `def check_provenance(component_id, repo_root=None)` was written inside a triple-quoted string literal passed to `path.write_text(...)` — the normal, expected way to write a fake module file (`R-AUTHOR-010`) — not as a literal top-level statement in the test's own module. `R-AUTHOR-020`'s AST walk only inspected top-level `FunctionDef`s and aliases, missing source living inside a string entirely.
- `AC-TRACK-009`/`011` both crashed with `AttributeError: 'list' object has no attribute 'precondition_error'` — a fake `impact-analyzer` returning a bare list of ids instead of the documented `BlastRadiusReport` object (`impacted`/`precondition_error` fields). This is the identical mistake `R-AUTHOR-011`/`D100` was created to close in the first place, recurring twice more across two different seeds despite the real, fully field-documented shape being present in `dependency_interfaces` the whole time (confirmed: `spec_bundle_assembler._interface_text()` already includes each dependency's `interface/data/*.md` content, not only `library.md`). Prose stating "match return shape exactly" is evidently not reliably sufficient on its own — the same lesson `R-AUTHOR-010` already learned for the loader convention, now shown to apply here too.
- A `comp-provenance-tracker is documented to declare no dependencies at all` assertion failure, traced to `AC-TRACK-004`'s own Gherkin phrasing — "confirmed by this component's own depends_on listing no dependency on comp-component-gate-runner at all" was read as "lists no dependencies, period" rather than "excludes this one specific dependency." A pre-existing ambiguity in this session's own spec authoring, not a test-author gap — `AC-TRACK-004`'s Gherkin is reworded directly, no `R-AUTHOR-*` change needed.

## Decision

`R-AUTHOR-020` is amended: the arity check's AST walk MUST also parse any string literal in the test that itself parses as valid Python, and walk it the same way as top-level code — closing the blind spot that let a real wrong-arity fake through uncaught.

`R-AUTHOR-011` is amended: the instruction MUST include one worked example showing a fake constructing a return value that exposes every field of a documented type, never a bare primitive — the identical bare-list mistake it was meant to close has now recurred twice, unprompted, well after the prose-only version of this requirement already existed.

`test-author` is cold-regenerated against both amendments; `provenance-tracker` is retried once more.
