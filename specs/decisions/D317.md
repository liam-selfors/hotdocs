# D317 — test-probe stubs every module a capability scenario imports

## Context

A capability scenario's bundle names no module of its own: its
`component_id` is `capabilities/P-<ID>`, and `module_names` lists the
realizing components' modules (`D198`). `test-author` passed `probe` a
name derived from that `component_id`, and `probe` took one name, so
the stub run failed to write `capabilities/P_SLUGS.py`, and a test
importing two realizing modules could never pass the import check.
`test-author`'s hand suite found it.

## Decision

`probe`'s `module_name` is a name or a list of names; each gets its own
stub module and counts as resolvable. `test-author` passes the bundle's
`module_names` when it is non-empty, else the slug-derived name.

## Consequences

`test-probe` and `test-author` are regenerated again. A single-name
call is unchanged.
