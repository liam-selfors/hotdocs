# D375 — criterion-compiler states only what it must do itself to be loaded

## Context

`R-COMPILE-014` told every component depending on `criterion-compiler`
how to import it: a plain `import`, then `sys.path` entries under
`pipeline/` and `gen/` (`D83`). A dependent never receives another
component's requirements (`R-ASSEMBLE-002`), so no dependent's generator
saw the rule; and since `D199` each dependent states in its own
interface that it loads `criterion-compiler` by path from
`<repo_root>/pipeline/criterion-compiler/`, else the tool root. The
requirement described an algorithm nothing used.

## Decision

`R-COMPILE-014` states what `criterion-compiler` itself owes its
loaders: its module works when loaded by path alone, from any
directory, with no other `hotdocs` component imported at module level.
`AC-COMPILE-015` checks exactly that.

## Consequences

Dependents' loading stays where their generators see it, in their own
interfaces. `criterion-compiler` is sealed and its key covers only its
code, so this changes no provenance of its own; its regenerated
characterization test for `AC-COMPILE-015` is re-authored from the new
text.
