# D204 — review-packet-builder's criteria state their shared fixture

## Context

Under `D201`'s criteria, `review-packet-builder` was generated seven
more times. Every candidate passed every mutant, and every round failed
on a generated test's own fixture: a component directory named by its
id instead of its slug, a fake report `repr`'d twice, a fake written
in JSON spelling, a diff marker placed outside `specs/`, a module copy
read after the test deleted it, and the real `provenance-tracker` used
where the criterion assumed a stand-in. One round produced no test at
all for the eight-scenario `AC-PACKET-012`. The criteria said what to
check and left the fixture to each test's guess.

## Decision

`interface/library.md` gains a "Test fixtures" section every criterion
inherits: `repo_root` is a git repository with a commit, the
`provenance-tracker` stand-in lives at its real path and defines both
functions as Python literals, and a spec id in a criterion exists only
in the fixture. Criteria that depended on a particular layout now name
it. `AC-PACKET-012` keeps the CLI scenarios; the markdown rendering
moves to `AC-PACKET-014`, so each stays short enough for one answer.

## Consequences

`review-packet-builder` regenerated (mutation score `0.81`) and
`hotdocs review-packet build` works from a project. A fixture every
criterion shares belongs in the library document, stated once, not
implied by each criterion.
