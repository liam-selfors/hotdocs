# D321 — An empty_response error carries what the model said

## Context

A reply with no file blocks ended `hotdocs generate` with
`empty_response: the model reply contained no files`, and nothing kept
the reply: the call log records only that text was present. In the
demo, the reply explained which document the bundle lacked, the one
fact that would have fixed the spec (issue #5).

## Decision

`generator`'s `empty_response` message holds the reply's first 4000
characters, with a count of what was cut. It already reaches the
attempt record under `.hotdocs/attempts/` and the `generate` output.
The call log stays content-free (`R-ENDPOINT-006`).

## Consequences

A person sees why the model wrote nothing without capturing the reply
by hand. A spec reference to a document outside the bundle is still
found only this way; a lint check for it is left for later.
