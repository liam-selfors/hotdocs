# D343 — Asset kinds are built now, with javascript first, replacing JavaScript mutated inside strings

## Context

`D335` closed issue #13 by mutating JavaScript found inside Python
strings: a regular expression decides which strings hold JavaScript,
`<script>` regions are cut out of HTML, and a hand tokenizer skips the
script's own strings and comments. Pinning those heuristics took
`D342`, and three regenerations of `verifier-orchestrator` fell below
the bar on them. `D340` had already planned asset kinds for the next
round, which would declare such JavaScript as a file of its own and make
the string heuristics unnecessary, and which regenerates the same
pipeline components again. Building both meant regenerating the
pipeline twice and maintaining a mechanism planned for removal.

## Decision

Asset kinds are built in this round, in the same regeneration as
`D332`-`D342`, as `specs/architecture/asset-kinds.md` states:

- A component declares non-Python assets in frontmatter,
  `assets: [<kind>:<path>]`; `python` stays the pipeline's own kind,
  with no adapter.
- A kind is a definition, `specs/architecture/asset-kind-<kind>.md` with
  seven sections, a spec only, and an adapter component,
  `comp-kind-<kind>`, loaded by path so that a new kind never
  regenerates the pipeline. The running pipeline reads only the adapter:
  its `guidance()` returns the generator and test author guidance the
  definition states, so the tool's built-in kinds need nothing outside
  `gen/`, the place everything the installed tool reads at run time
  belongs.
- `spec-bundle-assembler` adds each kind's generator guidance to the
  `SpecBundle` and its test author guidance to `CriterionBundle.testing`;
  `generator` and `agentic-generator` check declared assets' layout;
  `surface-checker` checks their surface; `test-probe` stubs
  `asset_runner`; `verifier-orchestrator` supplies `asset_runner`,
  provisions environments, fails on an unprovisioned one with
  `failure_origin` `"environment"`, and adds each asset's strength
  sites to the one mutation score; provenance records each asset's kind,
  definition, adapter and environment; `spec-linter` checks the
  declarations and definitions.
- `javascript` is the first kind: an ES module of pure functions run in
  Node 24 or later through `asset_runner`, mutated with `D335`'s token
  swaps over the whole file. `docs-site-renderer` and
  `provenance-tracker-ui` move their JavaScript into `static/app.js`.
- `D335`'s mutation inside strings is withdrawn. JavaScript left in a
  Python string fails verification with a `mutation_error` naming the
  file and line and asking for an asset, so a component cannot score on
  logic no mutant reaches (issue #13).
- No `hotdocs env sync` verb yet: an adapter provisions on first use.

## Consequences

The pipeline regenerates once for everything on this branch. A project
with JavaScript in strings must declare it as an asset before its
components verify. `sql`, `data-schema`, `sandbox-profile`, `document`
and `prompt` kinds follow as their own decisions, each adding only an
adapter and the components that declare it.
