# D363 — hotdocs <verb> --help prints the verb's usage

## Context

`hotdocs lint --help` printed `usage error: unknown argument: --help`
and returned `2`. Every verb did: `cli-conventions.md` defines no
`--help`, so each component treats it as an argument it does not define.
The usage line a new user wanted was there, on stderr, under an error.

Defining `--help` in `cli-conventions.md` is the complete fix, and it
re-authors every test of the 22 components that implement the document,
since the document is part of each criterion's bundle. That waits for the
next full wave (`notes/backlog.md`).

## Decision

`hotdocs-cli` answers `--help` and `-h` after a verb itself
(`R-CLI-007`). It dispatches the verb as usual, without resolving a
model, and captures the component's stderr. A component that defines no
`--help` answers with a usage error and its usage line, as
`cli-conventions.md` requires and `surface-checker` probes; `hotdocs-cli`
then prints `hotdocs <verb words>: <summary>` and the usage line on
stdout and returns `0`. Any other answer passes through unchanged.

## Consequences

Only `hotdocs-cli`, a leaf, is regenerated. A component's own `main`
still answers `--help` with a usage error; when `cli-conventions.md`
later defines `--help`, each component's answer passes through and
`R-CLI-007`'s rewriting stops applying, with no change here. A usage
error must stay free of side effects, which the conventions already
require.
