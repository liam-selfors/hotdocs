# D65 — A third real gap, found by this component's own hand-written test suite

## Context

A retry of `impact-analyzer`'s `generate()` call, with `D64`'s two
fixes in place, produced a 618-line candidate that correctly resolves
"the prior commit" via real `git merge-base` and real `git show`/`git
ls-tree` content comparison — directly confirming `D64`'s fix works —
and correctly outputs `component_id` in full `comp-<slug>` form.

Building this component's own hand-written verification suite
(synthetic lint-clean fixture, real git repo, matching every
`AC-IMPACT-*` criterion's literal scenario) found a third, narrower
bug: `R-IMPACT-008`'s narrowing feature (`depends_on_guarantees`)
never actually narrows anything. The candidate's entry parser only
recognized a nested `{component, guarantees}` dict shape; the real
frontmatter shape, confirmed from `generator`'s own real
`depends_on_guarantees: [G-CACHE-001]`, is a flat list of bare
`G-<comp>-NNN` id strings. Against real data the parser always found
zero recognized entries and fell back to the coarse, unnarrowed
default — confirmed directly: a test matching `AC-IMPACT-008b`
(narrowing must *exclude* a dependent from an unclaimed guarantee
change) failed, while the coarse-default and narrowed-inclusion cases
(`AC-IMPACT-008`/`008c`) passed, because both of those don't actually
require narrowing to work correctly, only `008b` does.

The real shape was already documented — in `SPEC_GUIDELINES.md` §2,
which no `SpecBundle` ever includes, the same root cause `D62` found
for output layout. `R-IMPACT-008`'s own bundle-visible text spoke of
entries "whose owning component is this upstream component" without
ever saying that ownership is derived by scanning real
`interface/guarantees/` directories, never parsed from the `G-id`
string itself or declared per-entry — real room for a plausible but
wrong invented structure.

## Decision

Clarified directly in `R-IMPACT-008.md`: `depends_on_guarantees` is a
flat list of bare `G-<comp>-NNN` strings; a `G-id`'s owning component
is never parsed from the id itself (ambiguous once a component slug
contains hyphens) but determined by which component's real
`interface/guarantees/` directory contains that file.

The candidate's `gen/impact-analyzer/` output was deleted before being
committed, never swapped in.

## Consequences

A fourth retry, with this fix in place too, is the next real test.
Three real gaps found across two `generate()` attempts for this one
component (`D64`'s two, now this third) — each found by a different
verification step: the first two by direct testing against the real
repo before writing any test suite at all, this one only once the full
hand-written `AC-IMPACT-*` suite existed. Worth naming plainly: a
quick manual smoke test and a full acceptance-criteria suite catch
different things, and this component needed both.

Linter: 0 failures once this file exists. Pytest: all 118 tests across
all nine built components re-verified unchanged (spec-only edit).
