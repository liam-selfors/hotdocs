# D40 — Rename `spec_bundle_words`; validate `D<N>` decision citations

## Context

Two findings from an earlier self-audit of the methodology were flagged
but never resolved, since the conversation went deep on a third finding
(the cache/provenance trust gap, resolved by `D39`) and never circled
back. This decision closes both.

**Finding:** `SPEC_GUIDELINES.md` §4 defined `spec_bundle_words` as
`component.md` + `requirements/` + `interface/` + `acceptance/` +
`constraints.md` — but the actual `SpecBundle` type
(`spec-bundle-assembler`'s own output, what `generator` sees) explicitly
excludes `acceptance/` (`R-ASSEMBLE-001`). Same root term, two different
scopes, with nothing calling out the distinction.

**Finding:** nothing validated that a `D<N>` citation in prose resolves
to a real `specs/decisions/D<N>.md` file — unlike `R-id`/`AC-id`/`P-id`,
which are graph-validated (`R-LINT-008`/`009`/`021`). A typo or a
dropped follow-up commit would go silently uncaught; this session's own
two-commit decision pattern (implement citing `D<N>` → commit → *then*
write `D<N>.md`) walks through this exact unchecked window every time.

## Decision

**Renamed `spec_bundle_words` to `component_doc_words`** everywhere it
appeared — `SPEC_GUIDELINES.md`'s size-cap table, `R-LINT-012`/`022`/
`023`, the real linter code (`gen/spec-linter/spec_linter.py`) and its
test suite, `pipeline-decomposition.md`, `components/README.md`, and
this session's own playbooks. Decision records (frozen) keep the old
name, accurately describing what was true when each was written.
`SPEC_GUIDELINES.md`'s table row now states the distinction explicitly
rather than leaving two same-named-but-different concepts to be
discovered by accident.

**Added `R-LINT-026`**: every `D<N>` citation in a live document must
resolve to a real `specs/decisions/D<N>.md` file, except `D1`–`D14`
(frozen historical decisions that live only in `notes/initial-ideas.md`
by design, and must never be flagged). Implemented as a real rule in
`gen/spec-linter/spec_linter.py`, registered in `ALL_RULES`, with two
new pytest cases (`AC-LINT-026`) confirming both the dangling-citation
and frozen-decision-exempt paths.

## Consequences

Both findings are closed. `spec-linter` itself — the component both
fixes landed in — is now at 3994/4000 `component_doc_words`, its
tightest margin yet; per `notes/component-sizing-playbook.md`'s own
Step 3, this is the accepted "one cohesive responsibility" case (D29's
precedent), tightened rather than split, with essentially no headroom
left for the next addition.

Linter: 0 failures, 17 warnings. Pytest: 41 passed (two new cases). See
`R-LINT-026` and the amended `R-LINT-012` for the current, authoritative
text.
