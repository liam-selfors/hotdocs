# D107 — test-author's synthetic-fixture guidance states that status ratified requires last_ratified_commit

## Context

With `D106`'s crash fixed, the next real `spec-bundle-assembler` bootstrap retry produced a clean pass/fail result for the first time (no crash) but regressed to 8/14: five of six failures shared one exact cause, confirmed by directly linting each failing criterion's own synthetic fixture in isolation — `R-LINT-002`: a document whose frontmatter declares `status: ratified` but omits `last_ratified_commit`. `R-AUTHOR-012` already states the required frontmatter fields and the `status` enum (`D102`/`D105`), but never stated this one additional, `ratified`-specific requirement — a gap this corpus's own real decision/component files never hit in practice (new real records are drafted first, never authored directly as `ratified`), so a synthetic fixture reaching for `status: ratified` as a plausible-looking default had no real-file precedent to copy from either.

The sixth failure, `AC-ASSEMBLE-007`, is a different, pre-existing-pattern issue, not a test-authoring bug: its own acceptance criterion asks the test to recompute `spec_bundle_hash` from the bundle's contents and confirm it matches, but `R-ASSEMBLE-007` deliberately specifies only that the hash is *a* content hash, never a canonical formula — the same already-known, already-accepted gap `generator`'s own `spec_bundle_hash` criteria have had since before this session. Not fixed here; recorded as a known limitation alongside the other pre-existing generator gaps.

## Decision

`R-AUTHOR-012` is amended with a fourth addition: a synthetic fixture using `status: ratified` on any frontmatter-bearing document MUST also set `last_ratified_commit` to a short, clearly-fake-but-present placeholder value (`R-LINT-002` requires one whenever `status` is `ratified`, never for `draft`/`deprecated`). New `AC-AUTHOR-018`.

`test-author` is cold-regenerated against this amendment; `spec-bundle-assembler`'s five affected criteria are re-authored and re-verified once in place. `AC-ASSEMBLE-007` ships as a documented known limitation regardless of this retry's outcome, matching the precedent already set for `generator`.
