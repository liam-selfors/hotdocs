# D164 — A var's runtime value comes from one environment variable name

## Context

`SPEC_GUIDELINES.md` §3.3 declares configuration parameters as
`VAR-<NAME>` files with no `value` field, but nothing ever said where a
running component reads the value from. Each component guessed:
`cache-manager` and `provenance-checker` read `VAR_<NAME>`;
`secret-scanner` read `VAR_<NAME>` with the hyphenated name as a
fallback. Regenerating `license-scanner` (`D163`) produced four
different answers in one round: the candidate read the hyphenated
name, and three generated tests set the underscored name, the
hyphenated name, and a value written into the declaration file. Three
of its four failures traced to this.

## Decision

The glossary, which every spec bundle includes, defines a var's
environment name: `VAR_<NAME>`, hyphens replaced by underscores, and
nothing else consulted. `VAR-ANTHROPIC-API-KEY`'s existing
`ANTHROPIC_API_KEY` exception, already stated in its own declaration,
stands. The underscored form was chosen because it is what most
existing code already reads, and a hyphenated name cannot be set from
most shells.

The same round's fourth failure was the `D156` shape again: a faked
`cache-manager` provided `get`/`put` but not `CacheKey`, so the
candidate's key construction raised and `get` was never reached.
`license-scanner`'s and `secret-scanner`'s `interface/library.md` now
name the three `cache-manager` names each uses.

A further round showed the same gap one level down: two generated
tests read `blocked`/`component_id` off the top level of what `put`
received, while the candidate correctly wrapped the result in
`cache-manager`'s `CachedResult`. Both scanners' `interface/library.md`
now state that `put` receives a `CachedResult` whose `payload` holds
the scan result.

That wording was itself incomplete: a candidate then constructed
`cache-manager`'s `CachedResult` class, a fourth name the stand-ins
following "exactly three" did not provide, and its `put` was never
reached. The real `put` requires that class, so both documents now
name all four: `CacheKey`, `get`, `CachedResult`, and `put`.

`secret-scanner`'s first round surfaced two more environment facts a
test author cannot infer. A stand-in placed under `gen/` is itself
scanned, and one embedding a temporary-directory path tripped the
entropy heuristic, making a clean fixture scan flagged. And
`http.server.HTTPServer` resolves its host name on bind, which took 35
seconds on this machine, timing a test out. `secret-scanner`'s
`interface/library.md` now says both: stand-ins carry no high-entropy
strings, and the webhook is reached only through
`urllib.request.urlopen`, which a test replaces. `R-SECRET-001` now
reports one match per secret, never a pattern match and an entropy
match for the same span, and `R-SECRET-009`/`AC-SECRET-009` lose
their merge-era wording.

The next round passed every criterion at `mutation_score` 0.78. Most
survivors sat in behavior the spec left to the implementation, and
the live and regenerated implementations had in fact chosen
differently (a 12- versus 20-character entropy candidate, two
different entropy `rule_id`s). `R-SECRET-001` now pins the entropy
heuristic exactly; `PatternDatabase.md` says what a relative path
resolves against; `interface/cli.md` defines the precommit form's
default file set; and `AC-SECRET-005`/`013` exercise a cache hit, a
malformed rule, and that default.

A further round failed because the candidate scanned a compiled
`.pyc` under `__pycache__`, whose bytes tripped the entropy heuristic.
`R-SECRET-001` said "every file", which literally included it.
It now says every UTF-8 text file, skipping `__pycache__`, with a
scenario in `AC-SECRET-001`. Another added the `auth`/`timeout`/
`network` mapping for a failed webhook call to
`SecretScanResult.md`, with scenarios in `AC-SECRET-011`.
