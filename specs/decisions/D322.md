# D322 — claude-cli can be told to use the claude.ai login

## Context

`claude-cli` passes `--bare` whenever `ANTHROPIC_API_KEY` is set
(`D82`). Claude Code sets that variable for the processes it starts,
with a key that is not valid for a separate `claude -p` call, so an
agent driving `hotdocs` inside Claude Code failed every call with
`auth` while the same command with the variable unset worked
(issue #6).

## Decision

`hotdocs.toml`'s `[llm]` table takes `auth = "login"` or `auth = "key"`
for `claude-cli`. With `"login"` the command runs without
`ANTHROPIC_API_KEY` in its environment and with `--safe-mode`; with
`"key"` it always gets `--bare`; unset keeps `D82`. An `auth` failure
under the unset default with the key present says to unset it or set
`auth = "login"`. `hotdocs init --auth` passes the choice through. The
adapter's rules move to `specs/architecture/claude-cli-adapter.md`.

## Consequences

A Claude Code session can drive `hotdocs` with one line of config, and
the error that used to be opaque names the fix.
