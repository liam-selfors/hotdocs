# D27 — `spec-linter`'s requirement-traceability rules (R-LINT-008/009) adopted onto `nodes`/`edges`, closing D24's one deferred item

## Context

`D24` deferred this because it looked like it needed a second graph
vocabulary (`R-id`/`AC-id` nodes, a `Covers:`-derived edge) separate
from `nodes`/`edges`. Reading `spec_linter.py`'s actual
`rule_forward_traceability`/`rule_backward_traceability` implementation
before deciding — rather than reasoning from the rule names alone —
changed that assessment: R-LINT-008 only needs a *count* of `covers`
edges per requirement; R-LINT-009 only needs each edge's *target*
validated against known `R-id`/`P-id` nodes. Neither needs `AC-id` or
`GS-id` as addressable nodes — golden scenarios in particular, living
as inline `### GS-...` headings inside a product file rather than
their own file, never have to be resolved as a node, only extracted as
an edge *target value*. The real scope was smaller than `D24`
estimated.

## Decision

Presented as a choice regardless of the smaller real scope — minimal
extension, full node modeling, or not adopting this one at all.
**Chose full node modeling**, for a complete graph rather than one
trimmed to exactly today's two consumers.

- `nodes` gains three kinds: `requirement`, `acceptance`, and
  `golden_scenario` (the one kind extracted from headings inside a
  file's body rather than from a glob, since it has no file of its own).
- `edges` gains `covers`: from each component-acceptance file's single
  `Covers:` line, and from each golden scenario's `Covers:` line paired
  with the heading immediately above it — flagged explicitly as the one
  genuinely harder piece of this corpus's DuckDB adoption, since it
  breaks the "one row per file" shape every other view has.
- `spec-linter`'s new `R-LINT-021` adopts both rules onto this surface.

## Consequences

Neither rule's actual check changed — implementation requirement only.

See `specs/architecture/graph-query-engine.md`'s "Query surface" and
"Scope of adoption" sections, and `specs/components/spec-linter/
requirements/R-LINT-021.md` for the current, authoritative rules.
