# D378 — Scanners return results; callers record them and decide merges

## Context

Four scanner requirements asked for what neither scanner does.
`R-LICENSE-002` and `R-SECRET-003` required every result to be "written
into the provenance manifest"; `provenance-writer` writes it.
`R-SECRET-002` required a match to "block the merge"; since `D371`
`hotdocs verify` decides. `R-LICENSE-007` described merge retries
retired with `D3`. Their tests checked whatever the test author could
reach: cache writes, exit codes and printed JSON.

## Decision

Each requirement states what its scanner owns. A scan returns a
complete result, clean or flagged, never a null or empty one
(`R-LICENSE-002`, `R-SECRET-003`); a license scan never overwrites an
earlier result for different content, so a flagged result stays
retrievable (`R-LICENSE-007`); a secret match reports `flagged` true
and `main` exits 1, and `hotdocs verify` decides the merge
(`R-SECRET-002`). Their criteria are rewritten to match.

## Consequences

Regenerated: `license-scanner`, `secret-scanner` and the components
their code hashes reach. The license scanner's `gate_version` is
unchanged, so existing manifests still hit.
