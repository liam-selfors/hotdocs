# D175 — A compiled capability scenario can never pass, and what the build rounds exposed

## Context

`D174` made capability scenarios decided by running their test, not by a
test having been produced. Regenerating against that exposed what the old
rule had hidden.

## Findings

- **A `compiled` capability scenario cannot pass.** `R-SCENARIO-001`
  compiles with `surface=None`. The compiler's `Then x equals 1` becomes
  `assert result.x == 1`, and `result` exists only if a `When` step
  invoked a function — a step that cannot resolve without a surface and
  is then a compile error. So a scenario with no `When` compiles but
  raises `NameError`, and one with a `When` does not compile. The old
  hand tests, and the first draft of two criteria here, used `Given a x
  is 1 / Then x equals 1`, which "passed" only because compiling counted.
  `AC-SCENARIO-003` and `009` now assert that this scenario **fails**, and
  exercise the green path with a fake compiler.
- **The one real `compiled` scenario already fails.**
  `CS-DECISION-INTEGRITY-001` in `specs/product/decision-integrity.md` is
  free prose and does not compile, so `P-DECISION-INTEGRITY` has always
  reported `fail`. That file is outside this change; the scenario's
  `Kind:` should be `generated-test`.
- **Shared fixture facts must live in `interface/`.** A test author sees
  its own criterion, the requirement it covers, and `interface/`. The
  fixture rules in `AC-SCENARIO-001`, and `R-SCENARIO-001`'s "scenarios
  live in `specs/product/`, never `specs/capabilities/`", were invisible to
  the other eleven criteria, and eleven of twelve failed on the first
  round. They now live in `interface/library.md` ("Test fixtures").
- **A fixed absolute path in a criterion pollutes.** A mutant that
  disabled the path guard wrote `/tmp/escape.py`, which made the next real
  run fail. `AC-SCENARIO-008` now uses a path inside a temporary directory
  the test creates.
- **`interface/cli.md` removed**, not given a CLI: it said only "None",
  and `D162` treats a CLI document's existence as a CLI needing coverage.
  `D92` retired the CLI deliberately.

## Result

Regenerated over five rounds and landed at 12 of 12, `mutation_score`
0.84. Against a throwaway copy, `provenance-tracker`'s `check_readiness`
reached the real `run_capability_gates` for every capability.

## Not changed here

`provenance-tracker` calls `run_capability_gates(capability_id, repo_root,
judge=…, test_author=…)` and builds both from `llm_backend.judge` and
`.test_author`, which no backend has. It must pass `model`, `seed`, and
`llm_backend`, as `R-TRACK-010` should now say. The judge response
contract is restated in `R-SCENARIO-008` rather than shared, because
adding it to the glossary would change every component's spec hash; it
could be promoted there once hashes are being recomputed anyway.
