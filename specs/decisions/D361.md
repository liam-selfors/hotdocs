# D361 — Spec check finds a missing asset interface and stops asking about test mechanics

## Context

Two things went wrong for a new user who ran `hotdocs spec check` before
generating, as `QUICKSTART.md` advises.

A component declared a JavaScript asset and had no
`interface/assets/<file name>.md`. `specs/architecture/asset-kinds.md`
requires that file, but neither `hotdocs lint` nor `spec check` looked for
it, so the first sign was three failed generation attempts, each ending in
`surface-checker`'s `asset_error` (`D359`).

With a model, `spec check` reported for a sound criterion that its author
would have to guess the test framework and where the test file lives. The
review prompt stands in for a test author but lacks what the real one is
told by `test-author`'s fixed prompt: the framework, the file's name and
place, and how the component's code is reached are the pipeline's, never
the spec's.

## Decision

`spec-reviewer` gains a deterministic check, `R-REVIEW-008`: for each
component the targets name, every declared asset with no
`interface/assets/<file name>.md` gives one `asset_interface_missing`
finding, whose `criterion_id` is the component's id. It runs before lint
and needs no model, so the findings are in every report.

The review prompt of `R-REVIEW-004` states, in a fixed sentence, that the
pipeline fixes those test mechanics and that none of them is a gap.

## Consequences

`hotdocs spec check comp-<name> --no-model` names a missing asset
interface before any generation. `spec-reviewer` is regenerated, and
`spec-completeness-assistant` without spec changes, since `ReviewReport`
is in its bundle. The same check as a `spec-linter` rule, which would
reach `hotdocs lint` too, stays in `notes/backlog.md`: `spec-linter` is a
dependency of most components.
