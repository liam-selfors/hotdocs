# D329 — Criteria added where the honest mutation score fell below the bar

## Context

Before `D324`, a mutation run whose tests could not run in the sandbox
counted every mutant as killed, so many manifests recorded 1.0. Run in
the corrected layout, `size-checker` scored 0.64, `impact-analyzer`
0.77 and `spec-linter` 0.59 against the bar of 0.8, with every
criterion passing. Their surviving mutants sat in behavior the specs
state but no criterion exercised: `SPEC_GUIDELINES.md` §4's
`interface_surface`, guarantee, acceptance and fan-in counts and
acceptance-file word counts; `impact-analyzer`'s usage-error exits and
git-root default from its `interface/cli.md`; `spec-linter`'s summary
counts, `--strict`, judge outcomes, `paths` scoping, the
bounded-context split, and architecture docs' own `depends_on`
resolution and cycles (`R-LINT-020`'s residual checks). Re-authoring the same criteria's tests with
another seed did not raise `size-checker`'s score.

## Decision

New criteria cover that stated behavior: `AC-SIZE-005` to `007`,
`AC-IMPACT-011` and `012`, and `AC-LINT-034` to `038`. No requirement
or interface changes, so no bundle hash moves and the code stays as
generated. Their tests are authored for the existing code
(`tools/rerecord_provenance.py --author-tests`) and provenance is
re-recorded. Behavior no spec states, such as `impact-analyzer`'s text
output layout, stays unchecked; the score clears the bar without it.

## Consequences

The three components' manifests report scores measured in the
corrected layout. A later spec change that states the unchecked
behavior should add its criterion in the same change.
