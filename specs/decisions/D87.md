# D87 — Formalizing a mechanism that was designed but never once used

## Context

The user recalled a prior process for nullifying decisions superseded
by later ones, and asked for it to be made real, with temporal
insight into which decisions were in force at any given time. Checking
the actual corpus state: `supersedes` (frontmatter) and
`status: deprecated` have existed in the universal frontmatter schema
since the start — but across all 72 decision records, neither has
ever been set, even once. Real superseding relationships exist only
as unstructured prose throughout the corpus.

A systematic sweep of all 72 decisions, forked out given the scale,
found two full reversals and two partial ones. Verifying the sweep's
own classifications directly, rather than taking them on faith,
mattered: the sweep called D47-supersedes-D45 a full reversal, but
reading D45's actual text found it has two separable conclusions —
the four-subagent simulation mechanism (fully retired by D47) and the
corpus-graph-builder cold-generation result (still valid, still
correctly cited elsewhere in the live corpus). Marking all of D45
`deprecated` would have misrepresented the still-valid half. Only
D31-supersedes-D17 survived as a genuine full reversal: D17 concluded
to keep best-of-k retry with diagnostic feedback; D31's own text
explicitly reopens that question "with a different answer than the
one D17 rejected," retiring the mechanism entirely.

Checking D45's real content also surfaced an unrelated, genuine bug:
two component.md files and a requirement credited "D45" for the fact
that `llm-endpoint` dispatches via the `claude` CLI's non-interactive
mode — a fact D45 never states anywhere. That fact is D46's. A
citation existing and resolving to a real file (satisfying `R-LINT-026`
today) is not the same as the citation being correct — the exact
distinction this whole feature exists to help catch, found manually
this time, before any mechanism for it existed.

## Decision

`SPEC_GUIDELINES.md` §3.5 now states the one sanctioned exception to
decision-record immutability: when a new decision's `supersedes`
names a prior one, that prior record's `status` flips to `deprecated`
as a metadata-only edit — never touching the body — with
`last_ratified_commit` retained as the unchanged historical fact of
when it *was* ratified. `supersedes` is scoped to full replacement
only; a partial reversal (`D33`⊂`D31`, `D15`⊂`D1`-`14`, both already
correctly classified by the sweep) stays a plain prose cross-reference,
never this formal field.

Retroactively applied to the one confirmed case: `D31.supersedes: D17`,
`D17.status: deprecated`. New `R-LINT-029`/`AC-LINT-029` mechanically
enforces the relationship going forward both directions — every
`supersedes` must resolve to an actually-`deprecated` record, and
every `deprecated` record must be named by some real `supersedes` —
so the chain stays fully reconstructible, never silently incomplete
in either direction. Fixed the two D45/D46 mis-citations found along
the way.

## Consequences

The schema-but-never-exercised gap this closes is structurally the
same shape as the glossary-promotion gap `D86` just formalized: a
mechanism existing on paper is not the same as it being real. This is
piece 1 and 2 of a four-piece initiative the user scoped explicitly;
piece 3 (a `graph-query-engine` view surfacing the `supersedes` chain
with ratification commits, for "what was in force as of X" queries)
and piece 4 (the actual staleness diagnostic cross-referencing a spec
file's own last-modified commit against this chain) are each their
own, larger pieces of work, tracked as separate decisions once built —
not bundled here, consistent with this session's practice of scoping
one decision to one cohesive finding.
