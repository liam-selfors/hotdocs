# D79 — A sealed component's own bug, found only once something finally executed its output

## Context

`verifier-orchestrator` (batch 2) is the first component whose job is
to actually *run* `criterion-compiler`'s emitted scaffolding against
real `gen/<component>/` code, rather than just inspect its content.
Doing that surfaced a real bug in `criterion-compiler` itself (sealed,
`D60`): every `When ... is invoked` step and every typed `Given` step
compiled to a bare, unqualified call (`do_the_thing(1)`) with no
import of the target module anywhere in the emitted file. This had
never been caught before because none of `criterion-compiler`'s own
12 prior tests ever executed emitted output as a real running test —
they checked content, determinism, or ran `exec()` on the source
purely as a safety check, never by calling the defined test function
against real target code.

## Decision

Fixed directly in the sealed implementation (never a `generator`
candidate, per `component.md`'s Purpose): added
`InterfaceSurface.module_name` (the target component's underscored
slug) and a `_qualify()` step applied at both the `When`-invoke call
site and the `Given`-Type-construction call site, prefixing every
resolved reference with `<module_name>.` and setting a `needs_import`
flag; `_emit_pytest` now compiles all scenarios first, then emits a
single top-level `import <module_name>` line iff any scenario needed
it (`R-COMPILE-013`, `AC-COMPILE-014`).

This also exposed a previously undocumented fact: emitted output now
requires any caller that *executes* it to scope its import search
path (`PYTHONPATH` for `pytest`) to the specific `gen/<component>/`
directory, never a broader ancestor like `gen/` — confirmed empirically
that `gen/` resolves `import <module_name>` as an empty implicit
namespace package (no `__init__.py` there), while `gen/<component>/`
resolves it to the real module. Documented in `R-COMPILE-013` itself
and cross-referenced into `verifier-orchestrator`'s own `R-VERIFY-001`,
since that component is the concrete caller this contract was written
for.

One existing test (`test_ac_compile_007_literal_data_is_inert_never_
executed`) needed updating to register a fake target module in
`sys.modules` before its `exec()`-based safety check, since emitted
source now legitimately contains an `import` statement it didn't
before.

## Consequences

All 15 `criterion-compiler` tests pass (13 pre-existing + 2 new for
`AC-COMPILE-014`). `verifier-orchestrator`'s own candidate has a
structurally identical PYTHONPATH-scoping bug in its
`_run_pytest_file`/`_mutant_is_killed` functions — set too broadly
before this contract was ever documented, so not a model failure to
follow a known rule. Since the contract is now written down for the
first time, the right next step is a clean retry of `generate()` for
`verifier-orchestrator`, not a hand-patch of the existing candidate
(not sealed, not yet swapped in).
