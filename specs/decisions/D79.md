# D79 — Baseline component size-cap thresholds

## Context

`SPEC_GUIDELINES.md` §4's size-cap table states warn/hard-fail numbers for six dimensions — generated code per component, `component_doc_words`, requirements per component, public interface surface elements, `depends_on` fan-out, and dependents fan-in — with no decision record backing the original six, unlike the three dimensions `D17` added later (guarantee count, acceptance-criterion count, per-file words) and the `Purpose`-section cap `D22` added. A real choice that could reasonably have gone another way (any of these numbers could have been set higher, lower, or omitted entirely) had never been written down.

## Decision

The founding thresholds are: generated code per component, 800 LOC warn / 1500 hard-fail; component docs (`component_doc_words`), 2000 words warn / 4000 hard-fail; requirements per component, 20 warn / 40 hard-fail; public interface surface elements, 10 warn / 20 hard-fail; `depends_on` fan-out, 7 warn, no hard-fail; dependents fan-in, 10 warn, no hard-fail. These are a first pass, calibrated against this corpus's own content at the time they were set rather than derived from an a priori formula — the same posture `D17`'s own three additions already state explicitly for themselves. They are enforced by `spec-linter` (`R-LINT-012`), and crowding across them is the trigger `R-LINT-022` (`D15`) watches for.
