# D304 — A truncated reply, or one without the component's module, is a generation failure

## Context

The generator's reply wraps each file in nonce-delimited markers. When
a reply ran out of output tokens, the last file's block had no end
marker and was dropped silently; the remaining files were written and
the missing one surfaced later as an unrelated verification failure.
The tool's own regeneration hit this repeatedly with `claude-cli`
before its output limits were raised by hand, and a user outside a
supervised session has no way to recognize the cause. A reply that
produced files but not the component's own module failed the same
indirect way.

## Decision

- The prompt asks the model to end its reply with the line
  `-----END REPLY <nonce>-----`. A reply without that line, or with a
  `BEGIN FILE` block that has no matching `END FILE`, is
  `model_call_error` category `truncated_response`.
- A reply whose files hold neither `<module>.py` nor
  `<module>/__init__.py` is `missing_module`.
- In both cases nothing is written or cached, and the result names the
  cause, so a caller can retry or tell the user to raise the provider's
  output limit.

`PROMPT_VERSION` becomes `v11`.

## Consequences

The whole reply format, sentinel included, is in the generator's
`interface/library.md`, so every criterion's mock model sees it.
