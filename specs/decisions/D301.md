# D301 — `hotdocs assist` previews with `spec-reviewer` and judges against the criteria

## Context

`spec-completeness-assistant` had four defects that made it close to
useless on a real corpus:

- Its completeness judgment never saw an acceptance criterion: it was
  given hint-mode spec bundles, which exclude `acceptance/` by design, so
  it could not tell whether a requirement was tested.
- Its "preview" was a full generation per component in the blast radius,
  paid for and then discarded.
- It halted on any lint failure anywhere in the corpus, so one unrelated
  problem disabled it.
- Its redundancy check saw only the blast radius's bundles, not the rest
  of the corpus where a restated rule usually lives.

## Decision

- `depends_on` drops `comp-generator` and `comp-spec-bundle-assembler`
  and adds `comp-spec-reviewer`. The preview for each blast-radius
  component is `spec-reviewer`'s deterministic check, with no model call;
  `hint_previews` becomes `criterion_reviews`.
- Lint halts only on a `fail` finding inside a changed component, and the
  report says so with a new `halted` field; the CLI exits `1` on `halted`.
- The completeness prompt holds each changed requirement with the full
  text of the criteria that cover it, or a line saying none does.
- Redundancy candidates are found deterministically across the whole
  corpus by word-set similarity, and the model judges only those pairs;
  with no candidate there is no redundancy call.
- With a model, `lint` runs with `spec-reviewer`'s glossary judge.

`R-ASSIST-004` becomes a `generated-test` criterion over a recorded
prompt. Only `R-ASSIST-005`'s judgment remains a model's, and its
mechanics are now tested with a stand-in.

## Consequences

`spec-completeness-assistant` is a leaf; only it regenerates.
