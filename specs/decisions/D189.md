# D189 — test-author's prompt never named the component under test's module

## Context

The first run of the tool against a project outside this repository
(a scratch project with a `semver` component) failed all five of its
generated tests with `ModuleNotFoundError: No module named
'comp_semver'`. The generator had written `gen/semver/semver.py`
correctly. `R-AUTHOR-010` tells the test author the component under
test is imported with a plain `import <module_name>`, but defines
`<module_name>` only for a component's dependencies. Left to guess, the
model derived a name from the `component_id`. A neighbouring `slugify`
component passed only because its function name equalled its module
name, so the guess was inferable from the criterion text. Every
component in this repository got lucky the same way; no test of
`test-author` ever varied the two.

## Decision

New `R-AUTHOR-025` (with `AC-AUTHOR-025` and a hand test over two
component ids): the prompt names the module concretely as the slug with
hyphens replaced by underscores and writes the exact statement
`import foo_bar`, whether the generator lays the module out flat or as
a package. To stay under the 4000-word cap, backstory was trimmed from
`R-AUTHOR-009`–`015`; their normative content is unchanged.
`test-author` was regenerated through the `D58` route.
