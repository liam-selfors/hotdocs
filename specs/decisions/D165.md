# D165 — generator strips a redundant component-directory prefix from output paths

## Context

A `license-scanner` round (`D163`) returned its one file as
`license-scanner/license_scanner.py`. Paths are relative to
`gen/<component>/`, so it was written to
`gen/license-scanner/license-scanner/license_scanner.py`, nothing
could import it, and every criterion failed with
`ModuleNotFoundError`. The prompt already states the layout
explicitly (`R-GEN-015`); the model restated the directory anyway.
Another prompt sentence would not make the next violation less
likely, only a check would.

## Decision

Before writing, `generator` strips one leading `gen/<component>/` or
`<component>/` from each returned path, and `GenerationResult.files`
carries the stripped paths. That prefix is unambiguous: it names the
directory being written into. No other path is rewritten — a `src/`
layout, for instance, still fails verification visibly, since
guessing what any other layout meant would hide the mistake rather
than fix it. `GATE_VERSION` moves to `generator@1.6.0` so no output
cached under the old behavior is reused. `generator` is hand-authored
(a permanent exception), so the change is made directly, with hand
test `AC-GEN-021`.
