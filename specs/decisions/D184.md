# D184 — One hotdocs command, a vendoring init, and a table-driven dispatcher

## Context

Running the tool on a small project outside this repository (the
scratchpad `customer/` experiment) showed three things. There was no
`hotdocs` command: every component has its own `main`, each claims a
`prog="hotdocs <verb>"`, and nothing routes between them. The tool could
not run on any other project, because every component loads its
dependencies from `<repo_root>/gen/<slug>/`, so it failed with an
`ImportError` unless the whole tool had first been copied into the project.
And the components disagree about their own argument contract: some
expect their verb words kept (`generate`, `provenance write`,
`track ui build`), some stripped (`lint`, `impact`), and `corpus-graph`
wants only its first word stripped.

## Decision

A new component, `hotdocs-cli`, with two jobs.

**The dispatcher** is driven by one data table (`VerbTable.md`) giving,
per verb, the component directory, module, and number of tokens to strip.
The table is data so that a cold generation never guesses a contract, and
so that adding a verb is a one-row change. Components are reached by
loading their `main` by path, not through their Python APIs, so the only
declared dependency is `llm-endpoint`. A default `--model` is injected
from `hotdocs.toml` only for the two verbs that cannot run without one
(`generate`, `author-test`): for `verify`, `track ui build`, and `assist`
a model changes what the command does (it can start paid scenario runs or
turn on model-backed review), so the user must ask for it.

**`init`** sets up a project by vendoring the tool into it: the
stop-gap that makes the existing loading convention work. It never
overwrites, refuses before writing on a name collision or when pointed at
the tool's own repository, never installs anything (it prints the command),
and never handles an API key, only the NAME of the environment variable
that holds one. It configures the provider through `llm-endpoint`'s own
`detect_providers`, `check_connection`, and `save_config`, so
`hotdocs.toml` has a single writer. Vendoring is a pilot measure: it
mixes tool code into a project's `gen/` and complicates upgrades, and the
proper fix (a tool root separate from the project root) touches the loading
rule of about a dozen components.

`hotdocs verify` is solely the readiness check (`provenance-tracker`);
`verifier-orchestrator`'s per-component command is `verify-component`.

## Known inconsistencies found while deriving the table

- `cache-manager` documents `hotdocs cache inspect|stats` but defines no
  `main`, so `cache` has no row.
- `generator.py` still has a `main` claiming `prog="hotdocs generate"`,
  although that verb was retired to `component-gate-runner` (`D91`).
- `capability-scenario-verifier` and `llm-endpoint` have no CLI.

## Reconciled with the landed multi-provider `llm-endpoint`

`init`'s provider step was first specified against the endpoint's announced
function names and then re-read against the code that landed:

- `complete()` finds `hotdocs.toml` through `VAR_HOTDOCS_CONFIG` or the
  *current directory*, so a verb run with `--repo-root` elsewhere would
  silently miss the project's provider settings. The dispatcher now points
  that variable at the project's file for the duration of the call.
- `check_connection` and `save_config` raise `ValueError` for invalid input
  rather than returning an error, and `save_config` refuses a `base_url`
  or `api_key_env` for `claude-cli`. `init` reports both as messages and
  rejects the combination as a usage error before writing.
- `openai-compatible` has an empty `suggested_model` and requires a
  `base_url`, so both are asked for (and are required flags).
- `timeout_seconds` has a 300-second floor (`R-ENDPOINT-004`); `init`
  never prompts for or passes it.

## Found by the first generation round

Three criteria failed on genuine ambiguities, each fixed in the spec:
the vendoring stamp was rewritten on a second run (the never-overwrite rule
had not been applied to it); prerequisite reports went to stderr (the
channel was unspecified); and the `claude` check read only an existing
`hotdocs.toml`, missing the provider chosen during the same run. Four more
criteria failed only because the test author's own model call errored, and
were rerun unchanged.
