# D327 — AC-TRACK-004 checks behavior, not the corpus

## Context

`AC-TRACK-004` confirmed `R-TRACK-004` by reading
`specs/components/provenance-tracker/component.md` and checking that
its `depends_on` omits `comp-component-gate-runner`. Its test passed
only when run from `repo_root`. Since `D324`, a mutation run needs its
tests to pass once in a sandbox holding only `gen/`, so every seed of
`provenance-tracker` failed with "mutation baseline failed in the
sandbox: pytest exited 1", though every criterion passed.

## Decision

`AC-TRACK-004` checks what the component does: `write_attempt_record`
builds its record from plain-dict parameters, and the module's own
source never names `component_gate_runner` or
`ComponentPipelineResult`. The acyclic `depends_on` itself stays
checked by `spec-linter` (`R-LINT-004`).

## Consequences

Only `provenance-tracker`'s own criterion changes, so nothing else
regenerates. A criterion about corpus facts belongs to the linter, not
to a generated test.
