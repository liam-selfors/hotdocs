# D131 — provenance-writer's _to_jsonable must handle any attribute-bearing object, not only dataclasses

Fourth real cold-generation attempt (after `D130`'s `R-PROV-015` CLI
fix landed clean: `mutation_score=1.0`, 14 of 15 passed). The one
failure, `AC-PROV-007`, crashed with `TypeError: Object of type
SimpleNamespace is not JSON serializable`. Diagnosed directly: the
generated test built `license_scan_result`/`secret_scan_result` as
`types.SimpleNamespace` instances — a legitimate shape under this
corpus's duck-typing convention (`D94`), and the same convention
`R-PROV-014` already required `inputs`' own top-level reads to
tolerate. The candidate's `_to_jsonable` helper special-cased `dict`,
`list`/`tuple`, and `dataclasses.is_dataclass()` instances, but fell
through to returning a `SimpleNamespace` unchanged for anything else,
which `json.dumps` then rejected outright.

This is a different operation from `R-PROV-014`'s own fix (reading a
field off a value, dual dict-or-attribute) — this is *serializing* an
already-read nested value for writing, and needs to handle the same
range of shapes on the way out that `R-PROV-014` already handles on
the way in. New `R-PROV-016` closes it: `_to_jsonable`-style
conversion MUST fall back to reading an object's public attributes
directly whenever it is neither a dict nor a recognized container nor
a dataclass instance. Retrying generation next.
