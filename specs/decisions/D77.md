# D77 — The same capability-intersection bug, reproduced twice in a row

## Context

A real `generate()` call for `capability-scenario-verifier`, with
`D76`'s `dependency_usage` fix in place, correctly loaded
`criterion-compiler` from its real sealed location — confirming that
fix — but reproduced the *exact same* bug a prior, rejected candidate
had already hit: its local `realizes`-edge-building fallback scanned
`specs/product/<name>.md` files (capability files) for a `realizes:`
frontmatter field. Checked directly, again: that field only ever
exists on a *component's* own `component.md`, never on the
capability's own file. Reproducing the identical bug twice in a row,
independently, confirms this is a real spec ambiguity rather than a
one-off mistake — `impact-analyzer`'s own `R-IMPACT-005` already
establishes the correct direction for this exact field, but that text
is invisible from this component's own bundle, which does not depend
on `impact-analyzer`.

## Decision

`R-SCENARIO-002` now states explicitly: `realizes` edges are declared
per-component (`source_id` in the SQL `R-SCENARIO-002` already gives),
never per-capability; building the equivalent edge set locally (no
real `graph-query-engine` dependency) means scanning every
`specs/components/*/component.md` for its own `realizes:` list, never
scanning capability files for one.

The buggy candidate was deleted before being committed, never swapped
in.

## Consequences

A third retry, with this fix in place, is the next real test. Worth
naming plainly: this is the first time in this whole self-hosted-
generation sequence that the *same* bug recurred across two
independent candidates for the same component — every other finding
so far was new each time. A spec fix was the right call here
specifically because it recurred; a single occurrence might have been
dismissed as one candidate's own mistake the way `D64`'s and `D74`'s
plain-bug findings were.

Linter: 0 failures once this file exists. Pytest: all 166 tests across
all fourteen real components re-verified unchanged (spec-only edit).
