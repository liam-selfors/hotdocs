# D276 — Unmutated runs get 300 seconds; verifier fixtures avoid `foo`

## Context

Seeds 3 and 4 of `verifier-orchestrator` each failed `AC-VERIFY-016` and
`AC-VERIFY-004`.

`AC-VERIFY-016`'s test runs `verify` on a candidate with a never-ending
mutant, which alone takes `R-VERIFY-014`'s 10-second floor to time out,
while the verifier running that test allows it the same 10 seconds. No
candidate could pass.

`AC-VERIFY-004`'s tests faked a function `foo`, and `test-author`'s
fake-arity check matched it against `foo(x)` in example text inside
`spec-bundle-assembler`'s interface, rejecting the test.

## Decision

- `R-VERIFY-014`: a run on unmutated code times out after 300 seconds,
  a mutant's after 2 seconds or 10× the unmutated run time, whichever
  is larger.
- `interface/library.md` tells fixture authors to name functions other
  than `foo`. Renaming the example in `spec-bundle-assembler`'s
  interface instead would change the bundles of every component that
  depends on it, already-landed ones included.

## Consequences

`verifier-orchestrator` is regenerated. Until it lands, the verifier
running its tests is the previous one, whose unmutated-run limit is
10 seconds; a test for `AC-VERIFY-016` fits that once the inner mutant
floor is 2 seconds.
