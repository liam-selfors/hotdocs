# D203 — One environment and one dependency list, on Python 3.11

## Context

Dependencies were declared twice: `pyproject.toml` listed them loosely
(`pytest>=8`) for `pip install -e .`, and `requirements.txt` pinned them
for `hotdocs init`'s prerequisite check (`R-INIT-003`, `D197`). The two
could drift, and a project whose environment satisfied one could fail
the other. The declared floor was Python 3.10, but `llm-endpoint` reads
`hotdocs.toml` with `tomllib`, which the standard library gained in
3.11, so 3.10 never worked.

## Decision

There is one environment: the virtual environment in the tool's
checkout, where `pip install -e .` puts the `hotdocs` command. Every
project uses that command (`D199`); a project has no environment of its
own. There is one dependency list, `requirements.txt`, with exact pins.
`pyproject.toml` declares its dependencies as dynamic and reads that
file, so installing and checking use the same list. The Python floor is
3.11, in `requires-python` and in `R-INIT-003`'s check alike.

## Consequences

`hotdocs-init` is regenerated for the new floor. `QUICKSTART.md` tells a
user to install once and keep that environment active, or its `bin` on
`PATH`, in every project. A dependency is added or bumped in
`requirements.txt` only.
