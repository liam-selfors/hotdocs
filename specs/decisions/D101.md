# D101 — spec-bundle-assembler MUST read corpus structure via spec-linter's own parsed Corpus, never a separate YAML library

## Context

The first real cold-generation attempt at `spec-bundle-assembler` (via `claude-opus-5-5`, restarted mid-flight from `claude-sonnet-5` for this complex, foundational component) produced a candidate that `import yaml` directly to parse `component.md` frontmatter — and failed all 13 of its own `AC-ASSEMBLE-*` criteria (plus triggered `interface_drift`, since the module failed to import at all) with `ModuleNotFoundError: No module named 'yaml'`. This corpus has never installed the standalone PyYAML package; every other component that reads YAML frontmatter — `spec-linter` itself, via `graph-query-engine`'s `load_views` — does so through DuckDB's own `yaml` community extension (`INSTALL yaml FROM community; LOAD yaml`), a SQL-level mechanism with no Python package dependency at all.

Nothing in `spec-bundle-assembler`'s own spec actually required this, though it should have been unnecessary regardless: `spec-bundle-assembler` already `depends_on` `comp-spec-linter`, whose own `load_corpus` function already parses every `component.md`'s frontmatter and returns structured `Component` objects — `.depends_on`, `.requirements`, `.acceptance`, etc. — as the original hand-authored implementation already did, reading all of it through that one call and never re-parsing YAML independently. `R-ASSEMBLE-005` only required *checking* that the corpus passes `spec-linter` cleanly; nothing required *reusing* its already-parsed result for everything else assembly needs, leaving a real candidate free to reinvent frontmatter parsing from scratch — and reach for the single most common way to do that in the wider Python ecosystem, one this corpus happens not to have installed.

## Decision

New requirement `R-ASSEMBLE-012`: `assemble`/`assemble_criterion` MUST read all corpus structure — frontmatter fields, `depends_on`, `requirements/`, `acceptance/`, everything `spec-linter`'s own `load_corpus` already parses — through that one call's returned `Corpus`/`Component` objects, never by independently re-parsing any spec file's YAML frontmatter or Markdown structure. No new third-party dependency may be introduced for something a declared dependency already provides.

`spec-bundle-assembler` is regenerated via the sandboxed `bootstrap_component.py` driver against this clarified spec, with `--retry-feedback=R-ASSEMBLE-005` (the requirement already describing the `spec-linter` relationship, the closest existing citation) alongside the new `R-ASSEMBLE-012`.
