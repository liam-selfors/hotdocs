# D29 — Test per-file word-count granularity and per-file-type count caps

## Context

Item 6 from a simplification/user-friendliness review questioned whether
D2's size caps are set too low or whether the specs genuinely needed
splitting. Rather than settle that philosophically, this decision tests
a concrete, additive change: can finer-grained caps give a clearer
signal than the whole-bundle aggregates alone, without creating noise?

## Decision

**Per-file word cap (`R-LINT-023`, warn 250 / fail 500).** Distinct from
`R-LINT-012`'s `spec_bundle_words` whole-bundle aggregate — names the
specific oversized requirement/acceptance file rather than only the
bundle total. D15's intent is that each such file is one atomic,
single-purpose unit; a single file running long is a signal a bundle
aggregate can't distinguish from "lots of ordinary content spread
evenly."

**Two new per-file-type count caps**, folded into the existing
`SIZE_CAPS`/measurements machinery (so they get `R-LINT-022`'s
crowding-signal check for free): `guarantee_count` (warn 5 / fail 10)
and `acceptance_count` (warn 25 / fail 50). `guarantee_count` closes a
real gap — `interface_surface` deliberately excludes
`interface/guarantees/` (a promise, not a callable surface element),
which meant an unbounded number of guarantee files could previously
accumulate with zero cap visibility at all.

All thresholds are explicitly a first pass, calibrated against this
corpus's own content rather than an a priori judgment, and flagged in
`SPEC_GUIDELINES.md` §4 as open to recalibration.

## Consequences

Run against the real corpus: zero new hard failures. `R-LINT-023`
found four real dense files (`R-COMPILE-007`, `R-GEN-011`,
`R-IMPACT-002`, `R-LICENSE-001`) in components `R-LINT-022` never
flags — confirming it measures something genuinely different from the
bundle aggregate. `acceptance_count` crossed warn for `spec-linter`
itself (26/25). `guarantee_count` fired nowhere — the corpus has
exactly one guarantee file total — confirming no false-positive noise
from the new dimension at current corpus size.

See `SPEC_GUIDELINES.md` §4 and `specs/components/spec-linter/
requirements/R-LINT-023.md` for the current, authoritative rules.
