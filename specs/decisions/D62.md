# D62 — A second provenance-checker retry chose a layout dependency_usage can't see

## Context

A second real `generate()` call for `provenance-checker` (after
`D61`'s glossary fix for the `component_id`/slug gap) produced a
well-reasoned, non-erroring, 4-file candidate — but laid its output
out as `src/provenance_checker/{__init__,core,cli}.py` plus a
`pyproject.toml`, a full installable-package layout. Checked against
`spec-bundle-assembler`'s real `_dependency_usage()`
(`R-ASSEMBLE-011`): it only ever looks for a dependency's code at
`gen/<slug>/<module>.py` or `gen/<slug>/<module>/__init__.py` — a
`src/` layout matches neither, and `dependency_usage` would silently
(by design, fail-to-empty) return nothing for this component to any
future dependent, exactly the class of silent, hard-to-notice failure
`D55` built `dependency_usage` to prevent in the first place.

Checked whether a flat-or-top-level-package layout was ever actually
required anywhere: it was not. Every component built before this one
simply happened to produce one, because nothing ever forced the
question.

## Decision

New `R-GEN-015` (acceptance: `AC-GEN-016`): `generator`'s own prompt
MUST instruct every candidate to lay its output out as a flat module
or a top-level package, never deeper. Added directly to
`generator.py`'s `_SYSTEM_PROMPT` — this is a cross-cutting
output-format instruction, not `SpecBundle` content, the same bucket
the nonce-delimiter format (`D56`) and the `sys.modules` registration
warning (`D57`) already live in, so it reaches every future
cold-mode call regardless of which component is being generated.
`PROMPT_VERSION` bumped `v4` → `v5`.

Also documented the same rule in `SPEC_GUIDELINES.md` §1, for human
readers — but noted explicitly that this file is never part of any
real `SpecBundle` (confirmed: zero references to it in
`spec_bundle_assembler.py` outside one code comment), so it cannot be
the actual fix reaching a generating model on its own. The prompt
addition is the real fix; the guideline is documentation for people,
not model input.

The `src/`-layout candidate's `gen/provenance-checker/` output
(`R-GEN-006`'s "write on success" — success meaning "didn't error,"
never "passed independent verification") was deleted before being
committed, never swapped in.

## Consequences

This is the fourth real gap this exact self-hosted-generation sequence
has found in an unwritten, previously-implicit corpus convention
(`D55`'s import paths, `D57`'s cache-manager schema, `D61`'s
component-id-to-slug mapping, now output layout) — each one a fact
more than one component needs that had never been promoted to a
single, documented, discoverable place (`SPEC_GUIDELINES.md` §10's own
rule, applied recursively to the methodology that enforces it). A
third retry for `provenance-checker`, with this fix in place, is
tracked separately, not assumed here.

Linter: 0 failures once this file exists. Pytest: 109 tests across all
eight real components re-verified, 13 of them `generator`'s own.
