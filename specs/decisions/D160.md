# D160 — spec-completeness-assistant's CLI and model-call mechanics had no testable coverage

## Context

With `D157`'s fixes, every behavioral criterion passes, but
`mutation_score` sits at 0.47, unchanged under `D158`'s corrected
mutation gate, so it was never a timeout artifact. Re-running every
mutant directly: 16 of 30 survive, in two clusters.

The first is `main`: `interface/cli.md` documents `hotdocs assist`, and
no requirement or criterion ever exercised it. This is the fourth
component with exactly this gap, after `D130`, `D136`, and `D145`.

The second is everything around the model calls: unwrapping a
code-fenced response, handling a `model_call_error`, rejecting an
incomplete redundancy entry, a null score. That path runs only with a
model configured. The criteria touching it are the two `llm-judge`
ones, `skipped` here, and no generated test could cover it anyway: the
spec never said what the model is asked to return, so no test could
fake a response the candidate would parse. Whether the judgment is
*good* is genuinely an `llm-judge` question; whether a well-formed,
malformed, or failed response is *handled* correctly is plain
deterministic code, and was left without any spec at all.

## Decision

New `R-ASSIST-009`/`AC-ASSIST-009` cover the CLI. New
`R-ASSIST-010`/`AC-ASSIST-010` pin the model-call contract: exactly two
`complete` calls in a fixed order, each response's exact JSON shape,
fence unwrapping, score clamping, dropping incomplete redundancy
entries, and null-not-guessed degradation on a failed or unparseable
call. `interface/library.md` states the call order.

The first build against these raised `mutation_score` from 0.47 to
0.76. Of the 10 survivors, six are equivalent mutants (for example,
`lines and` flipped to `lines or` on a list `split` never returns
empty). Four were real gaps, now closed: `interface/cli.md` never said
a flag may take its value as the next argument, the CLI's `--model`
was never shown reaching `assist`, text output was never required to
show the score, and a score with an empty rationale was never said to
be unparseable.
