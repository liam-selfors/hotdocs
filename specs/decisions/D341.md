# D341 — Tests have their own spec and are authored again only when faulty or their inputs change

## Context

Regenerating the corpus re-authored far more tests than it needed to.
The bootstrap tool started every seed from an empty `verification/`, so
a seed that failed one criterion threw away every test that passed; a
component with 26 criteria paid for 26 new tests per seed. The staleness
header hashed only the criterion and requirement text, so a change to a
fixture document such as `verifier-fixtures.md` (`D339`) left the tests
written against the old rule looking current, while dependency
interface rewording would have made an exact whole-bundle hash discard
tests that were still sound. Test mechanics lived in interfaces and in
`Implements:` documents, so the generator read text meant only for test
authors, and it counted against the 4000-word cap.

Three other faults surfaced in the same runs: a test that only passes
from the real repository fails the mutation baseline and fails the
whole verification without saying which test is at fault (`D336`,
`D339`); a faulty test that is not caught by the probe keeps blaming
the code on every attempt; and a timed-out run's descendants that
started their own session outlived it at full CPU.

## Decision

`specs/architecture/test-reuse.md` states the rules, implemented by
`spec-bundle-assembler`, `test-author`, `verifier-orchestrator` and
`generation-loop`:

- A component may have `testing.md`, test mechanics only, with an
  optional `Uses:` line for shared fixture documents. It reaches test
  authors as `CriterionBundle.testing` and never the generator, and
  `graph-query-engine`'s `component_size` no longer counts it.
  `spec-bundle-assembler`'s own fixture section moves there first.
- The criterion header hashes the criterion, requirement, interface,
  glossary and test spec. It leaves out dependency interfaces, whose
  mismatched fakes the probe catches (`R-PROBE-004`), and the test
  author's version, whose newer rules the probe enforces.
- A current test is authored again only when shown faulty: it fails its
  probe; it fails alone in the mutation sandbox, which now names it with
  `failure_origin` `"test"` and lets the remaining tests be scored; or
  its criterion failed with the same test file against two consecutive
  candidates in one `generation-loop` run (`R-LOOP-007`, at most once per
  criterion per run).
- A timed-out run's whole process tree is found by walking parent links
  and killed, since killing its process group misses descendants in a
  new session; `DEFAULT_TEST_TIMEOUT` becomes part of the interface so
  a criterion can check it.
- `generated_test@3.0.0` and `verifier-orchestrator@3.3.0`. The bootstrap
  tool reuses committed tests whose bundle is unchanged and stamps the
  header the running verifier expects, so the format change does not
  re-author them.

## Consequences

`spec-bundle-assembler`, `graph-query-engine` and `generation-loop`
change, so with `test-author` and `verifier-orchestrator` nearly the
whole corpus regenerates; the branch's paused wave resumes from
`graph-query-engine`. Migrating other components' fixture text into
`testing.md` is incremental: a component moves it when it is next
edited.
