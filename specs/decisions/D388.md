# D388 — Re-seal the secret allowlist after the D373-D387 regeneration

## Context

The `D373`-`D387` regeneration re-authored many generated tests. Seven
findings in five of them hold planted fixtures the allowlist sealed by
`D357` did not cover: repeated 16-digit hex runs standing in for
SHA-256 values in
`verification/generator/generated-test/test_ac_gen_018.py` and
`verification/provenance-checker/generated-test/test_ac_provcheck_005.py`,
`_006.py` (two) and `_008.py`, and two made-up AWS-shaped access key ids
in `verification/secret-scanner/generated-test/test_ac_secret_017.py`,
whose criterion plants them. The values are not quoted here, so this
record is not itself a finding.

## Decision

The allowlist is the scanner's own `propose()` output, each new line
read by hand: the 43 entries sealed by `D357` plus those seven, each
`planted-fixture`; `propose()` reported nothing ineligible. This record
carries the file's hash.

## Consequences

A full scan is clean again. Entries for tests since replaced stay as
unused entries, which never block.
