# R-UI-001

**R-UI-001** — This component MUST be a static, client-side page using
  DuckDB-WASM to query its data sources directly in the browser — no
  backend computation, consistent with `docs-site-renderer`'s existing
  "pure renderer" design. `R-UI-006`'s local static-file server (D16)
  serves bytes only and is not an exception to this — every query still
  runs entirely client-side.

  **This now genuinely needs `duckpgq`** (`specs/architecture/
  graph-query-engine.md`), not just core `read_json` — rendering a
  graph of components/capabilities, not a flat per-component list,
  requires graph-shaped queries against `corpus-graph-builder`'s
  committed graph (`D88`). An earlier version of this requirement
  concluded the opposite, correctly, for the data this component
  rendered at the time (`TrackingRecord`, flat JSON) — that data no
  longer exists; what replaced it is graph-shaped by nature.
