# R-UI-007

**R-UI-007** — MUST support navigating/filtering between at least two
  scopes: a blast-radius view (given a developer-supplied changed-ids
  set, the same scope `provenance-tracker`'s `check_readiness` accepts)
  and a whole-corpus view (every component/capability). This component
  never calls `check_readiness` itself — it is a static page (R-UI-001)
  — so switching scope MUST re-run its own client-side DuckDB-WASM
  query against the current on-disk `.provenance.json`/
  `.hotdocs/attempts/` state for the new scope, never reuse a stale,
  previously-fetched result and re-filter it client-side, since that
  state can change between queries (a developer may run
  `hotdocs build` while this page is open, in another terminal).

  Further views (e.g. filtered by capability, by owner) are a natural
  extension of this same scope-selection mechanism, not a different
  one — left open for later, not assumed here.
