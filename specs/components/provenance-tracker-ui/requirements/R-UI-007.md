# R-UI-007

**R-UI-007** — MUST support two scopes, chosen at build time:
  whole-corpus (`changed_ids` omitted) and blast-radius (`changed_ids`
  given — the same scope `check_readiness` accepts). Every call to
  `render_tracker_ui` MUST call `check_readiness` afresh with exactly
  the `changed_ids` it was given, never reusing or client-side
  filtering an earlier result, since provenance state can change
  between builds. The page MUST state its own scope visibly: the
  snapshot's `scope` string, plus the `changed_ids` for a blast-radius
  view.

  The page shows state as of its last build; switching scope or
  refreshing means rebuilding (`D154`). Further views (by capability,
  by owner) are a natural later extension, not assumed here.
