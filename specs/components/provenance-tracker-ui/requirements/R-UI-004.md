# R-UI-004

**R-UI-004** — This component MUST read `corpus-graph-builder`'s
  committed `corpus-graph.json` for topology (nodes, edges — which
  components/capabilities exist and how they relate) and
  `provenance-tracker`'s `VerifyReport`/`AttemptRecord` for provenance
  status layered on top of it. Reads nothing else committed
  (`specs/`, `gen/`, `verification/` directly) and writes nothing.

  **Reverses an earlier version of this requirement**, which ruled out
  reading any committed corpus state at all, specifically to keep this
  component's local-only data separate from CI-rendered, committed
  data (`D10`). That boundary's own stated exception — "revisit only
  if a concrete cross-referencing need actually surfaces" — is what
  happened: rendering a graph of components/capabilities needs their
  topology, which only exists in `corpus-graph.json`, not in anything
  local-only. The two data sources are still read separately and never
  conflated — this component's own output remains local-only and
  per-developer, same as before, even though one of its two inputs
  is now committed, CI-rendered data.
