# R-UI-006

**R-UI-006** — The built page MUST be opened via a trivial local
  static-file HTTP server (`hotdocs track ui serve`), not `file://` —
  resolving this component's own open question (`component.md`).
  `fetch`-ing local JSON from a `file://` context hits CORS restrictions
  inconsistently across browsers; a local server removes that
  inconsistency entirely rather than leaving it to chance per developer.

  The server MUST serve only static bytes — the built page
  (`render_tracker_ui`'s output), `corpus-graph.json`, and
  `.hotdocs/attempts/*.json` — with zero backend logic of its own: no
  computation, no response built from anything but a file's literal
  contents. DuckDB-WASM still performs the actual query entirely
  client-side, exactly as before — this is a transport fix for CORS,
  not a backend addition, and does not reopen `constraints.md`'s "no
  server process" posture in the sense that constraint was stated (no
  backend *computation*); it is clarified there accordingly.
