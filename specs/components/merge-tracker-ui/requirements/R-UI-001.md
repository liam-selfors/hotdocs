# R-UI-001

**R-UI-001** — This component MUST be a static, client-side page using
  DuckDB-WASM to query `.hotdocs/tracking/*.json` directly in the
  browser — no backend computation, consistent with
  `docs-site-renderer`'s existing "pure renderer" design.
  `R-UI-006`'s local static-file server (D16) serves bytes only and is
  not an exception to this — the query still runs entirely client-side.

  **Correction to this decision's own earlier framing:** `TrackingRecord`
  (`merge-tracker`'s output) is plain JSON, not YAML frontmatter and not
  graph-shaped — rendering it needs only DuckDB-WASM's **core** `read_json`
  support, no extension at all. `duckpgq` (`specs/architecture/
  graph-query-engine.md`) only becomes relevant if this component is later
  extended to also show corpus-graph context (component's Open Questions)
  — it is not a dependency of this component's actual current scope, and
  this spec previously implied otherwise.
